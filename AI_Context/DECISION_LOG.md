# DECISION_LOG — 架构与流程决策

> 每个决策一条记录。推翻时新增条目，旧条目标 `SUPERSEDED`，不改写历史。

## ADR-0001 采用 Agent Workflow Kit v3

- **状态**：ACCEPTED（2026-11-24）
- **背景**：工程已具备编译、注释和配表门禁，但缺少统一任务状态、CEO 批准记录、独立验证与上下文回写机制。
- **决定**：在现有 Unity 工程中布设 v3 工作流：`AI_Context/`、`FEED_DROP/`、四角色技能、交接模板与两份 Python 校验器。
- **后果**：L1/L2 任务必须产生任务简报、Manifest、PLAN、批准记录、执行报告和验收记录；L0 保留快速通道但仍需证据。

## ADR-0002 项目级角色技能放在 `.agents/skills/`

- **状态**：ACCEPTED（2026-11-24）
- **背景**：需要让每个新 Codex 会话可直接加载职责技能，而不是依赖口头角色扮演。
- **决定**：八个套件技能复制到仓库内 `.agents/skills/`；会话通过 `$skill-name` 显式调用。
- **后果**：技能随项目版本化；更新套件时需要同步项目技能副本，并运行一次会话发现检查。

## ADR-0003 保留 Unity 根宪章，增加工作流入口

- **状态**：ACCEPTED（2026-11-24）
- **背景**：原 `AGENTS.md` 已包含高价值的 asmdef、0 GC、生成物与注释纪律，不能被通用模板覆盖。
- **决定**：只在根 `AGENTS.md` 增加第 0 节任务治理入口，所有 Unity 技术铁律原样保留。
- **后果**：任务必须先满足工作流授权，再满足工程编译和架构门禁；冲突时采用更严格约束。

## ADR-0004 `FEED_DROP` 是本地可重建缓存

- **状态**：ACCEPTED（2026-11-24）
- **背景**：真实源文件投喂用于降低上下文成本并让 Chat / Agent 共用物理入口。
- **决定**：`AI_Context/TASKS/**/FEED_DROP/` 加入 `.gitignore`；Manifest 与任务凭证入库，源文件仍在原路径维护。
- **后果**：新机器或缓存丢失时可重新运行 `stage_context.py`；禁止把暂存副本当作代码真源。

## ADR-0005 四层 asmdef 与本地 Luban 持续有效

- **状态**：ACCEPTED（依据现有工程文档，2026-11-24 工作流化）
- **背景**：四层依赖和 `cfg` 边界已由编译门与负向测试建立。
- **决定**：`Presentation → Logic → Data → Foundation` 单向依赖继续作为唯一架构拓扑；`cfg.asmdef` 保留在 `Generated/` 上层。
- **后果**：任何引用、新程序集或生成物目录变更都需要重新审查拓扑与批准计划。
