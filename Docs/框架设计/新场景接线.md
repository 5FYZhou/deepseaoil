# 新场景接线（空白场景 → 可玩）

**适用**：新建一个空场景、或把已废弃场景（如 `Assets/Scenes/TextTile.unity`）重接一遍。
**依据**：逐条核对过当前代码（`715e585`）与 `Assets/Scenes/EmptyTest.unity` 的实际序列化数据；标 `【推断】` 的是"按代码路径推出、但没在 Play 里目视确认"的结论。
**分工**：本文只讲"在 Unity 里点哪里、填什么"；为什么这么设计看 [框架蓝图.md](框架蓝图.md) 与 [分层设计/](分层设计/)，逐字段的运行时行为看 [分层设计/表现层.md](分层设计/表现层.md) §3 / §8。

## 0 · 一张总表

| 类别 | 内容 |
| :-- | :-- |
| **必须存在** | `GameRoot`、`InputProvider`、`PlayerController`（＋`PlayerMotor`＋`Rigidbody2D`＋`Collider2D`＋`SpriteRenderer`）、`CombatRoot`、`TilemapAdapter`、**画了地板的 Tilemap**、`Grid`、主相机（tag `MainCamera`）、**一盏 Global Light 2D** |
| **可选** | `BoundsArea`（不接只是不钳位，会 Warning）、`Fountain`（不接就没有水源）、`ballRoot` / `actorRoot`（只影响层级整洁）、三个调试面板、Cinemachine 跟随与 Confiner |
| **禁止** | 场景里放 `Canvas` / `EventSystem`（`UIMgr.Init` 会把场上那份停用，并打一条 Error 说明）、第二个 `AudioListener` |
| **不用管** | 层（全用 Default）、Physics2D 设置、UI 三件套 / 面板 / 字体 / 音频配置（全部由 `Resources` 在运行期创建） |

目标层级（照 `EmptyTest` 的实测结构）：

```text
Main Camera      Camera + AudioListener + UniversalAdditionalCameraData + CinemachineBrain
Grid             Grid（cellSize 1×1）
├── Ground       Tilemap + TilemapRenderer      ← 画了地板的那一层
└── TileEffect   Tilemap + TilemapRenderer      ← 状态贴图层（初始留空）
GridView         TilemapAdapter                 ← 单独一个根物体，字段指向上面两层 Tilemap
BoundsArea       BoxCollider2D（Is Trigger ✓）
GameRoot         GameRoot
InputProvider    InputProvider
Player           Rigidbody2D + BoxCollider2D + SpriteRenderer + PlayerController + PlayerMotor
CombatRoot       CombatRoot
Fountain         CircleCollider2D（Is Trigger ✓）+ Fountain
cm / vcam        CinemachineVirtualCamera（由 CM 菜单建；它自己的隐藏子物体才叫 cm）
```

## 1 · 项目级前提（已就绪，一个都不用动）

| 项 | 现状（已核实） |
| :-- | :-- |
| URP 2D | `ProjectSettings/GraphicsSettings.asset` 的 `m_CustomRenderPipeline` → `Assets/Settings/UniversalRP.asset` → renderer 列表 → `Assets/Settings/Renderer2D.asset`（**2D Renderer 生效**） |
| Input System | `com.unity.inputsystem@1.14.2`；`InputSys` 由 `InputProvider.Awake` 里 `new` 出来，**不需要拖资产** |
| Cinemachine | `com.unity.cinemachine@2.10.7`（CM **2.x** API：`CinemachineVirtualCamera` / Framing Transposer / Confiner） |
| Physics2D | 重力 `(0, −9.81)`，但执行器会把角色 `gravityScale` 写成 0（`ActorMotor.ApplyPhysics`）；`AutoSyncTransforms = 0`；`QueriesHitTriggers = 1`（冲量查询会命中 Trigger，但 `ImpulseExecutor.PushBodies` 会滤掉无刚体 / 运动学 / 玩家 / 敌人） |
| 层与标签 | **唯一硬要求**：主相机 tag = `MainCamera`（`PlayerController` 瞄准兜底用 `Camera.main`）。其余全用 Default 层；`RenderOrder.OverlayLayer = 0` |
| 排序 | 只用 `sortingOrder` 数字，不动 sorting layer：地板 0 / 效果层 1 / 贴地阴影 310 / 瞄准高亮 320 / **角色与球 500–559（按 y 自动算）** / 碎片 1200 |

## 2 · 第一步：建场景与光照

**最省事的做法**：打开 `Assets/Settings/Scenes/URP2DSceneTemplate.unity` → `File ▸ Save As` 存成你的场景。
它自带「Main Camera（正交、Size 5、z = −10、tag `MainCamera`）＋ **Global Light 2D**（Global / Multiply / 白色 / 强度 1）」，正好是本文 §3 要的那套。
若你坚持建空场景：自己加 `Camera` ＋ `GameObject ▸ Light ▸ 2D ▸ Global Light 2D`。

> ⚠️ **为什么必须有 Global Light 2D**：场景里手工摆的 `SpriteRenderer` / `TilemapRenderer` 用的是 `Sprite-Lit-Default`（URP 的**受光**材质），而 `Render2DLightingPass` 在"本层零光源"时会把 `_ShapeLightTexture0…3` 绑成 `Texture2D.blackTexture` 并只启用 blend style 0 ⇒ **受光精灵乘出来是全黑**。项目 2D 模板自带这盏灯正是为此。
> 【推断·待目视确认】**现状**：`EmptyTest` / `SampleScene` / `TextTile` 三个场景**都没有 Light2D**；而运行期由代码 `AddComponent<SpriteRenderer>()` 建的件（敌人 / 球 / 碎片 / 瞄准格高亮，见 `Presentation/白模用/PrimitiveSprites`）用的是 Unity 默认的 `Sprites-Default`（不受光）。所以零光源下的表现很可能是"代码建的件正常、场景里摆的玩家方块与地板偏黑"。**进 Play 看一眼即可确认**；确认发黑就补一盏 Global Light 2D。

## 3 · 主相机

| 组件 | 字段 | 值 |
| :-- | :-- | :-- |
| Transform | Position | `(0, 0, −10)`（没配 CM 时的初始位；配了 CM 后由 vcam 接管） |
| Camera | Tag | **`MainCamera`**（瞄准兜底依赖它） |
| | Projection | **Orthographic** ✓，Size = **5** |
| | Clear Flags | Solid Color；Background 建议 `(0.19, 0.30, 0.47)`（与模板一致） |
| | Culling Mask | Everything（保持默认） |
| AudioListener | — | **保留一个**：`Assets/Resources/ui/UICamera.prefab` 里没有 AudioListener，UI 相机不提供 |
| UniversalAdditionalCameraData | — | 保持默认（Render Post-processing 关） |

`PlayerController.aimCamera` **留空**即可 —— 代码是 `aimCamera != null ? aimCamera : Camera.main`；CM 的 Brain 挂在主相机上，`Camera.main` 始终是它。

## 4 · Cinemachine 配置（CM 2.10.7）

### 4.1 加 Brain

`Main Camera ▸ Add Component ▸ Cinemachine ▸ Cinemachine Brain`。
（用 CM 菜单建 vcam 时它**会自动**给主相机加一个 Brain，所以也可以先建 vcam 再回来确认。）

### 4.2 建跟随相机

`GameObject ▸ Cinemachine ▸ **2D Camera**`（菜单源码里就是 `Cinemachine/2D Camera`）。它会新建一个 `Virtual Camera` 对象、**自动带上 `CinemachineFramingTransposer`**，并把镜头参数抄自主相机（正交 ✓、Size 5 ✓）。然后：

| 组件 / 字段 | 值 | 说明 |
| :-- | :-- | :-- |
| `CinemachineVirtualCamera ▸ Follow` | 拖入 **Player** | 跟随物理体所在的 Transform |
| `▸ Look At` | 留空 | 2D 不旋转 |
| `▸ Priority` | 保持 **10**（CM 默认值就是 10） | 单台相机无所谓，别改成负数 |
| `▸ Lens ▸ Orthographic` | ✓ | 2D |
| `▸ Lens ▸ Orthographic Size` | **5** | 与主相机一致；改它等于改可视范围（**不影响瞄准**，见 §4.5） |
| `▸ Body ▸ Framing Transposer` | `Camera Distance` = **10**（默认） | 语义是"沿相机轴与目标的距离"，实现是 `目标位置 + back × CameraDistance` ⇒ 目标 z=0 时相机落在 **z = −10**，与项目既有约定一致 |
| | `Dead Zone Width/Height` = 0（默认） | 想"小幅走动相机不动"就填 1~2 |
| | `Soft Zone` / `Damping` = 0.15~0.3 | 0 = 硬跟 |
| `▸ Aim` | `Do nothing` | |
| `CinemachineBrain ▸ Update Method` | **SmartUpdate**（默认） | 目标由物理驱动时它会选 `FixedUpdate`；**必须配合 §4.3** 才顺滑 |

### 4.3 让相机不抖（必做）

`Player` 的 `Rigidbody2D ▸ Interpolate` = **Interpolate**。
物理步是 50Hz、渲染帧通常更高；不插值时 Transform 每 20ms 跳一次，相机硬跟就会看出台阶。开插值后 `Rigidbody2D.position` 仍是物理真值（逻辑层读的就是它，见 `ActorMotor.Position`），只有视觉被平滑 —— 对玩法零影响。

### 4.4 限制相机不出图（可选，两种选一）

| 方案 | 怎么加 | 要求 | 备注 |
| :-- | :-- | :-- | :-- |
| **`CinemachineConfiner`（旧版，推荐）** | vcam ▸ `Add Extension ▸ CinemachineConfiner` | `Confine Mode` = **Confine2D**；`Bounding Shape 2D` = **直接拖 `BoundsArea` 的 BoxCollider2D**；`Confine Screen Edges` ✓；`Damping` 0~0.3 | 接受**任意** `Collider2D`，复用已有边界盒，零额外对象 |
| `CinemachineConfiner2D` | vcam ▸ `Add Extension ▸ Cinemachine Confiner 2D` | `Bounding Shape 2D` **必须是 `PolygonCollider2D` 或 `CompositeCollider2D`（Geometry Type = Polygons）**，否则 Inspector 直接报 `Must be a PolygonCollider2D or CompositeCollider2D.` | 更精确（支持凹多边形、自动失效缓存），代价是另建一个多边形 |

### 4.5 与项目代码的关系（都不用改代码）

- **瞄准不受 CM 影响**：`PlayerController.AimWorldPoint` 只读 `aimCamera ?? Camera.main` 与 `ThrowTuning.cameraPlaneDepth = 100`，**刻意不读相机的 z** —— 所以 CM 每帧驱动相机 z 对它无害。
- **屏幕抖动现在不要接**：CM 自带 Impulse 系统，但项目里 `EffectId.ScreenShake` 只是**枚举占位**（没有驱动实现），接它属于"要写代码"的活。
- **`EmptyTest` 里的 `cm`** 只有 `CinemachinePipeline`、没有 vcam 也没有 Brain，是历史残留 —— **建议直接删掉**再按本节重配。

## 5 · 逐对象接线

### 5.1 地板与格子

1. 建 `Grid`（`GameObject ▸ 2D Object ▸ Tilemap ▸ Rectangular`），它自带一个子物体 `Tilemap`；`Grid.cellSize` 保持 **1×1**（非正方形会报 `[Grid] 地板 Tilemap 的格子不是正方形`）。
2. 把那个 `Tilemap` 改名 **`Ground`**，再在 `Grid` 下**复制一份**改名 **`TileEffect`**（状态贴图层）。
3. 用 `Window ▸ 2D ▸ Tile Palette` 打开 `Assets/Art/TileMap/demoTile/Demo_Palette.prefab`，在 **Ground 层**刷出一片地板（`Tile_Floor`）。**至少要有一格**，否则报 `[Grid] 地板 Tilemap 上一个 tile 都没有：落点不会产生任何效果。`
   - `TileEffect` 层**初始留空**（`TilemapAdapter` 按状态写入并在状态结束时还原原贴图）。
   - 两层 `TilemapRenderer ▸ Sorting Order` 保持 **0 / 1**（远低于角色频带 500+）。
4. 新建根物体 **`GridView`**，挂 **`TilemapAdapter`**：

| 字段 | 值 |
| :-- | :-- |
| `groundTilemap` | 拖 **Ground** 的 `Tilemap` |
| `effectTilemap` | 拖 **TileEffect** 的 `Tilemap` |
| `stateTiles` | `Size = 1`；`Element 0`：`State = Mud`，`Tile = Assets/Art/TileMap/demoTile/Tiles/Tile_Mud.asset` |

> `TilemapAdapter.Awake` 的自检：`groundTilemap` 空 → Error；`effectTilemap` 空 → Warning「状态变化只记逻辑、不显示」；两层填成同一个 → Error「状态结束时会把地板一起擦掉」；`stateTiles` 空 → Warning。

### 5.2 边界盒（可选但强烈建议）

新建 **`BoundsArea`**：加 `BoxCollider2D`，**`Is Trigger` ✓**（不勾会变成一堵实心盒子把玩家挡在外面），`Size` = 你的可走区域（现有场景是 40×20），物体位置放在区域中心。
> **但不要**把 `CinemachineConfiner2D` 的 Bounding Shape 指向这个盒（它只吃多边形）；旧版 `CinemachineConfiner` 才能直接用盒。

### 5.3 玩家

| 组件 | 字段 | 值 |
| :-- | :-- | :-- |
| Transform | Position | 出生点（打空重来会回到这里：`PlayerController.Awake` 按物理体位置记一次） |
| **Rigidbody2D** | Body Type | Dynamic |
| | Gravity Scale | 0（运行期 `ActorMotor.ApplyPhysics` 也会写成 0） |
| | Constraints | **Freeze Rotation Z** ✓ |
| | Collision Detection | Continuous |
| | **Interpolate** | **Interpolate**（配合 Cinemachine，见 §4.3） |
| **BoxCollider2D** | Size | 约 `(0.7, 0.5)`；**非 Trigger** |
| **SpriteRenderer** | Sprite / Color | 任意（白模用 `Assets/Resources/demo/Square.png` 或纯色）；**必须在 `PlayerController` 同一个 GameObject 上**（`PlayerController.UpdateSortingOrder` 用的是 `GetComponent<SpriteRenderer>()`） |
| **PlayerMotor** | `body` | 留空即可（惰性自取 `GetComponent<Rigidbody2D>()`） |
| **PlayerController** | `config` | `Assets/ConfigAssets/玩家配置.asset` |
| | `motor` | 拖自己身上的 `PlayerMotor` |
| | `inputProvider` | 拖 §5.4 的 `InputProvider` |
| | `aimCamera` | 留空（= `Camera.main`） |
| | `boundsArea` | 拖 `BoundsArea` 的 `BoxCollider2D`（不接只 Warning：玩家不被钳位） |

### 5.4 输入与进程根

| 对象 | 组件 | 字段 |
| :-- | :-- | :-- |
| `InputProvider` | `InputProvider` | **无字段**（`Awake` 里 `new InputSys()`，`Start` 自己向 `GameRoot` 报到） |
| `GameRoot` | `GameRoot` | **无字段**（`Awake` 装配 Data 层 → UI → 音频 → 四个 Service） |

> `GameRoot` 不放也会被 `Singleton<T>` 在第一次 `Instance` 访问时**自动创建**（`InputProvider.Start` 就会触发），但那是"在别人的 `Start` 里现场造组合根"，装配失败时不好定位 —— **建议显式摆一个**。

### 5.5 战斗组合根与喷泉

| 对象 | 字段 | 值 |
| :-- | :-- | :-- |
| `CombatRoot` | `player` | 拖 `PlayerController`（**必需**） |
| | `gridView` | 拖 `TilemapAdapter`（**必需**） |
| | `ballRoot` | 可留空（留空 = 球与瞄准高亮建在场景根下） |
| | `actorRoot` | 可留空（留空 = 敌人在场景根下） |
| | `fountains` | 把喷泉拖进来（可以不填；不填就没有水源） |
| | `enableWaves` | ✓（只想验投掷链路时**取消勾选**，此时不刷敌人） |
| `Fountain` | `CircleCollider2D` | **Is Trigger ✓**，Radius 3（玩家进圈才产出） |
| | `spawnInterval` | 1 |
| | `radiusView` | 可留空（进出触发区时显隐的提示物件） |
| | `landingRadius` / `minLandingDistance` | 3 / 0.8 |

> 触发依赖：`Fountain.OnTriggerEnter2D` 用 `GetComponentInParent<PlayerController>()` 认人 —— 玩家身上有 Collider2D 且有 Rigidbody2D，条件天然满足，**不需要配层**。

### 5.6 可选调试件

`MovementDebugPanel`（状态 / 速度 / 是否越界）、`EventBusDebugPanel`（订阅 `TileStateChanged`，看真实事件流量）、`EffectDebugPanel`（特效单播与池统计，**当前三个场景都没挂**）—— 都是空字段，随便挂在一个物体上。

## 6 · 启动验收

1. **进 Play**，Console 应出现：
   `[Combat] 装配完成：格子 N 个（初始状态 0 个），球种 2 个，喷泉 M 个，敌人 启用`
   （`M` = 拖进 `fountains` 的数量；不勾 `enableWaves` 时末尾是「敌人 关闭（CombatRoot 的「是否刷敌人」未勾选：想要刷怪请在 Inspector 上勾上它）」）。
2. **此刻是菜单态**：`GameManager.ChangeState(Menu)` 会发 `RequestPause` ⇒ `timeScale = 0`，一切冻结；Hierarchy 里出现 `[Effects]` 根、UI 三件套与 `BeginPanel`（均 `DontDestroyOnLoad`）。
3. 点开始面板的 **`StartBtn`** → `GameState.Running` → HUD 出现（血量 / 水球 / 波次三行）。
4. 操作验收：WASD 移动（8 向吸附）、`Shift` 冲刺、**左键投水球 / 右键投土球**（瞄准格高亮：白 = 可投，红 = 冷却中或没水球）、走进喷泉圈等 1 秒拿水球、踩泥浆变慢（玩家也会被减速）、敌人追来接触掉血、打空后延时重生并清场、`Esc` 暂停。
5. 相机验收：移动时跟随且**不抖**（抖 = 忘开 `Rigidbody2D.Interpolate`）；走到地图边缘被 Confiner 挡住、看不到图外。
6. 只有需要运行时切场景（`TestChangeScene` 那条路）时，才要把场景塞进 `Build Settings`；本地 Play 不需要。

## 7 · 排错对照（文案都来自代码，可直接在 Console 里搜）

| Console 文案 | 原因 | 修法 |
| :-- | :-- | :-- |
| `PlayerController 引用未接线（config / motor / inputProvider），已停用。` | 三件缺一 | §5.3 |
| `PlayerController.boundsArea 未接线、被停用或尺寸为 0：玩家不会被限制在地图边界内。` | 边界盒没接 / 被禁用 / size 为 0（Warning，不致命） | §5.2 |
| `CombatRoot 引用未接线（player / gridView 至少缺一个），战斗内容已停用。` | 两个必需引用缺一 | §5.5 |
| `CombatRoot 的 TilemapAdapter 没有接 Tilemap，战斗内容已停用。` | `groundTilemap` 空 | §5.1 |
| `CombatRoot 拿不到玩家的逻辑层（PlayerController 的 config / motor 没接好，或它的装配失败），战斗内容已停用。` | `PlayerController` 自己装配失败 | 先修玩家 |
| `[Grid] 地板 Tilemap 上一个 tile 都没有：落点不会产生任何效果。` | 忘了刷地板，或 `groundTilemap` 指错层 | 在 Ground 上刷 `Tile_Floor` |
| `[Grid] TilemapAdapter 的 groundTilemap 与 effectTilemap 指向了同一层…` | 两层拖成同一个 | 分成两层 |
| `[Grid] TilemapAdapter.stateTiles 是空的…`（Warning） | 没配状态贴图 | 加 `Mud → Tile_Mud` |
| `[Grid] 格子几何自检失败：CellToWorld(0,0) + 半格 = …` | `Grid` 的 Cell Size / Tile Anchor 被改过 | 恢复 1×1 与 Anchor 0.5 |
| `[UI] 场景里已经有一份 EventSystem…` | 场景里摆了 `Canvas` / `EventSystem` | 删掉它们（UI 由 `UIMgr` 从 `Resources` 建） |
| `[Ball] projectile 表里没有球种 X，这次投掷被丢弃。` | 配表缺行 / 没导表 | 跑 `Luban ▸ 表格数据导入` |
| 点鼠标没反应、瞄准格不亮 | 主相机没有 `MainCamera` tag，或场景里没有相机 | §3 |
| 玩家方块 / 地板发黑 | 缺 Global Light 2D（受光材质） | §2 |
| 相机纹丝不动 | 没建 vcam / Brain 没挂 / vcam 的 `Follow` 空 | §4 |
| 相机抖 | `Rigidbody2D.Interpolate = None` | §4.3 |
| 玩家被"看不见的墙"挡住 | `BoundsArea` 没勾 `Is Trigger` | §5.2 |
| `[Combat] 领取了没有接线效果的掉落物 X（N 个），本次不产生任何变化。` | 出现新的 `DropType` 但 `CombatRoot.OnDropCollected` 没加 `case` | 属于加功能，不是接线问题 |

## 8 · 两条纪律（照做能省掉大半返工）

1. **别给场景加 `Canvas` / `EventSystem` / 第二个 `AudioListener`**：UI 三件套由 `UIMgr` 从 `Assets/Resources/ui/` 建并跨场景常驻；场景里那份会被停用并报一条 Error。
2. **只让 `GameRoot` 驱动帧**：不要在场景里给任何脚本加 `Update` / `FixedUpdate`"顺手推一下"；`PlayerController` 与 `CombatRoot` 都是在自己 `Start` 里**注册**（`ISceneRoot`），由 `GameRoot` 按 `Order`（玩家侧 `-100` → 世界侧 `0`）先 `Attach` 装配、再逐帧驱动。加新场景件时照同一套接口实现。

## 9 · 与 `EmptyTest` 的差异（重接时要顺手清掉的）

| 差异 | 处理 |
| :-- | :-- |
| Main Camera 下有个孤儿 `cm`（只有 `CinemachinePipeline`，**没有 vcam 也没有 Brain**） | 删掉，按 §4 重配 |
