### 一、切图与导入规范（硬性）

1. **PPU (Pixels Per Unit)：`100`**。全仓美术件（`art/Character`、`art/Prop`、`art/Background`、`demo/Square.png`）当前都是 100，别改成 128（例外：`art/Prop` 里的 `prop_machine_penqvan.png` / `prop_machine_tiqvqi.png` 是 64；`art/UI` 三张面板贴图 `ui_panel_duihuakuang` / `ui_panel_shezhi` / `ui_panel_zantin` 是 128 —— 那是 UI 交付件的既有口径，与角色 / 地块这一套无关）。
   - **1 世界单位 = 1 格 = 100 像素**：`Grid.CellSize = (1,1,0)`（XY 布局），`demo/Square.png` 恰好 100×100 像素 ⇒ 正好铺满一格（它同时是 16 张状态贴图与 `Tile_Floor` 的占位 sprite）。
   - **图幅按 100 的整数倍出**：现有角色图是 `idle_zheng` / `idle_fan` / `walk_zheng` / `walk_fan` `1024×256`、`gun` `512×256`、`die` `256×256`，都是 100 的整数倍，单帧宽度取 100 的约数（一个身位 ≈ 100×100 像素）。**格子对齐由策划摆位置，别靠改 PPU 去凑格子**（那样会把所有关卡贴图一起缩放）。
2. **Filter Mode**：像素画选 `Point`（`filterMode: 0`，`demo/Square.png` 就是这个）；手绘/矢量选 `Bilinear`（`filterMode: 1`，现有角色与道具件都是它）。
3. **Compression**：选 `None` 或 `Normal Quality`（现有件为 `textureCompression: 1`）。
4. **Pivot 对齐约束**：
   - **角色：`Center (X: 0.5, Y: 0.5)`**。现有角色件全是 `alignment: 0` + `spritePivot: (0.5, 0.5)`，**别改成 Bottom**：Y-Sort 与格子登记用的都是角色的**物理体中心**（`EnemyActor` 用 `BoundsArea` 的圆心算 `Position.y`，`GridLogic.WorldToCell` 也拿这个点），`ActorMotor` 的 `BoundsArea` 碰撞体同样是圆心。改成 Bottom 会让贴图整体上浮半个身位，与碰撞体、格子判定错位，且不报错。
   - **地块瓦片与 UI**：`Center (0.5, 0.5)`（同现状）。
   - **贴地道具**（喷泉、机器等）：`Center (0.5, 0.5)`，用物体自身的 y 参与 Y-Sort，不要靠 pivot 抬底。
5. **Sprite Mode**：现有角色图里 `gun` / `idle_zheng` / `idle_fan` / `walk_zheng` / `walk_fan` 已经是 `spriteMode: 2`（Multiple，切好帧），只有 `die` 还是 Single。若一张 PNG 里有多帧，**要么在导入设置里改 Multiple 并切好帧，要么让美术出单帧图**。

### 二、地块 TileBase 归档规约（约定懒加载）

- **归档路径**：必须放入 **`Assets/Resources/tiles/`** **顶层，不建子目录**（`tiles/Ground/` 只放背景 tileset 切图，不参与状态约定）。
- **文件命名**：必须严格命名为 **`Tile_<TileStateType 枚举名>.asset`**。

#### 16 种合法状态文件名速查（直接复制命名）

对应 `cfg.dso.TileStateType` 里除 `None` 外的 16 个值（`Normal` 也要有一份）：

```text
Tile_Normal.asset           Tile_Mud.asset               Tile_MudSkid.asset
Tile_Freeze.asset           Tile_TerracottaBrick.asset   Tile_Steam.asset
Tile_BasicWater.asset       Tile_BasicEarth.asset        Tile_BasicFire.asset
Tile_BasicIce.asset         Tile_BasicElectricity.asset  Tile_BasicPlant.asset
Tile_ConductZone.asset      Tile_FlameField.asset        Tile_ChargedThorn.asset
Tile_FrostSpike.asset
```

> 这 16 份不是"建议都建"，而是**枚举的镜像**：`tile_state` 表有几行、`TileStateType` 有几个成员，`tiles/` 下就该有几份。少一份的后果是**那个状态被触发时静默不显示**——`TilemapAdapter.TileFor` 只打一条 `[Grid] 未找到地块资源: tiles/Tile_X` 警告，逻辑照常扣血，表现成"看不见但真在掉血"。

另有一份**不是状态**的地板贴图：

| 文件 | 用途 |
| :-- | :-- |
| `Tile_Floor.asset` | `Grid/Ground` 层刷的常规地板。`TilemapAdapter.RegisterCells` 把所有地板格一律按 `Normal` 登记，所以它**不参与反应**，只回答"这一格能不能站" |

#### 🔴 文件名的 `Tile_` 前缀 vs 资产内部名（两条通道，别只记一条）

- **效果层贴图**（`TileFor`）：认**文件路径** ⇒ 文件名必须是 `Tile_<状态>`，走 `AssetModule.Load<TileBase>("tiles/Tile_<状态>")`。
- **InitialSetup 笔刷层**（`ResolveSetupState`）：认**贴图的资产名 `tile.name`**（Unity 里是资产 yaml 的 `m_Name`）。解析顺序是**先剥 `Tile_` 前缀再 `Enum.TryParse`、失败后拿全名再解析**。
- 现状：17 份资产的**文件名与 `m_Name` 都带 `Tile_` 前缀且逐字符相同**（`Tile_Mud.asset` 的 `m_Name` 就是 `Tile_Mud`）⇒ 第一通道直接命中，第二通道根本不跑。**新建资产时 Unity 默认用文件名当 `m_Name`，别手动改短**：改成 `Mud` 不影响效果层，但会让 InitialSetup 笔刷静默落回 `Normal`（笔刷刷上去的泥浆开局变空地，不报错）。

### 三、场景 Tilemap 分层装配标准

在场景的 `Grid` 节点下保持「地板 ＋ 初始编辑 ＋ 效果层组」的结构：

```text
Grid                (Cell Size = 1, 1, 0；Cell Layout = XY；Cell Swizzle = 0)
├── Ground          (TilemapRenderer Order = 0)  ← 地板层（必须刷满常规地板，提供合法走行动线）
├── InitialSetup    (TilemapRenderer Order = 1)  ← 关卡编辑层（笔刷画开局泥浆/火池/冰面，运行时读完自动 SetActive(false)）
└── TileEffect_*    (TilemapRenderer Order = 2, 3, …)  ← 动态反应层（按动效分组，可多张，开局留空）
```

> `Range.unity` 的效果层是 `TileEffect_Static` / `TileEffect_Fire` / `TileEffect_Water` / `TileEffect_Steam` 四张，`Order` 自 `2` 起逐层递增（2 / 3 / 4 / 5）。

- **Grid 本体**：`CellSize` 必须 `1 × 1`（`TilemapAdapter.ReadGeometry` 对非正方只报错不修：`格子不是正方形（x × y）…几何按 x 取值`）、`Cell Swizzle = 0`、位置留在整数（`Grid` 与各 `Tilemap` 的 Transform 若被挪到小数坐标，`WorldToCell` 与 `CellCenter` 会静默错半格）、缩放 `1`、不旋转。Tilemap 的 `Tile Anchor` 保持默认 `(0.5, 0.5)`——`GridGeometry.CellCenter` 按"格中心 = 原点 + (格号+0.5) × 格边长"算，而 `ReadGeometry` 会拿 `GetCellCenterWorld((0,0))` 跟它比对一次：对不上直接报 `[Grid] 格子几何自检失败…检查 Grid 的 Cell Size / Tile Anchor`。锚点一改，投掷落点高亮与实际效果格就整体错开。
- **`TilemapAdapter` 接线**：
  - `groundTilemap` 拖入 `Ground`（**必接**，`IsWired` 只看它）。
  - `effectLayers` 每行一个 `Tilemap` ＋ 该层负责的 `States`（**至少接一层**，状态贴图盖在这些层上；一层都不接时状态只记逻辑不显示）。
  - `fallbackEffectTilemap` 接没在任何 `effectLayers` 行登记的状态；留空 = 回落 `effectLayers[0]`。
  - `initialSetupTilemap` 拖入 `InitialSetup`（可选，见下）。
  - `stateTiles` 数组**保持为空**（自动走约定的 `tiles/Tile_*.asset`）。
- **任一层不得与别的层指向同一个 Tilemap**：`TilemapAdapter.Awake` 会报错。`groundTilemap` 与任一 `effectLayers` 行同层最坏（状态结束时会连地板一起擦掉，地上出现空洞）；`initialSetupTilemap` 指错层最隐蔽（它读完会 `SetActive(false)`，开局把地板或效果层整个关掉，现象离病因很远）。
- **`InitialSetup` 是可选的**：不建该层，初始地块退回 `tile_initial` 表驱动。建了就必须单独一层且接进 `initialSetupTilemap`，否则你画的笔刷不生效且不报错。
- 🔴 **地板层只回答"这一格能不能站"，地貌归地块状态**：`TilemapAdapter.RegisterCells` 把所有地板格一律按 `Normal`（空地）登记。反应网是**双键驱动**的（`(原格地貌, 球种)` → 新地貌），于是：
  - **一级反应可达，不需要先铺任何地貌**：`空地 + 纯水 → 基础水`、`空地 + 纯土 → 基础土`、`基础土 + 纯水 → 泥浆`、`基础水 + 纯土 → 泥浆`。进 Play 直接扔水 / 扔土就能出泥浆。
  - **火 / 电 / 冰 / 植物那四类要先有对应地貌**，来源只有两条：在 `Grid/InitialSetup` 层刷几格（`Tile_BasicFire` / `Tile_BasicElectricity` / `Tile_BasicIce` / `Tile_BasicPlant`），或用种子播（每波备战期配给 1 颗，键盘 `E`）。
  - 笔刷只能刷在**有地板的格**上：`LoadInitialSetupTiles` 对没地板的格报 `[Grid] InitialSetup 层在格 (x,y,z) 刷了地块，但这一格没有地板` 并忽略（两张 Tilemap 必须挂在同一个 `Grid` 下，否则坐标对不上）。
  - 它读完就 `SetActive(false)` 隐藏，`TilemapRenderer Order` 填几都无所谓，按上表填 1 即可。

### 四、角色 Animator 控制器快速构建

角色的 View 子节点上还需要 `SpriteRenderer` 与 `ActorAnimationView`（`Presentation/Visual/ActorAnimationView.cs`）。

#### 4.1 挂载（Root-View 两层，别挂错节点）

```text
Player / Enemy        ← Root：Rigidbody2D + Collider2D + PlayerMotor/EnemyMotor + PlayerController/EnemyActor
└── View              ← localPosition 必须 (0,0,0)
    ├── SpriteRenderer
    ├── Animator      ← 本节产物挂这里
    └── ActorAnimationView
```

- **`Animator` 与 `ActorAnimationView` 都挂 `View`，不要挂 Root。** 将来受击抖动/后坐力/伪高度只改 `View.localPosition`；挂在 Root 上，抖动会和刚体位置打架。
- `ActorAnimationView` 的 `animator` / `spriteRenderer` 字段留空即可（`Awake` 用 `GetComponent` 从**本节点**自愈抓取；它**不会**往父级找，所以两者必须在同一个 `View` 上）。
- **`ActorAnimationView.useFlipX` 保持关闭**：`ActorMotor.Facing` 已把左右朝向落成 **Root 的 `localScale.x` 符号**，View 是 Root 的子节点，两条镜像叠在同一根 x 轴上会互相抵消（角色朝左反而显示成朝右，不报错）。同理 **动画美术不要自带左右翻转**。
- **敌人不用手工建：做成预制体**（`Assets/Resources/enemies/Enemy_<id>.prefab`，Root/View 结构同上）。`EnemyActor` 已不再运行期造 `View` 与头顶数字，见第五节。

#### 4.2 建立剪辑

把切好的帧拖进场景生成 `.anim`（采样率 12~15，循环动作勾 `Loop Time`）。现有可用图：

| 图 | 建议剪辑 |
| :-- | :-- |
| `art/Character/character_player_idle_zheng.png` / `character_player_idle_fan.png` | `Player_Idle*.anim`（Loop ✓） |
| `art/Character/character_player_walk_zheng.png` / `character_player_walk_fan.png` | `Player_Walk*.anim`（Loop ✓） |
| `art/Character/character_player_gun.png` | `Player_Throw.anim`（Loop ✗） |
| `art/Character/character_player_die.png` | `Player_Die.anim`（Loop ✗，播完停在末帧） |

#### 4.3 参数契约（`Presentation/Visual/AnimHashes.cs`，名字逐字符一致）

代码只按这些哈希推参数，名字写错**不报错**，表现为动画永远不切：

| 类型 | 参数 | 用途 |
| :-- | :-- | :-- |
| Float | `Speed` | 速度标量（单位/秒），Idle/Walk 混合 |
| Float | `MoveX` / `MoveY` | 本帧归一化移动方向，8 向混合树用 |
| Float | `FacingX` | 朝向水平分量，站住时也要保留 |
| Float | `FadeAlpha` | 尸体淡出系数：死亡剪辑自己用 `1 → 0` 的曲线驱动（参数默认值填 `1`），代码只读（`ActorAnimationView.FadeAlpha`）。**现状未接**：`Player_AC` / `Enemy_1_AC` / `Enemy_2_AC` 都没登记这个参数，`Assets/Resources/animation/**` 里也没有任何剪辑拉这条曲线 |
| Trigger | `Hurt` / `Die` | 受击 / 死亡（玩家与敌人共用） |
| Bool | `IsDashing` | 玩家冲刺（有持续段，故用 Bool） |
| Bool | `IsHurt` | 敌人受击僵直 |
| Trigger | `TriggerThrow` / `TriggerPlant` | 玩家投掷出手 / 放置 |
| Trigger | `Attack` | 敌人近战出手 |
| Trigger | `Impact` / `Collect` | 掉落物落地 / 被领取 |

> 死亡剪辑的**末帧**还要挂一个 AnimationEvent 调 `ActorAnimationView.OnDeathAnimationEnd`（靶点脚本就在 `View` 上那个 `ActorAnimationView`）：
> 它才是"死亡表现播完"的回收触发口。**兜底对两种情况都生效**：末帧事件未挂、或 `Controller` 留空（无可用 Animator）都会由 `VisualFeelTuning.deathFallbackSeconds` 到点收口 ——
> 因此"不挂末帧事件"不再导致尸体不回收，但会**提前到 1.0s 收口**：死亡剪辑时长若 > `deathFallbackSeconds`，请把该 SO 值调大（它是回收保险，不是剪辑时长）。
>
> **待人工验收**：现有剪辑的 `m_Events` 全为空（`Enemy_1_Die.anim` / `Enemy_2_Die.anim` 也在内，`m_StopTime` 0.833s），而两只敌人的 `Controller` 都非空 ⇒ `EnemyActor.Die`（`EnemyActor.cs:472`）既订阅末帧事件又起兜底协程，事件永不到，尸体一律由 1.0s 兜底收口（`0.833s < 1.0s`，当前不截断）。
> 判定方法：PlayMode 打死一只 `Enemy_1`，看尸体是否在约 1.0s 后消失（不是 0.83s，更不是永驻）；把末帧事件挂上后应收口时刻提前到剪辑结束、不再等满 1.0s（`Assets/Resources/tuning/VisualFeelTuning.asset` 里没有 `deathFallbackSeconds` 这一行，缺键取值请在编辑器 Inspector 里确认）。

#### 4.4 最小状态机（先跑通走跑）

> **仓库里已经有一份可直接用的** `Assets/Resources/animation/Player_AC.controller`（除 `FadeAlpha` 外的参数与 §4.3 一致），
> 且 `Assets/Resources/scane_prebs/Player.prefab` 的 `View/Animator` 已经接上它。下面 1~4 步是**重建 / 换一份**时的手顺。

1. 新建 `PlayerAnimator.controller`，加 Float 参数 `Speed`。
2. `Idle` ➔ `Walk`：条件 `Speed > 0.01`，**取消勾选 `Has Exit Time`**，`Transition Duration = 0`。
3. `Walk` ➔ `Idle`：条件 `Speed < 0.01`，**取消勾选 `Has Exit Time`**，`Transition Duration = 0`。
4. 把 controller 拖给 `View` 的 `Animator`。
5. **`Controller` 留空是合法配置（白模期）**：`HasValidAnimator` 为假时所有动画调用是安全 no-op，零报错零警告，`SpriteRenderer` 与 Y-Sort 照常工作。**没接 controller 时不要指望有动画，也别因此加警告日志。**

### 五、敌人预制体标准装配（`Assets/Resources/enemies/`）

**归档路径与命名**：必须放 **`Assets/Resources/enemies/`**，文件名 **`Enemy_<enemy 表的 id>.prefab`**（当前有 `Enemy_1.prefab` / `Enemy_2.prefab`）。
`CombatDirector.SpawnOne` 与 `CombatDummyHarness` 都按 `enemies/Enemy_{id}` 这条约定走 `AssetModule.Load<GameObject>`（与地块贴图同一套约定懒加载）。**缺件是硬错误**：Console 打 `[Combat] 严重阻断：未找到敌人预制体 Assets/Resources/enemies/Enemy_1.prefab！本次生成已取消。`，本次生成直接取消，**不会**在代码里拼白模兜底。
反过来的错也一样硬：根节点没挂 `EnemyActor` ⇒ `生成已作废` 并销毁刚实例化的物体；根节点没挂 `EnemyMotor` ⇒ `生成已作废`（它 `[RequireComponent(Rigidbody2D)]`）。

#### 5.1 结构（Root-View 两层，与角色同构）

```text
Enemy_1                ← Root：Rigidbody2D + CircleCollider2D + EnemyMotor + EnemyActor + YSortAgent
├── View               ← localPosition (0,0,0)
│   ├── SpriteRenderer
│   ├── Animator
│   └── ActorAnimationView
└── Hp_txt             ← localPosition Enemy_1 (0,1,0) / Enemy_2 (0,2,0)：遗留调试件，代码已不再读写（见下）
```

- **Root 的物理件**：`Rigidbody2D` 的 `Gravity Scale = 0`、`Constraints = Freeze Rotation Z`、`Interpolation = Interpolate`、`Collision Detection = Continuous`；`CircleCollider2D` 半径取 `Resources/tuning/EnemyTuning.asset` 的 `radius`（当前逐条：`Enemy_1` 0.3 / `Enemy_2` 0.5 —— 原 `enemy` 表的 `radius` 列已搬进这份 SO）。
  - `Gravity Scale` / `Freeze Rotation` 由 `ActorMotor.ApplyPhysics` 固化；`Interpolate` 与 `Continuous` 是敌人侧要求（击退会给到高速，离散检测会穿墙）。**预制体上写成同值**，否则 Inspector 显示与运行期真值是两个答案。
- **`EnemyActor.deathEffect`**：死亡特效由预制体配置（基准件是 `Shatter`）。代码不再写死 `EffectId`，改死亡表现改这一格，不用改代码。
- **`EnemyActor.enemyId`**：这只预制体对应 `enemy` 表的哪一行（`Enemy_1` 填 `1`，`Enemy_2` 填 `2`）。**只有场景里手摆的木桩读它**（`CombatRoot.AdoptSceneEnemy` / `CombatDummyHarness.EnsureDummy`）；波次怪的 id 由 `wave_enemy.enemy_id` 决定，与这一格无关。填错或忘填**不报错**，只表现成"场景木桩拿到了别的怪种的耐久与移速"（`Enemy_2` 忘填 = 精英怪顶着普通怪的 3 点耐久、3.5 移速）。
- **头顶数字已拔除，改用伤害飘字**：`EnemyActor` 不再读写 `Hp_txt`（`hpText` 字段与 `UpdateHpText` 已物理删除），受击改播 `EffectId.DamagePopup`（世界空间飘字，色值按 `Damage.Element` 查 `VisualPalette.DamageColor`）。基准件 `Enemy_1.prefab` / `Enemy_2.prefab` 下那个 `Hp_txt` 子节点（`TextMesh` ＋ 内置字体 `10102` / 内置字体材质 `10100`，`sortingOrder = 560`）**现在是死件**：留着不报错、也不再显示任何数字。飘字要的是挂 `PopupView` 的 `effects/DamagePopup.prefab`（**已在**：根节点挂 `PopupView`（`Presentation/Visual/PopupView.cs`），子节点 `Label` 是 `TMP_Text` 并接进 `PopupView.label`，字体是 `Assets/Fonts/蒙黑体 SDF.asset`），正式表现做进预制体美术后把这个死节点删掉即可。
- **`SpriteRenderer.m_Color` 是基线色，不是最终色**：`.color` 是顶点色乘数，`(1,1,1,1)` = 美术原色。运行期写它的是 `ActorTintDriver`（`EffectId.SlowTint` 减速垫色），它会把**首次看到的这个值捕获成基线**并在 `CleanAll` 时原样还原 ⇒ 想给身体做手绘淡染，改这一格即可，不会被洗掉；`EffectId.Flash` 闪白走的是材质属性块，根本不碰这一格。注意别在这里填有色值来"预演"减速色：那是状态，由 `VisualPalette.enemyBodySlowed` 给。
- **`SpriteRenderer.Materials[0]` 要挂 `M_SpriteFlash`**（`Resources/materials/M_SpriteFlash.mat`，Shader `DeepseaOil/2D/SpriteFlash`）：受击闪白靠片元向 `_FlashColor` 插值才能把黑发、暗色衣服也刷成纯白剪影 —— 顶点色乘数是乘法，乘以纯白等于原画，**不挂这个材质的角色闪白只会把浅色区域压亮，深色区域不动**（驱动会静默退化成乘法闪白：整段瞬态写满白、无渐变，不报错）。只挂**真身**那个渲染器；脚底 `ShadowView` 不要挂。**材质里的 `_MainTex` 是刻意留空的，别去填**：精灵贴图由 `ActorTintDriver.EnsureSpriteTexture` 在运行期按当前 `sprite.texture` 钉进去（`_MainTex` 一空，Shader 就落到默认白，闪白会变成一整块白剪影且淡出后不回原画）。
- **`View.localScale`**：`demo/Square.png` 是 100×100 像素 @ PPU 100 ⇒ 1 世界单位；要与碰撞体直径对齐就按该怪种 `EnemyTuning.radius` 的直径缩放（当前 `Enemy_1` 0.6 / `Enemy_2` 1.0；两只基准件的 `View.localScale` 都是 `1`）。`EnemyActor` 不碰 `localScale`，缩放全归预制体。
- `ActorAnimationView` 的 `animator` / `spriteRenderer` **建议在 Inspector 里显式连上**：留空也能在 `Awake` 自愈抓取，但显式连线才能保证 `EnemyActor.Awake` 抓到同一个渲染器（两个 `Awake` 的先后没有保证）。
- **`YSortAgent` 要手工挂在 Root**（`Presentation/Visual/YSortAgent.cs`）：它在 `LateUpdate` 里按锚点 y 把 `layers` 里的渲染器写进 `400~1000` 频带，锚点取 `EnemyActor.SortAnchor` / `PlayerController.SortAnchor`（物理体位置，不是被抖动改写的 `View`）。`layers` 只配**跟随 y 变化**的渲染器（真身 `View` 的 `SpriteRenderer`，`Offset = 0`）；**`ShadowView`（固定 310）与 `Hp_txt`（固定 560，已是死件）不要配进去** —— 进了 `layers` 就会一起被写进 Y 排序频带，影子盖住脚底、死件被无谓地逐帧改写。Target 拖 `SpriteRenderer` 组件本身（或它所在的 `View` 节点），**不要拖 Root**：Root 上没有 `Renderer`，拖上去不会被接受。`EnemyActor` / `PlayerController` 里原来的 `UpdateSortingOrder` 已删除，代码侧不再有第二个写档位的地方。
