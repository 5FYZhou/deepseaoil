## 1. 背景与目标

### 1.1 现状

- 白模两版已跑通投掷、敌人、波次、血量、格子泥浆
- 白模代码是脱离正式框架的硬编码实现：数值写死、单体类混杂关注点、HUD 是临时 `OnGUI`
- 正式框架（Data / Logic / Presentation 三层）就位，含 `ConfigModule` / `AssetModule` / `EventBus` / `EffectModule` / `UIMgr`

### 1.2 目标

把 v2 白模**已验证的玩法**迁移进正式框架：

1. 可测试的 Logic 层代码（纯 C#，零 UnityEngine 依赖）
2. 可扩展的格子系统（本次只实现泥浆格，骨架完整）
3. 走 Luban / SO 的数值通路
4. 走 `EventBus` / `UIMgr` 的 HUD
5. 删除全部白模代码，不留旧痕迹

### 1.3 非目标

- 不重构玩法
- 不新增机制（蒸汽、毒、火等留接口）
- 不保留旧白模、临时 HUD
- 不把 `PrimitiveSprites` 作为长期方案

## 3. 需求清单（8 个系统）

### 3.1 投掷物

**最终效果**：左键水球 / 右键土球；从玩家位置飞出，伪高度抛物线；鼠标落点**吸附到格子中心**；最远 5 单位；落地后球销毁并通知格子。

**需要**：

| #    | 内容                                                      |
| ---- | --------------------------------------------------------- |
| 1    | `BallData` 纯数据结构（起点 / 终点 / 时长 / 弧高 / 采样） |
| 2    | 球本体、阴影、驱动（Presentation 三组件）                 |
| 3    | 鼠标 → 世界点 → 格子中心的两段转换                        |
| 4    | 最大投掷距离 clamp（纯函数）                              |
| 5    | 球种枚举（Luban 承载）                                    |
| 6    | 落地回调：携带落点 cell 与球种                            |

**不需要**：飞行中命中检测、球本体物理体、复杂轨迹。

### 3.2 球效果

**最终效果**：球落地后**只通知格子**，不直接对敌人造成任何伤害或击退。

**需要**：

| #    | 内容                                                    |
| ---- | ------------------------------------------------------- |
| 1    | `IBallEffect` 接口                                      |
| 2    | 水球 → 通知格子"转泥浆状态"                             |
| 3    | 土球 → 通知格子"？"（待策划，本次空实现或触发一次冲量） |
| 4    | 球种与格子类型的映射表（Luban）                         |

**不需要**：球直接 `TakeDamage`、球携带泥浆系数、球 ID 去重。

### 3.3 敌人

**最终效果**：从玩家周围生成；直线追玩家但留 0.6 停止距离；3 点耐久；被打中变红闪烁 + 击退（可选）；被减速变深色；头顶写数字；死亡碎成 3 块。

**需要**：

| #    | 内容                                                        |
| ---- | ----------------------------------------------------------- |
| 1    | `EnemyLogic` + `Steering` + `EnemyVisual`（Logic 层纯逻辑） |
| 2    | `RigidbodyMotorBase` + `EnemyMotor`（空子类）               |
| 3    | `EnemyActor`（组合根）                                      |
| 4    | 实现 `IDamageable`                                          |
| 5    | **脚底中心**注册到 `EnemyCellRegistry`                      |
| 6    | `TakeDamage(Damage)` 唯一入口                               |
| 7    | 受击闪烁、耐久数字、死亡碎片                                |
| 8    | 击退**可选**（由 `Damage` 携带，非默认）                    |

**不需要**：`TakeDirectDamage`、敌人主动感知格子状态。

### 3.4 格子系统

**最终效果**：格子有状态（本次只实现泥浆）；状态由格子状态机管理；**状态转换时产生一次基础伤害**；状态可提交 Tick 请求；Tick 时对脚下敌人结算、对其它格子发起联动；联动形成连锁反应。

**需要**：

| #    | 内容                                                         |
| ---- | ------------------------------------------------------------ |
| 1    | `GridLogic`（格子状态持有者、Tick 调度、联动发起）           |
| 2    | `TileStateMachine`（状态机，管理状态切换）                   |
| 3    | `ITileState`（状态接口：`OnEnter` / `OnTick` / `OnExit`）    |
| 4    | `TileTickQueue`（双缓冲队列，一次性消费）                    |
| 5    | `EnemyCellRegistry`（独立于 GridLogic）                      |
| 6    | 联动机制（`TakeDamage` / `Linkage` 双通知）                  |
| 7    | 联动计数（接收方递减）                                       |
| 8    | 空间查询接口（`GetNeighbors4` / `GetNeighbors8` / `GetWithinRadius`） |
| 9    | 格子初始状态从关卡数据加载（Luban）                          |
| 10   | 泥浆格实现（行为 + 参数）                                    |
| 11   | **状态转换即产生基础伤害**（全局设定）                       |

**不需要**：其它格子类型、元素反应规则、复杂联动（本次无联动）。

### 3.5 玩家

**最终效果**：WASD 自由移动（不受格子约束）；100 点血；碰到敌人每 0.8 秒扣 10 点；受击被推开；打空后 1.2 秒重置。

**需要**：

| #    | 内容                                                      |
| ---- | --------------------------------------------------------- |
| 1    | `PlayerHealth`（纯逻辑，血量状态 + 无敌帧）               |
| 2    | `PlayerHealthController`（Presentation，物理查询 + 击退） |
| 3    | `PlayerMotor`（空子类）                                   |

**不需要**：`OnGUI` HUD、血量色块。

### 3.6 资源系统

**最终效果**：水球计数；靠近喷泉自动补给；HUD 显示数量；水球为 0 时瞄准环变红。

**需要**：

| #    | 内容                                              |
| ---- | ------------------------------------------------- |
| 1    | `PlayerResources`（纯逻辑，资源计数）             |
| 2    | `Fountain`（Presentation，触发补给）              |
| 3    | `WaterBall`（Presentation，飞向玩家）             |
| 4    | 资源变化事件（`EventBus<WaterBallCountChanged>`） |
| 5    | HUD 订阅事件刷新 UI                               |

**不需要**：`FindObjectOfType<ThrowSpawner>` 查找式耦合、setter 直刷 `TMP_Text`。

### 3.7 波次

**最终效果**：开局 1.5 秒后第一波；每波 4 只，0.25 秒间隔逐个出；清空后 2.5 秒下一波。

**需要**：

| #    | 内容                                          |
| ---- | --------------------------------------------- |
| 1    | `WaveLogic`（波次状态机，纯逻辑）             |
| 2    | `WaveDirector`（Presentation，建物体 + 驱动） |
| 3    | 生成位置计算（纯函数）                        |

**不需要**：波次规则写在 MonoBehaviour 的 `UpdateSpawn` 里。

### 3.8 输入与冷却

**最终效果**：左键水球（消耗 1，冷却 0.5s）；右键土球（不消耗，冷却 0.5s）。

**需要**：

| #    | 内容                                                         |
| ---- | ------------------------------------------------------------ |
| 1    | 走 `InputProvider` / `InputBuffer`（不直读 `Mouse.current`） |
| 2    | `AttackCooldown`（纯逻辑）                                   |
| 3    | `PlayerResources` 检查资源                                   |

**不需要**：白模的 `_nextTickTime` 时间比较。

## 4. 迁移边界

### 4.1 做

- 迁移白模已验证玩法
- 走正式框架的层、端口、事件、配置
- 走 `UIMgr` 的 HUD
- 走 `EffectModule` 的视觉表现（`LandingFlash` / `ShatterBurst`）

### 4.2 不做

- 重构玩法
- 新增机制
- 保留旧白模
- 保留临时 HUD
- 把 `PrimitiveSprites` 作为长期方案

### 4.3 改造清单

| 白模现状                          | 迁移后                                                       |
| --------------------------------- | ------------------------------------------------------------ |
| 硬编码数值                        | Luban 表 + SO（分界见 §4.4）                                 |
| 自由瞄准                          | 格子吸附                                                     |
| 单体类混杂                        | 拆分（`TileLogic` / `EnemyDirector` / `PlayerHealth` / `ThrowSpawner` 均拆） |
| `OnGUI` HUD                       | `UIMgr` 面板                                                 |
| 球直接伤害敌人                    | 球只通知格子                                                 |
| `TakeDamage` + `TakeDirectDamage` | 合并为 `TakeDamage`                                          |

### 4.4 数值分界规则

**四条判定规则**：

1. **谁调**：策划调 → Luban；程序调 → SO
2. **耦合程度**：紧密耦合的数值必须同源
3. **是否需要跨表校验**：需要 `ref` / `range` / `path` 校验 → Luban
4. **是否需要批量编辑**：多条同类数据 → Luban；单个全局配置 → SO

**归属样例**：

| 数值             | 归属               |
| ---------------- | ------------------ |
| 攻击范围         | Luban              |
| 玩家惯性加速度   | SO                 |
| 投掷速度与时间   | SO                 |
| 投掷最大距离     | SO（与投掷组同源） |
| 自动拾取判定范围 | Luban              |
| 敌人移动速度     | Luban              |
| 敌人耐久         | Luban              |
| 玩家移动速度     | SO                 |
| 泥浆减速系数     | Luban              |
| 泥浆持续时长     | Luban              |
| 波次敌人数       | Luban              |
| 波次间隔         | Luban              |
| 攻击间隔（玩家） | SO                 |
| 无敌帧时长       | Luban              |
| 玩家击退力度     | SO                 |
| 敌人击退力度     | SO                 |

**SO 资产位置**：`Assets/Resources/` 下（`AssetModule.Load<T>` 可加载）。

## 附：关键假设清单（A1~A16）

| #       | 假设                                                         |
| ------- | ------------------------------------------------------------ |
| A1      | 格子状态机钩子：`OnEnter` / `OnTick` / `OnExit`，每个钩子可提交 Tick 请求 |
| **A2**  | **Tick 请求是一次性消费的，被消费一次即消失；提交后必然被消费；状态切换时旧状态不再提交新请求，已提交的请求正常被消费** |
| A3      | `GridLogic` 与 `EnemyCellRegistry` 分离                      |
| A4      | 三个端口：`IDamageable` / `IEnemyResolver` / `IEnemyCellRegistry` |
| A5      | 同帧递归用双缓冲队列（模式 1）                               |
| A6      | 格子初始状态从 Luban 表加载（cell → 状态 ID）                |
| A7      | 格子参数走 Luban                                             |
| A8      | 敌人 ID 只增不复用                                           |
| A9      | 格子状态不叠加，由状态机转换                                 |
| A10     | 球落地 → `ThrowController` 直接调 `GridLogic.OnBallHit`，不走 EventBus |
| A11     | 格子 Tick 挂在 `GameRoot.Update` 顺序表内，`timeScale = 0` 时暂停 |
| **A12** | **格子状态转换 = 产生一次基础伤害（全局设定，所有状态都如此）；减速/击退等是额外效果** |
| A13     | 联动范围查询接口：`GetNeighbors4` / `GetNeighbors8` / `GetWithinRadius` |
| A14     | 联动计数在接收方递减                                         |
| A15     | 联动次数耗尽后由格子状态决定后续，框架不强制                 |
| A16     | `Damage` 重构为格子伤害事件：`Point` / `Amount` / 可选 `Impulse+Direction` / `Source` |
