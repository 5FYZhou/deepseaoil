# 粒子特效系统 · 需求分析

**状态**：设计已收敛，准备进入实现前的最后对齐。本文只描述"要什么"，不含代码。

---

## 一、任务背景与定位

### 背景

框架三层跑通，白模第一阶段交付。现在要补**粒子特效系统**，作为正式框架的一部分——白模单向使用它，但正式框架不认识白模。

### 定位

| 维度          | 结论                                                         |
| ------------- | ------------------------------------------------------------ |
| 所属层        | Presentation                                                 |
| 语义          | **纯工具**。谁调都行，不认识 EventBus，不认识 Logic          |
| 职责          | 管理所有特效的**播放与停止**——包括粒子、材质动画、Shader 动画、相机震动 |
| 触发          | 调用方决定何时播；EffectModule 只负责"怎么播"                |
| 与 Logic 关系 | **零依赖**。Logic 发布的事件由表现层组件订阅，组件再调 EffectModule |

### 明确不做

- 不做 EffectResponder（订阅集中层）——职责重叠，删特效要跑两处
- 不做"何时播"的策略——那是调用方的事
- 不做粒子/材质的**具体实现**——由用户自己写

## 二、EffectId 定稿

```csharp
public enum EffectId
{
    None = 0,            // 空/无特效
    HitSpark,            // 打击火花
    EnemyFlashWhite,     // 敌人白色闪白
    ObjectShake,         // 单个物品震动（血条抖动、受击震动等，或以此为基）
    ScreenShake,         // 屏幕震动
    MudSplash,           // 泥浆飞溅
    // 后续追加
}
```

`None = 0` 为哨兵值。后续追加时同步扩 enum。

## 三、数据类型需求

| 类型            | 用途         | 关键需求                                                     |
| --------------- | ------------ | ------------------------------------------------------------ |
| `EffectId`      | 特效类型标识 | enum，编译期检查                                             |
| `EffectContext` | 播放参数     | 位置 / 方向 / 缩放 / 强度 / 跟随 Transform；提供 `At(pos)` 便利工厂 |
| `EffectHandle`  | 播放实例句柄 | 带 `Generation`；支持 `IsValid` / `None` / 相等比较          |
| `EffectStats`   | 调试快照     | 活跃实例数 / Driver 数 / 池内待用数                          |

### 强度字段 `Intensity` 的语义

- 0~1，**由 Driver 解释**
- `ScreenShake` 用它做"取最大值合并"
- `HitSpark` 用它做粒子数量/大小缩放
- `MudSplash` 用它做飞溅量
- EffectModule 不解释它，只传递

## 四、EffectModule 职责

### 对外接口

```
Play(id, ctx) → EffectHandle
Stop(handle)
CleanAll()
Init()
Tick(dt)
Dispose()
GetStats()
```

### 职责

| 负责                                | 不负责                             |
| ----------------------------------- | ---------------------------------- |
| 按 `EffectId` 分发到对应 Driver     | 特效的具体实现（粒子/材质/Shader） |
| 维护 `EffectId → Driver` 映射表     | 单例合并策略（下沉到 Driver）      |
| 预加载清单的统一管理                | 池化（下沉到 Driver）              |
| 每帧 `Tick` 所有 Driver             | 感知 EventBus                      |
| 拒绝未注册的 `EffectId`（LogError） | 感知 Logic / 白模                  |

### 失败模式

| 场景                        | 处理                                   |
| --------------------------- | -------------------------------------- |
| `Play` 的 `EffectId` 未注册 | `LogError`，返回 `EffectHandle.None`   |
| 同一 `EffectId` 被注册两次  | 后覆盖前，`LogError`                   |
| `Init` 时预加载资源为 null  | `LogError` 并继续（不阻止游戏启动）    |
| `Play` 时池已满             | `LogWarning`，返回 `EffectHandle.None` |

**所有失败都不抛异常**——特效是表现层的锦上添花，不应阻塞游戏。

## 五、IEffectDriver 抽象需求

### 接口职责

```
EffectHandle Play(EffectId id, in EffectContext ctx)
void Stop(EffectHandle handle)
void Tick(float dt)
bool IsSingleton { get; }
```

### 单例 vs 多实例

| 类型       | 例子                                   | Play 行为      | Stop 语义                          |
| ---------- | -------------------------------------- | -------------- | ---------------------------------- |
| **多实例** | HitSpark / EnemyFlashWhite / MudSplash | 每次都新建实例 | 停该 handle 对应实例；过期则无操作 |
| **单例**   | ScreenShake / ObjectShake / WeaponGlow | 合并到当前实例 | 停当前实例（任一 handle 都生效）   |

**`IsSingleton` 由 Driver 声明**。EffectModule 转发 `Stop` 时不判断，直接交给 Driver。

### 合并策略下沉

Driver 内部决定：

- `ScreenShake`：取最大强度 + 重置计时
- `ObjectShake`：取最大强度，不重置计时
- `WeaponGlow`：覆盖，重置计时
- 多实例型不合并

**EffectModule 不感知合并的存在**。

### 每个 Driver 内部维护

- 自己的池（见第六节）
- 自己的单例状态（如果有）
- 自己的 Tick 逻辑
- 自己的 Follow 目标检测（对象被销毁时自动停止）

## 六、Pool 优化需求

### 现状问题

现有 `Foundation/Pool.cs` 存在以下问题：

| #    | 问题                       | 后果                                        |
| ---- | -------------------------- | ------------------------------------------- |
| 1    | 无上限                     | 高频 Play 时无限增长，内存爆炸              |
| 2    | 池空时现场创建 + Warning   | Warning 刷屏；现场创建违背"池空=超载"的语义 |
| 3    | 无活跃计数                 | 无法判断池是否够用                          |
| 4    | 无统计（峰值、命中率）     | 无法调优容量                                |
| 5    | `Prewarm` 调用 `onRelease` | 语义可疑——预热对象还没"用过"就 Release      |
| 6    | `Clear` 不销毁对象         | GameObject 池需要 Destroy 语义              |
| 7    | 无 `IDisposable`           | 进程退出时清理不明确                        |
| 8    | 池空策略单一               | 有时想扩容，有时想丢弃，有时想 Warning      |
| 9    | 无池名                     | 日志里看不出哪个池出问题                    |

### 优化需求

**核心需求**：

1. **容量上限**——构造时指定 `maxSize`，超限时按策略处理
2. **活跃计数**——跟踪 `active` / `idle` / `peak`
3. **池空策略可配**——至少支持 `CreateAndWarn` / `DropSilently` / `Throw`
4. **统计快照**——`GetStats()` 返回当前状态（active / idle / peak / 累计创建数）
5. **池名**——构造时传入，用于日志

**语义修正**：

6. `Prewarm(count)` **不再调用 `onRelease`**——预热是"造对象"，不是"归还对象"
7. `Clear()` 明确语义——清空 idle 部分，还是全部？idle 部分需要销毁回调（比如 `Destroy(GameObject)`）

**清理语义**：

8. 实现 `IDisposable`——`Dispose` 时调 `onDestroy`（可选回调）销毁每个对象

**兼容性**：

9. **现有 `Pool<T>` / `PoolInClass<T>` / `PoolInMono<T>` 的调用方不能破**——要么保留旧 API 兼容，要么全仓库替换调用点

### 优化后的形态（需求层面）

期望有**两种池**：

| 类型             | 用途             | 语义                         |
| ---------------- | ---------------- | ---------------------------- |
| `Pool<T>`        | 无上限，通用缓存 | 池空时现场创建（保留旧语义） |
| `BoundedPool<T>` | 有上限，用于特效 | 池空时按策略丢弃/警告/抛异常 |

或者用**一种池 + 策略对象**：

| 类型      | 用途                                               |
| --------- | -------------------------------------------------- |
| `Pool<T>` | 统一实现，构造时传入 `maxSize` 和 `overflowPolicy` |

**选择权在你**。两条路都能达到目的，区别只是 API 风格。

### 用户已有的初步建议（来自对话）

- "全面优化，使其更合理更易用"
- 用户未明确选择单池 or 双池，需要在实现前拍板

## 七、预加载与懒加载策略

### 混合模式

| 类型       | 策略                                                         |
| ---------- | ------------------------------------------------------------ |
| 常用资源   | 预加载——`EffectModule.Init` 时用 `AssetModule.Load<T>` 同步窄路一次性加载 |
| 非常用资源 | 懒加载——首次 `Play` 时发起 `AssetModule.LoadAsync<T>`，完成后自动播放 |

### 预加载登记表

**方案 A（已定）** ：EffectModule 内部维护一个 `static readonly EffectId[] PreloadList`。

- 加/删预加载项只改一处
- 集中评估"启动时加载了多少资源"

### 预加载的时机

- **GameRoot.Awake 阶段 1**（与 ConfigModule / AssetModule 同阶段）
- 预加载**同步完成**后才进 Start 阶段
- 代价：启动阻塞一段；收益：所有预加载资源 Play 时同步可用

### 懒加载的时机

- 首次 `Play` 该 EffectId 时发起异步加载
- 资源到达后自动播放（调用方不管）
- 加载期间重复 `Play`：合并到同一个加载请求（复用 AssetModule 的 pending 机制）

### 加载失败的策略（已定 A1）

- **LogError 并继续**
- 该 EffectId 对应的驱动标记为"资源缺失"，后续 Play 直接 `None` 返回
- 不重试、不降级、不阻塞

## 八、触发路径与职责边界

### 定案：EffectModule 是纯工具

```
Logic 发布 EventBus<EnemyHit>
    ↓
表现层：EnemyController 订阅
    ↓
EnemyController.OnHit() 自由决定：
    EffectModule.Play(HitSpark, ctx)
    EffectModule.Play(EnemyFlashWhite, ctx)
    EffectModule.Play(ScreenShake, ctx)
    ——或者什么都不播
```

### 边界

- **EffectModule 不认识任何 EventBus 事件**——写进契约
- **EffectModule 不认识任何 Logic 类型**——只认识 EffectId / EffectContext / EffectHandle
- **删除一个特效只需改一处**——调用方的 OnHit()，不去 EffectResponder 找

## 九、生命周期与装配

### GameRoot 装配改动

| 时机            | 改动                                                         |
| --------------- | ------------------------------------------------------------ |
| `Awake` 阶段 1  | 在 `AssetModule.Init()` 之后加 `EffectModule.Init()`         |
| `Update` 顺序表 | 在第 ② 步之后加第 ③ 步 `EffectModule.Tick(dt)`               |
| `OnDestroy`     | 在 `AssetModule.Dispose()` **之前**调 `EffectModule.Dispose()` |

### 顺序约束

- `EffectModule.Init` **必须**在 `AssetModule.Init` 之后——预加载依赖 AssetModule
- `EffectModule.Dispose` **必须**在 `AssetModule.Dispose` 之前——EffectModule 释放资源时要经 AssetModule 归还引用计数
- `EffectModule.Tick` 的位置——**只要每帧被调即可**，具体位置影响很小

### 切场景复位

`SceneService.Load` 的复位清单从四项扩到**五项**：

```
① Time.timeScale = 1f
② PauseService.SetPaused(false)
③ EventBus.ClearAll()
④ AssetModule.OnSceneSwitch()
⑤ EffectModule.CleanAll()      ← 新增
```

**`CleanAll` 而非 `StopAll`** —— 避免与 `Stop(handle)` 混淆。语义：清空所有活跃实例，全部归还池。

### 线程约束

- **仅主线程调用**——与 AssetModule 一致
- 整个框架主动避免多线程，EffectModule 不需要锁

## 十一、与白模的关系

### 单向透明

- **白模使用正式系统**：`Prototype/` 下的代码可以调 `EffectModule.Play`
- **正式系统不认识白模**：EffectModule 不引用任何 `Prototype` 类型
- **白模可以随时重构**：EffectModule 的接口稳定，白模怎么改都不影响正式系统

### 白模的使用示例（不入正式文档）

```
// 在 ThrowSpawner.ApplyKick 里
EffectModule.Play(EffectId.MudSplash, EffectContext.At(landingPos));

// 在 EnemyActor.TakeDamage 里
EffectModule.Play(EffectId.EnemyFlashWhite, new EffectContext {
    Follow = transform,
    Intensity = 1f,
});

// 在命中敌人时
EffectModule.Play(EffectId.ScreenShake, new EffectContext {
    Intensity = 0.5f,
});
```

### 已知限制

| #    | 限制                     | 影响                                |
| ---- | ------------------------ | ----------------------------------- |
| 1    | 懒加载首次 Play 有延迟   | 首次播该特效时可能卡几百毫秒        |
| 2    | 池满时丢弃新请求         | 极端情况下特效不播，有 LogWarning   |
| 3    | 未注册 EffectId 直接丢弃 | 拼错枚举名会静默不播（有 LogError） |
| 4    | 不做对象池的自动缩容     | 峰值容量会一直保留                  |

### 不做（本阶段）

- 不做 EffectResponder
- 不做特效的参数配置化（SO 驱动）—— enum 足够
- 不做跨场景特效保留——切场景清空
- 不做特效优先级调度——不排队，不合并（除了单例合并）
- 不做粒子系统的 LOD——不做距离裁剪
