## 阶段 1 · Pool 优化

**内容**：按阶段 0 的方案改造 `Foundation/Pool.cs`。

**拆解**：

1. 确定池的上限、活跃计数、统计快照的字段
2. 确定池空策略的形态
3. 修正 `Prewarm` 语义
4. 明确 `Clear` 与 `Dispose` 的语义
5. 处理旧调用方兼容

**产出**：改造后的 Pool 代码 + 调用方适配（若有）。

**验收**：

- 旧调用方全部编译通过
- 新增能力（上限 / 统计 / 策略）可用
- 不引入回归

**需重读**：`Foundation/Pool.cs` 全文、所有引用它的位置。

## 阶段 3 · EffectModule 骨架

**内容**：`EffectModule` 静态类，实现注册、分发、生命周期。

**拆解**：

1. 内部字典 `EffectId → IEffectDriver`
2. `Init` / `Tick` / `Dispose` 生命周期
3. `Play` / `Stop` / `CleanAll` 对外接口
4. `GetStats` 调试接口
5. 失败模式：未注册 / 重复注册 / 池满 / 资源缺失

**产出**：`EffectModule` 一个文件。

**验收**：

- 不接任何 Driver 也能编译
- 空跑 `Init` / `Tick` / `Dispose` 不报错
- 调 `Play(未注册 id)` 返回 `None` 并 LogError

**需重读**：需求文档 §4、§5、§7。

## 阶段 5 · GameRoot 装配与生命周期

**内容**：把 EffectModule 接进框架。

**拆解**：

1. `GameRoot.Awake` 阶段 1 加 `EffectModule.Init()`
2. `GameRoot.Update` 顺序表加 `EffectModule.Tick(dt)`
3. `GameRoot.OnDestroy` 加 `EffectModule.Dispose()`（在 AssetModule 之前）
4. `SceneService.Load` 复位清单加第五项 `CleanAll`

**产出**：3 处改动 + 1 处复位清单。

**验收**：

- Play 进场景后 EffectModule 已 Init
- 每帧 Tick 被调用（加临时 Log 验证）
- 切场景时 CleanAll 被触发
- 退出 Play 时 Dispose 被调用

**需重读**：`表现层.md` §3、`逻辑层.md` §6。

## 阶段 6 · 预加载集成

**内容**：实现预加载登记表 + 懒加载。

**拆解**：

1. `PreloadList` 常量数组
2. `Init` 时用 `AssetModule.Load<T>` 同步预加载
3. 加载失败 LogError 并继续
4. 懒加载路径：首次 Play 时 `LoadAsync`
5. 加载期间重复 Play 合并到同一请求

**产出**：EffectModule 内部增加预加载与懒加载逻辑。

**验收**：

- 预加载清单里的资源，Play 时立即有
- 清单外的资源，首次 Play 有延迟、第二次无延迟
- 预加载资源缺失时，Play 返回 None 并 LogError，游戏不崩

**需重读**：`数据层.md` §2（AssetModule 契约）。

## 建议顺序的核心理由

| 顺序                     | 理由                                         |
| ------------------------ | -------------------------------------------- |
| Pool 最先                | EffectModule 和所有 Driver 都依赖它          |
| 类型定义先于实现         | 接口定稿后，EffectModule 与 Driver 可以并行  |
| EffectModule 先于 Driver | 先有分发骨架，再接具体实现                   |
| 装配先于白模             | 白模需要 EffectModule 已在 GameRoot 里跑起来 |
| 预加载最后               | 依赖 EffectModule + AssetModule 都稳定后再接 |
| 文档最后                 | 代码稳定后写文档，避免反复改                 |

## 已知会拖慢进度的坑

| 坑                           | 规避                                                |
| ---------------------------- | --------------------------------------------------- |
| Pool 改造破坏旧调用方        | 阶段 1 先跑全仓库编译 + 旧测试                      |
| EffectModule 接口反复改      | 阶段 2 类型定义先审一遍再动手                       |
| Driver 实现混进 EffectModule | 每个 Driver 严格在 `Drivers/` 下，不碰 EffectModule |
| 预加载清单漏项               | 阶段 6 先把清单写死，跑通后再谈优化                 |
| 白模污染正式系统             | 白模只调 Play，不引用任何 EffectModule 内部类型     |
