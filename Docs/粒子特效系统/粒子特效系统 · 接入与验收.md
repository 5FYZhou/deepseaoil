# 粒子特效系统 · 接入与验收

三类读者：**写调用点的人**看 §1 §4；**做预制体内容的人**看 §2 §3；**验收的人**看 §5–§7。设计、契约与修订登记在《粒子特效系统 · 设计与契约》。

## 1. 前置：装配在哪里

`EffectModule` 的 `Init` / `Preload` **只由 `GameRoot.Awake` 触发**，不是自动的 MonoBehaviour。所以"有没有 `GameRoot`"决定了特效能不能播：

| 场景 | `GameRoot` | 结论 |
| :-- | :-- | :-- |
| 战斗切片验收入口（`Assets/Scenes/EmptyTest.unity`） | 有 | 可进 Play 验池与碎裂/高亮；**面板要自己挂**（见下） |
| `SampleScene` | **无**（场景里只有一台 `Main Camera`） | 直接 `Play` → 一条 `[Effect] EffectModule.Play 在 Init 之前被调用。` ＋ `None`，不出特效 |
| `TextTile` | **无** | 同上 |

> `TestEffect` 这个场景**已经不存在**（`Assets/Scenes/` 下只有 `EmptyTest` / `SampleScene` / `TextTile` 三个，另有一份 URP 模板场景在 `Assets/Settings/Scenes/`）。

**补装配的方法**：Hierarchy → Create Empty → 命名 `GameRoot` → Add Component → `Game Root`（`Presentation/Root/GameRoot.cs` 的组件显示名）。该组件**没有任何需要拖拽的字段**；副作用是这个场景会一并初始化 Config / Asset / Effect / Pause / Save（既有代码、幂等）。

> ⚠️ `EffectDebugPanel` **当前不在任何场景里**（按 `.meta` 里的 guid 在三个场景里都查不到）。要验面板，得先给场景里某个物体 Add Component → `Effect Debug Panel`；建议与 `MovementDebugPanel` 同物体。它的统计行与播放按钮是"没有面板就看不到"的验收工具，不影响特效本身。

> 白模演示场景（`TestThrow` 等）**没有 `GameRoot`**，且已随白模进入删除清单 —— 不要再把"白模投掷演示"当作特效验收路径。

## 2. 建一个特效预制体（内容规约）

1. `Assets/Resources/` 下建 `effects/`（**小写**，与 `EffectCatalog.KeyPrefix` 一致）。`Assets/Resources/effects/` **已存在**（里面是 `HitSpark.prefab` 与 `MudSplash.prefab`）。
2. Hierarchy 空白处右键 → **Effects → Particle System**，改名 = **枚举名**（当前只有 `HitSpark`、`MudSplash` 两行需要预制体）。
3. 按下表设置；`Looping` / `Play On Awake` / `Stop Action` / URP 材质四项是**硬要求**，其余是观感。
4. 把对象从 Hierarchy 拖进 `Assets/Resources/effects/`，再删掉场景里那个临时对象。

| 模块 | 项 | 值 | 为什么 |
| :-- | :-- | :-- | :-- |
| Main | Looping | **关** | 一次性爆发；开着永不结束（`EstimateDuration` 会直接返回 +∞），只能靠 `Stop` / `CleanAll` / 跟随丢失回收，或撞上 `+5s` 硬超时被强杀并警告 |
| Main | Play On Awake | **关** | 池对象每次借出会 `SetActive(true)`，开着会自己先播一次（双份粒子） |
| Main | Simulation Space | **World** | 对象是复用的，Local 会把上一轮粒子拖着走 |
| Main | **Stop Action** | **None** | 设成 `Disable` / `Destroy` 会让对象自己禁用或销毁 → **池拿到死对象，第二次播放起永久失效** |
| Main | Duration | 自定 | 决定多久回收：超时 = 各子系统的 `Duration + startLifetime` 取最大值（`ParticleDriver.EstimateDuration`），再加 `+5s` 硬超时兜底 |
| Emission | Rate over Time | 一次性特效设 **0** | 配合 Bursts 用 |
| Emission | Bursts | Time 0，Count 12~20 | 数量太少会显得"几粒豆子" |
| **Renderer** | **Material → Shader** | **`Universal Render Pipeline/Particles/Unlit`** | ⚠️ 默认材质是 Built-in 的 `Particles/Standard Unlit`，URP 下渲染成**粉紫色** |
| Renderer | Sorting Layer / Order | 与目标同层，Order 调高 | 否则被地面挡住（Y 排序频带 `500..559`，见 `Presentation/Visual/RenderOrder.cs`） |
| Renderer | Render Mode | Billboard | 2D 常用；`Max Particle Size` 只是上限钳制，不会放大 |

- **文件名必须逐字符等于枚举名**：Key 是 `effects/<枚举名>` → `Resources.Load<GameObject>` 查 `effects/<枚举名>`（不带扩展名）。Windows 上大小写写错**可能侥幸加载成功**，打包到 Android / iOS 必失败。
- **例外：程序生成的驱动不需要预制体**（当前是 `EnemyShatter` 与 `TileHighlight`）。它们的形状是逐像素算出来的（碎片是 `PrimitiveSprites.Circle` 正圆，高亮是 `PrimitiveSprites.Square` 整格方块），`AssetKey` 返回空串 ⇒ `EffectModule` 完全不碰 `AssetModule`。**别去找 `effects/EnemyShatter.prefab` / `effects/TileHighlight.prefab`** —— 它们不存在，也不需要存在。（已删掉的 `LandingRing` 曾属于这一类，现在整个特效都没了。）
- 判定"路径对不对"的快捷方式：删掉/改名预制体后进 Play，Console 会给出**期望路径**——`[Effect] 特效资源缺失：MudSplash → 期望 Assets/Resources/effects/MudSplash.prefab。该特效后续 Play 一律返回 None（不重试、不阻塞启动）。`
- **同一 `EffectId` 只会尝试加载一次**：缺失会被记进 `EffectModule._missing`，此后 `Play` 直接 `None`（那条 `[Asset] load failed` ＋ 这条 `[Effect]` 各只出现一次，不会反复刷）。修好预制体要重进 Play。
- 复合预制体（父物体 ＋ 子粒子系统）**支持**：驱动会驱动全部子系统（含未激活子物体）；**一个都没有时**打一次 Error 并把对象**还回池**。
- **z 由驱动各自决定**：`ParticleDriver` 写位置时**保留**预制体自带的 z（只换 x / y）；两个程序生成的驱动（`EnemyShatterDriver` / `TileHighlightDriver`）则把 z 明确写成 `0`。2D 排序看的是 Sorting Layer / Order，不是 z —— 见下一节。

## 3. 尺寸与观感调参

"特效看起来很大/很小"要分清是哪个量在起作用——它们是三件独立的事：

| 量 | 管什么 | 注意 |
| :-- | :-- | :-- |
| `Start Size` | **每个粒子**多大 | 作者值就是基准；`Intensity = 1`（`At` 系列）时与预制体**逐位一致** |
| `Start Speed` × `Start Lifetime` | **这一团**铺多远 | 最常见的"为什么这么大"来源 |
| `Shape`（半径 / 角度 / Scale） | 出生点散布范围 | Sphere 的默认半径是 **1**，等于"粒子从 1 单位外开始飞" |

**本项目的尺度参照**（都来自战斗切片的配置与场景，改相机后要重新对）：

| 参照 | 值 | 出处 |
| :-- | :-- | :-- |
| 投掷落地冲量半径 | 1.2 | `Assets/Resources/tuning/ThrowTuning.asset` 的 `impulseRadius` |
| 球半径 | 0.22 | 同上的 `ballRadiusMeters` |
| 敌方单位直径（判定半径 0.45） | ≈ 0.9 | `ConfigWorkspace/Data/enemy.xlsx` 的 `radius` |
| 相机正交半高（战斗切片场景） | 5 | `EmptyTest.unity` 里 `Main Camera` 的 `orthographic size` |

**实测案例（保留作为量纲参照）**：验收时反馈"`StartSize` 设好了却还是很大"。查预制体序列化数据后确认 **`Start Size` 并未被覆盖**（当时的作者值：`HitSpark` = 0.1、`MudSplash` = 0.3；`Constant` 模式，`Size over Lifetime` / `Size by Speed` / 3D 尺寸全关，缩放 1），真正的原因是 `Start Speed 20 × Start Lifetime 0.2 = 4 世界单位 ≈ 半个屏幕高（相机半高 5）`，再叠加 `Shape = Sphere` 的默认半径 1。修法是内容侧的：**Start Speed 20 → 3~5**、Shape 半径 1 → 0.05~0.2、Burst Count 提到 12~20，需要"飞出去但别飞远"时用 `Limit Velocity over Lifetime`（Drag 0.5~0.9）。

## 4. 在代码里播一次

```csharp
// 一次性：位置 ＋ 方向 ＋ 颜色（EnemyActor.Die 的真实写法）
EffectContext ctx = EffectContext.At(Position, hitDirection);
ctx.Tint = EnemyVisual.BodyColorNormal;
EffectModule.Play(EffectId.EnemyShatter, in ctx);

// 持续型：一次 Play ＋ 每帧 Update，不瞄了 Stop（TileHighlightView.OnAimChanged 的真实写法）
if (_handle.IsValid && EffectModule.Update(_handle, in ctx)) return;   // 已在播 → 只更新
_handle = EffectModule.Play(EffectId.TileHighlight, in ctx);            // 句柄失效 → 重建
...
EffectModule.Stop(_handle);
```

| 项 | 契约 |
| :-- | :-- |
| 返回值 | `EffectHandle`；**失败一律 `EffectHandle.None`（全零），永不抛异常**。不关心可以忽略返回值 |
| `EffectContext` | 纯数据 `struct`；`At` / `At(dir)` / `OnTarget` 三个工厂都给 `Scale = 1`、`Intensity = 1` = **按预制体原样播**（`Tint` / `Radius` / `Duration` 工厂**不设**，走各自的读取处默认：白 / 1 / 驱动默认时长） |
| 手写部分字段 | `new EffectContext { Intensity = 0.5f }` 也安全：读取处归一化（`Scale ≤ 0 → 1`、`Direction` 零向量 → `up`、`Tint` alpha 0 → 白、`Radius ≤ 0 → 1`；**只有 `Duration` 不归一化**） |
| `Intensity` | `[0,1]`，由驱动解释。`ParticleDriver`：`粒子量/大小 = 作者值 × Lerp(0.4, 1, Intensity)`；想更强的小体积效果用 `Scale` |
| `Tint` / `Radius` / `Duration` | 只有"把它们当参数"的驱动才读：`EnemyShatter` 读 `Tint`（身体色）与 `Duration`（默认 0.35 s、上限 5 s）；`TileHighlight` 读 `Tint`（可用白 / 阻挡红）与 `Radius`（边长 = `Radius × 2`）。`ParticleDriver` **三个都不读**（颜色在预制体里） |
| 跟随 | `Follow` 非空时 `ParticleDriver.Tick` 每帧把特效挪到目标上；**目标被销毁（Unity 假 null）即自动回收** |
| `Update(handle, ctx)` | 持续型特效的"只更新"入口。返回值**只代表"句柄有效"**（`false` 只有两种情形：未 `Init`、句柄为 `None`）；不支持的驱动是 no-op（接口默认实现），**不报错**。⚠️ **它不判断"句柄是否对得上当前这次播放"** —— 逐帧校验在驱动里（`TileHighlightDriver.UpdateInstance` 对编号/代次不符的句柄静默忽略） |
| `Stop(handle)` | 提前停一次播放；句柄过期/无效/no-op 三种情况都安全 |
| `EffectId.None` | 静默返回 `None`——写 `None` 表示"这次不播"，不是错误 |
| 调用频率 | 一次性特效每次落地/每次命中各一次即可；**持续型不要每帧 `Play`**（那等于每帧新建一个实例），用 `Play` 一次 ＋ 每帧 `Update` |

## 7. 排错速查

| 症状 | 最可能原因 | 处置 |
| :-- | :-- | :-- |
| `[Effect] EffectModule.Play 在 Init 之前被调用。` | 场景里没有 `GameRoot` | §1 |
| 面板显示 `EffectModule 未 Init（GameRoot 没跑起来？）` | 同上 | §1 |
| `特效资源缺失：X → 期望 Assets/Resources/effects/X.prefab` | 目录不是 `effects`（或多层嵌套）、文件名 ≠ 枚举名、不在 `Resources` 下 | 照期望路径逐字符核对 |
| 粒子是**粉紫色方块** | 材质用了 Built-in shader | Renderer → Material → Shader 改 `Universal Render Pipeline/Particles/Unlit` |
| 第一次正常、之后再也出不来 | 预制体 `Stop Action` = `Disable` / `Destroy` | 改 **None** |
| 每次播放**双份**粒子/一闪 | `Play On Awake` 开着 | 关掉 |
| 粒子跟着球或玩家跑 | `Simulation Space` = `Local` | 改 **World** |
| 粒子被地面挡住 / 盖住敌人 | Sorting Layer / Order | 提到前景层、调高 Order |
| "`Start Size` 设好了却还是很大" | **先分清是"每个点大"还是"这一团铺得远"**：`Start Speed × Start Lifetime` 与 `Shape` 半径 | §3 |
| 切 Curve / Random Between Two Curves 后尺寸突然变大 | 作者幅度住在乘数里——`E6` 已修（`作者值 × k`）；若仍异常，检查 `startSize.curveMultiplier` 与 `Size over Lifetime` | §3、《设计与契约》E6 |
| `池已满` 刷屏 | 同屏实例超过 `EffectCatalog` 的上限 | 调大 `maxSize`（警告本身已 1 秒节流，文案里带累计丢弃次数） |
| 面板 `驱动 4` 但池内远少于 12 | 有预制体没加载成功 | 看 Console 的 `[Asset] load failed` 行 |
| 面板按钮只有 2 个（没有 `EnemyShatter` / `TileHighlight`） | 按钮由 `EffectCatalog.All` 生成，说明这两行被删了 | 恢复 `new EffectSpec(EffectId.EnemyShatter, EffectDriverKind.EnemyShatter, maxSize: 16)` 与 `new EffectSpec(EffectId.TileHighlight, EffectDriverKind.TileHighlight, isSingleton: true, maxSize: 1)`；这两个**不需要预制体** |
| `播放 EnemyShatter` 只飞出 1~2 块碎片 | 上一批碎片没还回来（同屏碎裂次数超过 `maxSize`，碎片池上限 = `16 × 3 = 48`） | 等 5 s，或调大 `maxSize`；Console 会写 `[Effect] EnemyShatter 碎片池已满（上限 48），本次少飞 N 块` |
| 瞄准格**再也不亮**（也不报错） | 调用方手里的句柄是"这次清理之前"的：`TileHighlightDriver.UpdateInstance` 对"编号或代次对不上当前这次播放"的句柄**静默忽略**，而 `EffectModule.Update` **仍返回 `true`**（它只校验"句柄有效"），于是调用方一直走 `Update` 分支、永远不重新 `Play` | 当前调用方已规避：`CombatRoot.OnDestroy` → `TileHighlightView.Detach()` → `Hide()` 会把 `_handle` 复位为 `None`。**（待核对）**：若在 `CombatRoot` 还活着的时候单独调 `EffectModule.CleanAll()`，这条规避不再生效（没有任何代码这么做，属推断） |
| `effects/EnemyShatter.prefab` 找不到 | 不存在，也不该存在（`TileHighlight` 同理） | 程序生成的驱动不读资源；直接 `Play` 即可 |
| 找 `LandingRing` 相关的报错 / 资产 / 文档 | **这个特效已整个删除**（阶段九） | 见《设计与契约》§12 的删除清单；不要再按旧文档去建 `effects/LandingRing.prefab` |

## 8. 回滚

代码侧按文件回滚（`Effects/` 是新增目录，整体删除即回到接入前）：

```powershell
# 特效系统本身
git checkout -- Assets/Scripts/Foundation/Pool.cs Assets/Scripts/Presentation/Root/GameRoot.cs

Remove-Item Assets/Scripts/Presentation/Debug/EffectDebugPanel.cs*

```

内容侧：`Assets/Resources/effects/` 整个目录删掉即可（没有任何代码引用具体预制体路径，Key 是运行期拼的）。

⚠️ **白模迁移之后，`Effects/` 不再是"整个删掉就干净"**：`EffectId.EnemyShatter` / `TileHighlight` 与它们各自的驱动是战斗切片的一部分，删掉 `Effects/` 会让 `EnemyActor.cs`（`EffectId.EnemyShatter`）与 `TileHighlightView.cs`（`EffectId.TileHighlight` / `EffectModule.Update`）编译不过。要回滚整个战斗切片，按《框架设计/分层设计/表现层.md》§8 的组件表逐个拆（那条链没有单独的迁移报告了：`Docs/temp/` 已清空）；只想回滚特效系统的**原有部分**（粒子那两行）时，保留 `Effects/` 目录、只把 `EffectCatalog` 里 `HitSpark` / `MudSplash` 两行装配删掉即可（`LandingRing` 本来就已经没有了，不用再删）。
