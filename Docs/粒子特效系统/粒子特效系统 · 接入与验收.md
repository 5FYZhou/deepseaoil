# 粒子特效系统 · 接入与验收

三类读者：**写调用点的人**看 §1 §4；**做预制体内容的人**看 §2 §3；**验收的人**看 §5–§7。设计、契约与修订登记在《粒子特效系统 · 设计与契约》。

## 1. 前置：装配在哪里

`EffectModule` 的 `Init` / `Preload` **只由 `GameRoot.Awake` 触发**，不是自动的 MonoBehaviour。所以"有没有 `GameRoot`"决定了特效能不能播：

| 场景 | `GameRoot` | 结论 |
| :-- | :-- | :-- |
| 战斗切片验收入口（`Assets/Scenes/EmptyTest.unity`） | 有 | 可直接验面板、池、落地环与碎裂 |
| `SampleScene` / `TestEffect` | 有 | 可直接验面板与池 |
| 任何没有 `GameRoot` 的场景 | **无** | 直接 `Play` → 一条 `[Effect] EffectModule.Play 在 Init 之前被调用。` ＋ `None`，不出特效 |

**补装配的方法**：Hierarchy → Create Empty → 命名 `GameRoot` → Add Component → `Game Root`。该组件**没有任何需要拖拽的字段**；副作用是这个场景会一并初始化 Config / Asset / Effect / Pause / Save（既有代码、幂等）。

> 白模演示场景（`TestThrow` 等）**没有 `GameRoot`**，且已随白模进入删除清单 —— 不要再把"白模投掷演示"当作特效验收路径。

## 2. 建一个特效预制体（内容规约）

1. `Assets/Resources/` 下建 `effects/`（**小写**，与 `EffectCatalog.KeyPrefix` 一致）。`Resources` 已存在（里面有 `ui/`）。
2. Hierarchy 空白处右键 → **Effects → Particle System**，改名 = **枚举名**（`HitSpark`、`MudSplash`）。
3. 按下表设置；`Looping` / `Play On Awake` / `Stop Action` / URP 材质四项是**硬要求**，其余是观感。
4. 把对象从 Hierarchy 拖进 `Assets/Resources/effects/`，再删掉场景里那个临时对象。

| 模块 | 项 | 值 | 为什么 |
| :-- | :-- | :-- | :-- |
| Main | Looping | **关** | 一次性爆发；开着永不结束，会被 `+5s` 硬超时强杀 |
| Main | Play On Awake | **关** | 池对象每次借出会 `SetActive(true)`，开着会自己先播一次（双份粒子） |
| Main | Simulation Space | **World** | 对象是复用的，Local 会把上一轮粒子拖着走 |
| Main | **Stop Action** | **None** | 设成 `Disable` / `Destroy` 会让对象自己禁用或销毁 → **池拿到死对象，第二次播放起永久失效** |
| Main | Duration | 自定 | 决定多久回收：超时 = `Duration + startLifetime + 5s` |
| Emission | Rate over Time | 一次性特效设 **0** | 配合 Bursts 用 |
| Emission | Bursts | Time 0，Count 12~20 | 数量太少会显得"几粒豆子" |
| **Renderer** | **Material → Shader** | **`Universal Render Pipeline/Particles/Unlit`** | ⚠️ 默认材质是 Built-in 的 `Particles/Standard Unlit`，URP 下渲染成**粉紫色** |
| Renderer | Sorting Layer / Order | 与目标同层，Order 调高 | 否则被地面挡住 |
| Renderer | Render Mode | Billboard | 2D 常用；`Max Particle Size` 只是上限钳制，不会放大 |

- **文件名必须逐字符等于枚举名**：Key 是 `effects/<枚举名>` → `Resources.Load<GameObject>` 查 `effects/<枚举名>`（不带扩展名）。Windows 上大小写写错**可能侥幸加载成功**，打包到 Android / iOS 必失败。
- **例外：程序生成的驱动不需要预制体**（当前是 `LandingRing` 与 `EnemyShatter`）。它们的形状是逐像素算出来的（贴地环复用 `PrimitiveSprites.GroundDiscOrRing`，碎片是正圆），`AssetKey` 返回空串 ⇒ `EffectModule` 完全不碰 `AssetModule`。**别去找 `effects/LandingRing.prefab`** —— 它不存在，也不需要存在。
- 判定"路径对不对"的快捷方式：删掉/改名预制体后进 Play，Console 会给出**期望路径**——`[Effect] 特效资源缺失：MudSplash → 期望 Assets/Resources/effects/MudSplash.prefab。该特效后续 Play 一律返回 None（不重试、不阻塞启动）。`
- 复合预制体（父物体 ＋ 子粒子系统）**支持**：驱动会驱动全部子系统（含未激活子物体）。

## 3. 尺寸与观感调参

"特效看起来很大/很小"要分清是哪个量在起作用——它们是三件独立的事：

| 量 | 管什么 | 注意 |
| :-- | :-- | :-- |
| `Start Size` | **每个粒子**多大 | 作者值就是基准；`Intensity = 1`（`At` 系列）时与预制体**逐位一致** |
| `Start Speed` × `Start Lifetime` | **这一团**铺多远 | 最常见的"为什么这么大"来源 |
| `Shape`（半径 / 角度 / Scale） | 出生点散布范围 | Sphere 的默认半径是 **1**，等于"粒子从 1 单位外开始飞" |

**本项目的尺度参照**（都来自战斗切片的配置与场景，改相机后要重新对）：

| 参照 | 值 | 出处 |
| :-- | :-- | :-- |
| 投掷落地冲量半径 | 1.2 | `Assets/Resources/tuning/ThrowTuning.asset` 的 `impulseRadius` |
| 球半径 | 0.22 | 同上的 `ballRadiusMeters` |
| 敌方单位直径（判定半径 0.45） | ≈ 0.9 | `ConfigWorkspace/Data/enemy.xlsx` 的 `radius` |
| 相机正交半高（战斗切片场景） | 5 | 场景里的 `Main Camera.Size` |

**实测案例（保留作为量纲参照）**：验收时反馈"`StartSize` 设好了却还是很大"。查预制体序列化数据后确认 **`Start Size` 并未被覆盖**（当时的作者值：`HitSpark` = 0.1、`MudSplash` = 0.3；`Constant` 模式，`Size over Lifetime` / `Size by Speed` / 3D 尺寸全关，缩放 1），真正的原因是 `Start Speed 20 × Start Lifetime 0.2 = 4 世界单位 ≈ 半个屏幕高（相机半高 5）`，再叠加 `Shape = Sphere` 的默认半径 1。修法是内容侧的：**Start Speed 20 → 3~5**、Shape 半径 1 → 0.05~0.2、Burst Count 提到 12~20，需要"飞出去但别飞远"时用 `Limit Velocity over Lifetime`（Drag 0.5~0.9）。

## 4. 在代码里播一次

```csharp
EffectModule.Play(EffectId.MudSplash, EffectContext.At(point));            // 位置（满强度）
EffectModule.Play(EffectId.HitSpark,  EffectContext.At(pos, direction));   // 位置 ＋ 方向
EffectModule.Play(EffectId.HitSpark,  EffectContext.OnTarget(transform));  // 跟随目标
```

| 项 | 契约 |
| :-- | :-- |
| 返回值 | `EffectHandle`；**失败一律 `EffectHandle.None`（全零），永不抛异常**。不关心可以忽略返回值 |
| `EffectContext` | 纯数据 `struct`；`At` / `At(dir)` / `OnTarget` 三个工厂都给 `Scale = 1`、`Intensity = 1` = **按预制体原样播** |
| 手写部分字段 | `new EffectContext { Intensity = 0.5f }` 也安全：读取处归一化（`Scale ≤ 0 → 1`、`Direction` 零向量 → `up`） |
| `Intensity` | `[0,1]`，由驱动解释。`ParticleDriver`：`粒子量/大小 = 作者值 × Lerp(0.4, 1, Intensity)`；想更强的小体积效果用 `Scale` |
| 跟随 | `Follow` 非空时每帧把特效挪到目标上；**目标被销毁即自动停止回收** |
| `Stop(handle)` | 提前停一次播放；句柄过期/无效/no-op 三种情况都安全 |
| `EffectId.None` | 静默返回 `None`——写 `None` 表示"这次不播"，不是错误 |
| 调用频率 | 每次落地/每次命中各一次即可；同帧多次 `Play` 是多次独立播放（单例型除外） |

## 5. 验收清单

| # | 操作 | 判据 |
| --: | :-- | :-- |
| 1 | 在**有 `GameRoot` 的场景**（当前是战斗切片验收入口 `EmptyTest.unity`）进 Play | Hierarchy 多出 `[Effects]` 根（Play 下带 DontDestroyOnLoad）；Console **无** `[Effect]` 开头的 Error |
| 2 | 看调试面板第一行 | `特效: 活跃 0 / 驱动 4 / 池内待用 12`（12 = 预热 8 ＋ 4；两个程序生成的驱动预热 0，所以数字没变；池内不足说明有预制体没加载成功） |
| 3 | 鼠标移到画面中间 → 点 `播放 HitSpark` | 鼠标处爆出粒子；回执行变 `HitSpark → Effect#1g1`；`活跃` 1 → 播完自动回 0 |
| 4 | 点 `播放 MudSplash` | 同上，回执 `MudSplash → Effect#2g1` |
| 5 | 点 `播放 LandingRing` / `播放 EnemyShatter` | **不需要任何预制体**：落点环 / 碎片立刻出现（`ctx` 用面板的默认值：半径 1、白、时长取驱动默认）。这两行是程序生成驱动的冒烟测试 |
| 6 | 点 `全部清空 (CleanAll)` | `活跃` 立刻归 0、屏幕粒子立即消失、回执 `CleanAll`；`g` 后面的代次 +1（旧句柄自动失效） |
| 7 | 点 `未注册探针 (ScreenShake)` | 回执 `→ None` ＋ Console 一条 `EffectId ScreenShake 未注册：EffectCatalog 里没有这一行。`，**不崩** |
| 8 | 战斗：左键朝空地投水球 | 落点出**两个环**（球色冲量圈 ＋ 灰白格子圈）＋ 该格变泥浆；Console 无 `[Effect]` Error |
| 9 | 战斗：右键投土球 | 只出**一个环**（冲量圈，球色）；土球不改格子，所以没有格子圈 |
| 10 | 战斗：把敌人打到 0 耐久 | 死亡瞬间出扇形 3 块碎片（`EnemyShatter`） |
| 11 | 连投 5~8 发 | 无卡顿、**无** `池已满` 警告 |
| 12 | 把 `EffectCatalog.cs` 的 `MudSplash` 行临时改成 `maxSize: 2, prewarm: 0` → 等编译 → 连点 3 次 `播放 MudSplash` | 第 3 次 `→ None` ＋ 一条 `池已满（上限 2）`（**1 秒内只报一次**）。**验完改回 `maxSize: 16, prewarm: 4`** |
| 13 | 把 `MudSplash.prefab` 改名 `MudSplash_bak` → 重进 Play | 启动 **2 条** Error（`[Asset] load failed: …effects/MudSplash` ＋ `[Effect] 特效资源缺失：…期望路径…`）；面板池内少 4；投水球**无粒子但不崩**、**不反复刷错**。改回名字 |
| 14 | Esc 暂停 | 粒子与落地环冻住（`EffectModule.Tick(Time.deltaTime)`，`timeScale = 0` ⇒ `dt = 0`）；恢复后继续 |
| 15 | 停止 Play | 无 `Destroy may not be called…`、无 `Some objects were not cleaned up` |

## 7. 排错速查

| 症状 | 最可能原因 | 处置 |
| :-- | :-- | :-- |
| `[Effect] EffectModule.Play 在 Init 之前被调用。` | 场景里没有 `GameRoot` | §1 |
| 面板显示 `EffectModule 未 Init（GameRoot 没跑起来？）` | 同上 | §1 |
| `特效资源缺失：X → 期望 Assets/Resources/effects/X.prefab` | 目录不是 `effects`（或多层嵌套）、文件名 ≠ 枚举名、不在 `Resources` 下 | 照期望路径逐字符核对 |
| 粒子是**粉紫色方块** | 材质用了 Built-in shader | Renderer → Material → Shader 改 `Universal Render Pipeline/Particles/Unlit` |
| 第一次正常、之后再也出不来 | 预制体 `Stop Action` = `Disable` / `Destroy` | 改 **None** |
| 每次播放**双份**粒子/一闪 | `Play On Awake` 开着 | 关掉 |
| 粒子跟着球或玩家跑 | `Simulation Space` = `Local` | 改 **World** |
| 粒子被地面挡住 / 盖住敌人 | Sorting Layer / Order | 提到前景层、调高 Order |
| "`Start Size` 设好了却还是很大" | **先分清是"每个点大"还是"这一团铺得远"**：`Start Speed × Start Lifetime` 与 `Shape` 半径 | §3 |
| 切 Curve / Random Between Two Curves 后尺寸突然变大 | 作者幅度住在乘数里——`E6` 已修（`作者值 × k`）；若仍异常，检查 `startSize.curveMultiplier` 与 `Size over Lifetime` | §3、《设计与契约》E6 |
| `池已满` 刷屏 | 同屏实例超过 `EffectCatalog` 的上限 | 调大 `maxSize`（警告本身已 1 秒节流） |
| 面板 `驱动 4` 但池内远少于 12 | 有预制体没加载成功 | 看 Console 的 `[Asset] load failed` 行 |
| 落地环 / 碎裂不出现，Console 有 `EffectId LandingRing 未注册` | `EffectCatalog` 少了那一行（或被改坏了） | 恢复 `new EffectSpec(EffectId.LandingRing, EffectDriverKind.LandingRing, maxSize: 16)` 一行；这两个**不需要预制体** |
| `effects/LandingRing.prefab` 找不到 | 不存在，也不该存在 | 程序生成的驱动不读资源；直接 `Play` 即可 |

## 8. 回滚

代码侧按文件回滚（`Effects/` 是新增目录，整体删除即回到接入前）：

```powershell
# 特效系统本身
git checkout -- Assets/Scripts/Foundation/Pool.cs Assets/Scripts/Presentation/Root/GameRoot.cs
Remove-Item -Recurse -Force Assets/Scripts/Presentation/Effects
Remove-Item Assets/Scripts/Presentation/Debug/EffectDebugPanel.cs*
Remove-Item Assets/Tests/Runtime/Editor/粒子特效Tests.cs*
```

内容侧：`Assets/Resources/effects/` 整个目录删掉即可（没有任何代码引用具体预制体路径，Key 是运行期拼的）。

⚠️ **白模迁移之后，`Effects/` 不再是"整个删掉就干净"**：`EffectId.LandingRing` / `EnemyShatter` 与两个新驱动是战斗切片的一部分，删掉它们会让 `LandingResolver` / `EnemyActor` 编译不过。要回滚整个战斗切片，请按《迁移完成报告》§6 的路径级回滚命令走；只想回滚特效系统的**原有部分**（粒子那两行）时，保留 `Effects/` 目录、只把 `EffectCatalog` 的两行粒子装配删掉即可。
