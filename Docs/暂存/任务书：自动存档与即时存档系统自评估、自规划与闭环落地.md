
# 任务书：自动存档与即时存档系统自评估、自规划与闭环落地

## 1. 角色定位与执行纪律
- 严格遵循 `AGENTS.md`、`Docs/工程/架构约束.md` 与 `Docs/工程/注释规范.md`。
- 本任务采用**自评估与自适应规划范式**：你必须首先对工程现状进行全景只读审计，校准《自动存档实现方案 v1.0》与本地源码的物理差异，形成执行计划后再落地实现。
- **交付硬性指标**：交付 100% 完整带命名空间、异常防护的生产级代码，严禁出现 `// ...`、严禁使用 `// TODO` 等偷懒占位。
- **注释预算净零**：想加注释先删等量；新增代码行禁止写入多余叙事注释；仅允许使用单行 `<summary>` / `<remarks>`。
- **Hot-Path 0 GC 铁律**：存档导出与回填逻辑不得在战斗主循环（`FixedUpdate`）产生无谓的持续堆内存分配。

## 3. 第一阶段：全景源码只读自评估（强制工序）

在动笔写代码前，你必须**以只读模式**检索并核对以下 7 处源码现实，并在最终报告第一节明确汇报核对结果：

1. **服务容器检查 (`GameRoot.cs`)**：
   - 核对 `GameRoot` 是否只在 `_services` 列表中注册了 `SaveService`，而**缺少对外公开的只读属性 `public SaveService Save { get; private set; }`**？若缺少，规划在 `GameRoot.cs` 补上暴露入口。
2. **地貌存续倒计时检查 (`TableTileState.cs`)**：
   - 核对 `Assets/Scripts/Logic/Grid/States/TableTileState.cs` 中，`_duration` 与 `_elapsed` 字段是否对外部私有？是否需要补充只读属性 `public float RemainingDuration => _duration > 0f ? Mathf.Max(0f, _duration - _elapsed) : -1f;`？
3. **掉落物落点坐标检查 (`DropActor.cs`)**：
   - 核对 `Assets/Scripts/Presentation/Drop/DropActor.cs` 中，`Landing` 坐标是否为 protected？是否需要向外部公开 `public Vector2 LandingPosition => Landing;` 以支持确定性着陆保存？
4. **活体敌人状态导出检查 (`EnemyActor.cs` & `CombatDirector.cs`)**：
   - 核对 `CombatDirector` 的 `_enemies` 列表访问权限，以及如何从 `EnemyActor` 提取 `enemyId` 与残存 `Hp`。
5. **波次逻辑倒计时检查 (`WaveLogic.cs`)**：
   - 检查 `WaveLogic` 中倒计时字段 `_timer`、待刷怪计数 `_remaining`、当前波次号 `_waveIndex` 与游标 `_cursor` 的现有保护级别，确定回填函数 `ImportSave` 所需写入的字段。
6. **UI 槽位结构检查 (`SavePanel.cs` & `SaveSlot.cs`)**：
   - 读取 `Assets/Scripts/Presentation/UI/Panel/SavePanel.cs` 与 `Assets/Scripts/Presentation/UI/SaveSlot.cs`，确认现有按钮名（`BtnSave0` ~ `BtnSave3`）与文本控件名，核实 UI 贴图展示的承接组件（是否有 Image 控件用于显示缩略图）。
7. **URP 管线命名空间检查**：
   - 确认工程引用了 `UnityEngine.Rendering` 与 `UnityEngine.Rendering.Universal`，检查 `UniversalRendererData` 是否就绪。

## 4. 第二阶段：自适应任务分解与落地实施

完成第一阶段审计并对齐细节后，严格按以下模块次序实施编码：

### 任务 4.1：创建纯数据序列化契约 DTO
- **新建文件**：`Assets/Scripts/Data/Save/GameSaveDTO.cs`
- **规范**：
  - 命名空间属于 `DeepseaOil.Data`。
  - 包含 `SaveHeaderDTO`、`GameSaveData`、`PlayerSaveData`、`WaveSaveData`、`EnemySaveData`、`TileSaveData`、`DropSaveData`。
  - 所有类与结构体标记 `[System.Serializable]`，字段完全由基础值类型构成，支持 `JsonUtility` 零损序列化。
  - `SaveHeaderDTO` 包含槽位号、时间戳、标题文本、格式化时间字符串、自动存档标记等字段。

### 任务 4.2：子系统状态导出与回填接口补齐
- **文件 1：`Assets/Scripts/Logic/Grid/States/TableTileState.cs`**
  - 增加属性：`public float RemainingDuration => _duration > 0f ? Mathf.Max(0f, _duration - _elapsed) : -1f;`
- **文件 2：`Assets/Scripts/Presentation/Drop/DropActor.cs`**
  - 增加公开属性：`public Vector2 LandingPosition => Landing;`
- **文件 3：`Assets/Scripts/Logic/Player/PlayerStats.cs`**
  - 增加方法：`public PlayerSaveData ExportSave(Vector2 position)`
  - 增加方法：`public void ImportSave(PlayerSaveData data)`（夹取校验并刷新 HUD）
- **文件 4：`Assets/Scripts/Logic/Wave/WaveLogic.cs`**
  - 增加方法：`public WaveSaveData ExportSave()`
  - 增加方法：`public void ImportSave(WaveSaveData data)`（回填倒计时与出怪游标，并通知 Phase 刷新）
- **文件 5：`Assets/Scripts/Logic/Grid/GridLogic.cs`**
  - 增加方法：`public List<TileSaveData> ExportTiles()`（遍历 `_machines`，过滤 Normal 格）
  - 增加方法：`public void RestoreTiles(List<TileSaveData> list)`（遍历调用 `SwitchTileState` 覆盖重建）
- **文件 6：`Assets/Scripts/Presentation/Actor/CombatDirector.cs`**
  - 增加方法：`public List<EnemySaveData> ExportEnemies()`（收集活跃活体怪物数据）
  - 增加方法：`public void RestoreEnemies(List<EnemySaveData> list)`（清场、按 ID 加载 Prefab、实例化、差值扣血还原残血、绑定 `OnEnemyDied` 委托并挂接组合根）
- **文件 7：`Assets/Scripts/Presentation/Drop/DropDirector.cs`**
  - 增加方法：`public List<DropSaveData> ExportDrops()`（落实“确定性着陆”：取所有在场活体掉落物的 `LandingPosition`）
  - 增加方法：`public void RestoreDrops(List<DropSaveData> list)`（在落点原地重建处于静态的掉落物实体）

### 任务 4.3：创建 URP 2D 后处理抓取 Pass
- **新建文件**：`Assets/Scripts/Presentation/RenderPass/SaveCaptureFeature.cs`
- **规范**：
  - 命名空间属于 `DeepseaOil.Presentation.RenderPass`。
  - 继承 `ScriptableRendererFeature`，内部包含单例访问与 `SaveCapturePass`。
  - 执行事件点：`RenderPassEvent.AfterRenderingPostProcessing`。
  - 内部持有固定规格（320×180）`RenderTexture`，通过 `Blit` 将摄像机颜色纹理降采样拷贝。
  - 使用 `AsyncGPUReadback.Request` 异步回读像素数据，并在后台任务线程（`Task.Run`）中编码为 PNG 字节流，通过回调通知存盘服务。完全消除主线程卡顿。
  - 提供同步降级方案：若平台或驱动不支持异步回读，提供安全回退。

### 4.4：实装 SaveService 核心调度与 IO 管线
- **文件**：`Assets/Scripts/Logic/Services/SaveService.cs`
- **实现细节**：
  - 继承并实现 `IService`，定义统一服务契约（存盘、读盘、元数据查询、缩略图查询）。
  - **槽位物理存储规范**：
    - 数据路径：`Application.persistentDataPath/saves/slot_{id}.json`
    - 缩略图路径：`Application.persistentDataPath/saves/slot_{id}_thumb.png`
  - **故障安全原子写入**：
    - 写入流程：先写 `slot_{id}.json.tmp`，校验写入完毕后调用 `File.Replace` 替换原文件（不存在则 `File.Move`）。
  - **缩略图加载与本地缓存**：
    - 维护 `Dictionary<int, Sprite> _thumbCache`，避免 UI 打开时反复读取硬盘。
    - 内存释放：在 `Dispose` 时销毁所有生成的 `Texture2D` 与 `Sprite`，防止纹理内存泄漏。
  - **自动与手动槽位分流**：
    - `Slot 0`：专门保留给备战期自动存档。
    - `Slot 1 ~ 3`：供手动存档。

### 4.5：表现层接线闭环 (`GameRoot.cs`、`CombatRoot.cs`、`SavePanel.cs`)
- **文件 1：`Assets/Scripts/Presentation/Root/GameRoot.cs`**
  - 增加公开属性 `public SaveService Save => _saveService;`。
- **文件 2：`Assets/Scripts/Presentation/Root/CombatRoot.cs`**
  - 监听 `WavePhaseChanged`：当进入 `WavePhase.Prep` 阶段时，触发自动存档 `Save(0, isAuto: true)`。
  - 增加全局状态导出入口与全局读盘恢复入口：
    `public GameSaveData CollectGameState(int slotIndex, bool isAuto)`
    `public void RestoreGameState(GameSaveData data)`
  - 在 `Assemble` 执行完毕时检测是否有待加载槽位，若有则触发 `RestoreGameState`。
- **文件 3：`Assets/Scripts/Presentation/UI/Panel/SavePanel.cs` & `SaveSlot.cs`**
  - 绑定 `BtnSave0` ~ `BtnSave3` 点击事件：调用存盘或读盘。
  - 刷新槽位视图：调用 `SaveService.GetSlotHeader(i)` 与 `GetSlotThumbnail(i)` 绑定文字与图片。
