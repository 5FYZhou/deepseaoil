# 敌人转向抖动：分诊、修复与验收

> 起因：`Docs/任务/寻路优化.md`。目标是在**不重写流场**的前提下消除"追玩家时抽搐"。
> 结论一句话：抽搐不是流场算错路，而是**决策每帧翻面**＋**账本在反向那一帧不限幅**＋**玩家身体不在流场里**三件事叠加；
> 修法是给方向加闸门（只平滑、不改决策）、给卡死判据加贴脸豁免，并把 L1 调参一次性调到位。

> **2026-10-19 现状注记**：L2.2 模式滞回与 L2.3 固定前视路标已由 `EnemyPathFollower`（固定前视 ＋ 航点保持 ＋ 拐点扫描 ＋ 直线捷径）落地，
> `IsStraightDescend` 与直线/阶梯模式已删除；`Navigator.ModeSwitches` 改为 `DesiredSwitches`（原始期望方向 >20°/物理帧的计数）。
> L2.4 停靠环已由 `stopDistance` 0.75/0.90 ＋ `√(2a·d)` 刹车 ＋ 0.15 环外滞回落地。下文的实测数据是**改前基线**，保留作对照；
> 当前测试数与门禁基线以 `Docs/待办.md` 为准。
> **验收口径**：命令方向（20° 阈值）与单帧 |Δv| 是判据；`DesiredSwitches` 只是原始期望方向的噪声读数（改后仍有 21 次，但命令方向 20° 为 0 次），不是验收项。

## 1. 根因与分诊（L0）

四条机制（按贡献排序，与任务书一致）：

| # | 机制 | 落点 | 为什么编译器/测试都拦不住 |
| - | ---- | ---- | ------------------------ |
| ① | 直线 / 阶梯**每帧重判**，无滞回 | `EnemyNavigator.Resolve`（`IsStraightDescend`） | 两条腿都"合理"，只有观感错：实测原始方向切换 9–15 次/135 帧，单帧命令方向转过 101° |
| ② | **反向当帧瞬变**，配置加速度在这帧不存在 | `ActorLedger.SteerTowards` 反向分支 | 数学上那一支取的是未限幅的 `desired − current`（见第 5 节），单帧 \|Δv\| 实测 **5.02 u/s = 251 u/s²**，配置加速度 5 的 **50 倍** |
| ③ | **玩家身体未入流场** | `NavField.Build` 只读地块阻挡；`CombatRoot` 怪↔玩家碰撞是开的 | 顶住→速度归零→`DetectStuck` 判"卡死"→换步（换的还是一张不认玩家身体的场）→约 0.44 秒一轮 |
| ④ | 停靠环无滞回 ＋ 刹车滑行 1.2 格 | `stopDistance 0.6`、加速度 5 | 玩家一折返，敌人滑过玩家再掉头，正好把 ③ 触发起来 |

**分诊口径**（避免盲改）：验收夹具（`寻路Tests.玩家折返与贴脸顶住都不该抖`）在一次运行里同时量三条读数 ——
命令方向相邻帧夹角、单帧 \|Δv\|（读账本本帧的**提交量**，不含物理压速）、`Navigator.JamCount`；
另加 `Navigator.ModeSwitches`（原始方向翻转次数，`EnemyNavigator` 里的只读计数器）。

**改前实测（基线 ＋ 只加 `ModeSwitches` 计数器，不修任何东西）**：

```
135 帧：命令方向单帧转过 60° 共 5 次；峰值单帧 |Δv| 5.02（251 u/s²，上限 0.50）；JamCount 2；原始方向切换 15 次
翻面帧 第 73 帧：转过 69°，本帧速度 1.87 / 第 80 帧：转过 101°，本帧速度 1.44 /
        第 104 帧：转过 91°，本帧速度 3.42 / 第 106 帧：转过 85°，本帧速度 3.51
```

结论：**`JamCount` 在涨 ⇒ 机制③ 成立**（`JamCount 2`）；**命令方向在满速上翻 85–101°、\|Δv\| 251 u/s² ⇒ 机制①② 成立**。
两条都要修，只调参不够 —— 这也是 L1 单独做时"幅度下降但不消失"的原因。

### 2.1 方向闸门（L2.1，收益最大）

`EnemySteeringGate` 是一个**纯滤波器**，只吃"这一帧的原始方向 ＋ 当前速度 ＋ 帧时刻"：

1. **开门两条件**：单帧原始方向转过 `FlipDegrees`(45°)，或出现**抖动**（这一帧的原始方向比上一帧更靠回上上帧那一侧）。
   —— 前者是"翻面"，后者是"反复横跳"；一帧之内的小改动（≤45°）原样通过。
2. **门开着**：按 `turnRateLimit`（度/秒）与一阶低通（`turnSmoothSeconds`）推着命令走，追上原始方向（≤6°）就放行。
3. **前半平面约束（恒生效）**：命令方向与当前速度的夹角永不过 90°。
   这条是"单帧 \|Δv\| ≤ 5×加速度×Δt"能成立的原因：`ActorLedger.SteerTowards` 的反向分支**不做加速度限幅**（第 5 节），
   命令一旦越过 90°，账本那一帧就把速度整块翻过去。
4. **同一帧幂等**：按 `now` 判，同一物理帧内状态机与诊断各调一次拿到的必须是同一个方向。
5. **不滤的路径**：没网格 / 场给不出一步 / 目标停住（回退）与**换步**（脱困）走 `Reset`，把状态直接对到那条方向。
   换步是离散动作，拖成划弧就出不去。

**关键不变量：门关着时输出原样等于决策。** 直线/阶梯、绕障、软分离、停靠的既有语义一个都没动；
改后 `ModeSwitches` 仍有 9 次（决策照旧在翻），而命令方向一次都没转过 60° —— 这正是"只平滑，不改决策"。

### 2.2 卡死贴脸豁免（L2.5）

`EnemyLogic.DetectStuck` 里加一条：目标在 1 格内时不计卡死（`JamExemptRange`）。

任务书给的另一条判据（"窗口内沿期望方向净位移 < 0.1 格"）**没有采用**：正对玩家顶住时净位移本来就≈0，
换成位移判据仍然会判成卡死，摘不掉机制③。`CombatRoot` 的怪↔玩家碰撞一行未动。

### 2.3 L1 调参（会改手感，需实机复核）

| 参数 | 改前 | 改后 | 理由 |
| ---- | ---- | ---- | ---- |
| `acceleration`（普通/精英） | 5 / 8 | **12 / 16** | 刹停距离 1.22 → 0.51 格，滑过玩家再掉头的机会大幅减少（机制④） |
| `stuckFrames` | 10 | **18** | 假卡死更难触发（0.36 秒） |
| `jamFrames` | 12 | **6** | 真卡死时横向位移减半，压机制③的振幅 |
| `separationWeight` | 0.5 | **0.25** | 方向抖动幅度减半 |
| `separationRadius` | 0.6 | **0.45** | 同上 |
| `turnRateLimit` / `turnSmoothSeconds` | — | **540 / 0.05** | 闸门参数，按怪种可分别热改 |

**手感风险**：加速度翻倍会明显"更贴人"（起步更急、击退滑停更短）。这一条必须实机判定；
不满意只需把 `EnemyTuning.asset` 的 acceleration 往回收，闸门与豁免不依赖它。

## 3. 验收（改前红 / 改后绿）

夹具：`NewMaze(OpenField(24, 8))` ＋ `MotorProbe` 假物理 —— **位置自己积分**，并做引擎会做的那件事：
身体贴住时把速度压到零（下一帧帧首读到的就是它）。玩家在敌人正前方 1.8 格处以 8 单位/秒横向折返 3 次，再顶住它的脸 0.6 秒。

> 为什么折返段要保持 1.8 格间距：**贴住身体会把速度压没**，正好把"满速撞见原始方向掉头"这一条盖掉
> （第一版夹具就是这么假的：命令方向只翻 4 次、单帧 |Δv| 只有 0.10，红线根本显不出来）。

| 判据 | 改前 | 改后 | 断言 |
| ---- | ---- | ---- | ---- |
| 相邻帧命令方向夹角 > 60° | **5 次**（最坏 101°） | **0 次** | ≤ 2 |
| 单帧 \|Δv\|（账本提交量） | **5.02 u/s（251 u/s²）** | **0.10 u/s（5 u/s²）** | ≤ 5×加速度×Δt = 0.50 |
| `Navigator.JamCount` | **2** | **0** | == 0 |
| `Navigator.ModeSwitches`（诊断，不设断言） | 15 | 9 | — |

## 5. 未做 / 未收口

- **已做（2026-10-19）**：L2.2 模式滞回、L2.3 固定前视路标、L2.4 停靠环滞回。
  L2.2/L2.3 被 `EnemyPathFollower` 的纯追踪整体取代（不再有"直线/阶梯"二选一）；停靠环由刹车曲线 ＋ 0.15 外沿滞回落地。
- **未做**：L2.6 动态阻挡玩家格、L2.7 分离投影、L3 context steering —— 这些是"更干净"而不是"必需"。
- **未收口（已报，未改）**：`ActorLedger.SteerTowards` 的反向分支。
  它取"指数衰减"与"`desired − current`"中较快的一支，而 `|desired − current| > |current|` 在夹角 > 90° 时恒成立，
  所以实际执行的是**未限幅的整块翻面**，配置的 `moveAcceleration` 在这一帧完全不存在（本次夹具的基线版实测单帧 5.02 u/s）。
  本次靠闸门的前半平面约束让它够不到（敌人不会被命令成 > 90°），**但玩家（击退反向）与将来任何直接 `MoveTowards` 的写法仍暴露在这条上**。
  最小修法：反向那一支也用 `acceleration × Δt` 限幅，或在 `MotionParams` 里给一条独立的反向加速度。风险：会改玩家掉头手感，需要单独授权 ＋ 实机判定。

## 6. 风险 / 回滚

| 风险 | 触发条件 | 回滚 |
| ---- | -------- | ---- |
| 手感变"急"、更贴人 | acceleration 12/16 | 只改 `Resources/tuning/EnemyTuning.asset` 的 acceleration，闸门与豁免不依赖它 |
| 拐角变钝（>45° 的单帧转向被平滑） | `FlipDegrees` 45° | 调大 `FlipDegrees`（常量在 `EnemySteeringGate.cs`）或调大 `turnRateLimit`；`turnRateLimit = 0` 即整段关闭闸门 |
| 贴脸时不再换步，可能顶着玩家推 | `JamExemptRange` 1 格 | 调小它；或恢复原判据（删 `EnemyLogic.DetectStuck` 里那一段） |
| 敌人被"贴脸豁免"掩盖了真卡死（贴在墙边、目标恰在 1 格内） | 目标格与墙同时贴脸 | 已记录为已知取舍：1 格内本来就该减速停靠，不是脱困场景 |

回滚粒度：闸门是**独立文件 ＋ 一处接线**（`EnemyNavigator.Emit` / `Reset`），删文件 ＋ 还原 `Emit` 即回到基线；
L1 调参只动 SO；L2.5 是 `DetectStuck` 里的一段 `if`。三段互不依赖。
