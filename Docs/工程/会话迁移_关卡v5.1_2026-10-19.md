### 1.1 角色定位

用户给出的角色是 **"Unity2D 首席架构师 & 全周期执行专家"**，核心纪律（见用户长提示词，已被本仓实践固化）：

## 5. 关键设计契约

### 5.1 `impact_radius` 的代数几何（唯一权威）

| 表里填 | 几何 | 覆盖格数 | 实现位置 |
| :--: | :-- | :--: | :-- |
| `0` | 仅落点 | 1 | `SwitchTileState(cell)` 单格 |
| `1.0` | 欧氏 ≤ 1.0（`√2≈1.414 > 1.0`，对角被剔除） | 5（十字） | `SpreadTileInRadius` / `ApplyBlast` |
| `1.5` | 欧氏 ≤ 1.5（对角 1.414 纳入） | 9（九宫） | 同上 |
| `2.5` | 欧氏 ≤ 2.5 | 21 | 同上 |

- 单位是**格**，前提是场景 `Grid.cellSize = 1`（已逐场景核对：`Range` / `Level_1..6` / `Sandbox` 全是 1）。改成非 1 会让 5/9 格一起放大。
- `ApplyBlast` 与 `SpreadTileInRadius` 用的是同一套欧氏判据，**不要去写第二套几何**（设计书 §4.1 建议的 `SpreadTileByRadiusPattern` 与既有方法完全重复）。

### 5.2 落点 vs 次级波及（上一批的返工点）

- **落点**：`ApplyTileChange` 第一行**无条件** `SwitchTileState(cell, NextTile)`。
- **次级**：`SpreadTileInRadius` 会跳过 `duration <= 0` 的永久地貌（水/土/火/电源/冰面/植物/花/荆棘/冰刺）与同状态格。
- ⇒ 如果只调 `SpreadTileInRadius` 而不先切落点，"土 + 水 → 泥浆"会因为土是永久地貌而**完全不生效**（上一批第一版就是这么写的，3 条测试当场红，详见 §7.3）。

### 5.3 二级反应与一级冲击的关系

- `OnBallHit` 顺序：先 `TileChainReactor.TriggerDuo`（二级），再 `ReactionResolver.Resolve`（一级）。
- `duoTriggered == true` 时**只跳过一级的地貌覆盖**，`ApplyImpact` 仍会按一级规则结算一次冲击。
- 上一批把半径修好后，这次"叠加"从 1 格变成 5 格（例：火池 + 植物 + 水 → 燎原 9 格 ＋ 一级蒸汽 5 格 × 2 伤）。
- **当前刻意保留**（既有语义，改它属于平衡决策）。要收就 `if (!duoTriggered) ApplyImpact(...)`，并同步改 `网格连锁Tests.投掷命中用未改写状态激发并跳过一级覆盖` 的期望。

### 5.4 波前种子配给

- 数据：`wave.grant_seed`（`SeedType`：`None/Fire/Elec/Ice/Plant`）。当前 L3 发 `Fire`、L4 发 `Elec`、L5 W1/W2 发 `Fire/Elec`、W3 `Ice`、W4 `Plant`。
- 链路：`WaveLogic.EnterPhase(Prep)` 把 `_pendingSeed` 置上 → `CombatRoot.OnWavePhaseChanged`（`Prep` 分支）调 `ConsumeSeedGrant()` → 交给玩家。
- 口径：**顶替补满**（先 `TryDiscardSeed` 再 `GrantSeed`）。持种时旧种会被丢掉，目的是让 15 波的节奏确定。要改成"空仓才给"只需改 `GrantWaveSeed` 一处。
- `_restoring` 期间整段跳过，读档不会重复发。

### 5.5 昼夜触发点

- `CombatRoot.ApplyWaveTimeOfDay(waveIndex)`：`Level 2 && WaveIndex 2` → `Dusk`；`Level 4 && WaveIndex 2` → `Night`。
- `WaveIndex` 是**关卡内的 1-based 序号**（不是全局 wave id）。L2 = wave 3;4;5，所以 `WaveIndex 2` = 表里 wave id 4。
- 过渡时长由 `EnvironmentDirector.transitionDuration`（默认 1.5s，Inspector 可调）控制，**不碰** `Time.timeScale`。

### 5.6 关卡 / 波次 / 敌人 的数据流

```
level_wave.wave_ids ──> ConfigModule.GetLevel ──> LevelSpec.Waves ──> LevelLogic ──> WaveLogic
wave_enemy ──> ConfigModule.GetWaveEnemies ──> WaveSpec.Enemies ──> WaveLogic.FillPending（按 count 展开）
enemy ──> ConfigModule.GetEnemy ──> EnemySpec ──> CombatDirector.SpawnOne（Resources/enemies/Enemy_<id>.prefab）
enemy_drop ──> ConfigModule.GetEnemyDrops ──> CombatRoot.TryRollDrop
```

## 7. 踩坑与实测结论（15 条）

> 每条都附带"怎么发现的 / 怎么避免"，多数是**不报错、只表现成行为不对**的类型。

### 7.1 Luban 只报第一个错，一个错字就能让整批表导不出去
`element_duo_reaction.xlsx` 的 `K9 = FALSH` → `ERROR|…位置:[K9] FALSH / falsh 不是 bool 类型的值` → `EXIT=1`。
**判据**：导表前先跑 `-f -x outputSaver=null` 的零写入校验，`EXIT 0` 再正式导。
**注意**：Luban 每次只报第一个失败文件，修完必须**重跑**才知道有没有第二个。

### 7.2 改 xlsx 不要用 openpyxl 重存整表
`ConfigWorkspace/AGENTS.md` 明确：不要用 openpyxl 重建工作表（前 3 行是嵌套子表头，重建会丢 `alias`、丢数据验证下拉框）。
**上一批的做法**：用 `zipfile` 读出全部条目 → 只替换 `xl/sharedStrings.xml` 里的 `<t>FALSH</t>` 和 `xl/worksheets/sheet1.xml` 里两个 `<v>` → 原样写回。
**复核**：12 个 zip 条目一个不少、`testzip()` 为 `None`、`ws.data_validations` 仍有 1 条 list 型（`C/E` 列枚举下拉）。
**代价**：整包重新压缩，文件从 10959 → 8649 字节（属正常，不是内容丢失）。

### 7.3 落点会被"永久地貌保护"挡住（上一批自己写错的）
第一版 `ApplyTileChange` 直接 `return SpreadTileInRadius(...)`，结果"土 + 水 → 泥浆"不生效：土 `duration=-1`，被保护规则跳过。
**测试当场抓到 3 红**（`半径一点零…` / `半径一点五…` / `永久地貌…`），并连带把 `地块效果Tests.落地瞬间伤害当帧结算` 打红。
**修法**：先无条件切落点，再向外铺（`SpreadTileInRadius` 会因"同状态"跳过中心格）。
**教训**：范围铺设的"保护"只该拦次级波及，**永远不能拦落点**。

### 7.4 半径被钳制了两次，两个错误互相抵消
`ReactionOutcome` 构造器把 `0` 钳成 `1.0`；`ApplyImpact` 又用 `>1.0f` 判门槛 ⇒ 表里 `0` 和 `1.0` **都表现为单格**。
只改任一处会把另一批行改错：只改门槛 ⇒ 8 行本该单格的变 5 格；只改钳制 ⇒ 所有 1.0 行退回单格。
**必须同批改**（上一批已做）。判据：新测试第 88 行的 `Assert.AreEqual(0f, outcome.ImpactRadius)`。

### 7.5 `edit` 工具会吃掉 UTF-8 BOM
`StoryFlow.cs` 带 BOM，上一批改一行后发现 diff 第一行变成 `-﻿using System;` / `+using System;`。
**修法**：用 PowerShell 读字节、确认前 3 字节不是 `EF BB BF` 就前置补回。
**判据**：`git diff` 里不应出现第 1 行的增删。本批其它文件（`GridLogic` / `CombatRoot` / `ReactionOutcome` / `ReactionResolver` / `ElementRuleSpec` / `测试夹具`）本来无 BOM，未受影响。

### 7.6 生成物比源表还旧：`describe` 列从没进过生成 C#
批次 A 导出后 `Enemy.cs / Wave.cs / WaveEnemy.cs / LevelWave.cs` 各多出 6 行 —— 因为四张表早就加了 `describe` 列，但生成物停留在更早的 schema。
**连带**：`测试夹具.cs` 三处 `JSON.Parse` 字面量必须补 `"describe":""`，否则 `夹具自检Tests` 抛 `SerializationException`。
**教训**：任何"只改数据"的导出，也要看一眼生成 C# 有没有变；变了就得过编译门 + 跑夹具自检。

### 7.7 `-testResults` 落在工程 `Temp/` 下会拿不到文件
实测两次：日志打出 `Saving results to: …\Temp\test-范围.xml`，退出后文件不存在（Unity 退出时清理 Temp）。
**修法**：结果写工程外，例如 `C:\Users\V.Reason\AppData\Local\Temp\dsh-editmode.xml`。

### 7.8 `Start-Process -ArgumentList` 传数组会拆掉含空格的路径
工程路径是 `C:\UnityHub\Unity Project\deepseaoil`。传数组 ⇒ Unity 收到 `-projectPath C:\UnityHub\Unity` + 游离参数 ⇒ `exit code 2`、无日志。
**修法**：拼成一个整串（内部用双引号包路径），见 §8.5。

### 7.9 首次 batchmode 要 144 秒，之后 20~60 秒
首次会做完整资源导入（`Project init time: 135s`）。别以为卡死。第二次起 `Library/` 有缓存。
注意：报 `exit code 0/2` 的语义 —— `0` = 全过，`2` = 有测试失败，`3` = 运行失败。

### 7.10 中文 `-testFilter` 与中文结果路径是两件事

但**结果路径**不要用中文 + 不要放 Temp（两者叠加时排查成本很高）。建议全 ASCII、工程外。

### 7.11 注释门基线本来就是红的
实测 `comment-lint` 有 **4 个硬超标**：`AudioManager +918`、`SaveSlot +141`、`CombatRoot +115`、`TimerWheel +72`（容差 50 已算入）。
上一批把 `CombatRoot` 顺手压到 **−1**（新增 ~60 字符的同时删了 ~190 字符的复述/死注释），其余 3 个按决策 D5 **未动**。
⇒ **不要**为了"让门变绿"去 `-Mode seal`（它会把全仓余量清零）。也不要以为是自己改红的。

### 7.12 注释预算按文件算，新文件按密度 5.37 判定
新增 `地块范围Tests.cs` 时：测试文件不吃密度线的前提是**已在 `Tools/comment-budget.json` 登记**；新文件走 `densityCap = 5.37`（注释字符 / 代码行）。

### 7.13 旧档与 `Level_6` 已成悬空
表砍到 5 关后：`Level_6.unity` 一进就 `ConfigModule.GetLevel(6)` 抛 `ConfigLoadException`；停在 `currentLevelId=6` 的 v2 存档读档即炸；`StoryFlow` 的 `levelSix*` 字段与 `6001~6003` 段落失去入口。

### 7.14 二级反应仍会叠加一级冲击
见 §5.3。不是 Bug，是既有语义；但半径修好后叠加面从 1 格变 5 格，属**可感知的平衡变化**，已登记待办。

### D. 术语

| 术语 | 含义 |
| :-- | :-- |
| 一级反应 | `element_rule.xlsx`：某格地貌 × 投入球种 → 新地貌 + 落地冲击 |
| 二级反应 | `element_duo_reaction.xlsx`：两个相邻发生器地貌 → 质变 + 广域冲击（等离子 / 极温 / 超导 / 燎原…） |
| 永久地貌 | `tile_state.duration <= 0` 的地貌（水/土/火/电源/冰面/植物/花/荆棘/冰刺），不被次级铺设覆盖 |
| 落点 | 球实际命中的那一格（`OnBallHit(cell, ball)` 的 `cell`） |
| 次级波及 | 以落点为圆心的其余覆盖格 |
| 波前配给 | 进入备战期（`Prep`）时按 `wave.grant_seed` 发种子 |
| 门 / 三绿 | 编译门、注释门、（历史上还有冒烟台）；本工程当前实际可跑的是编译门 + 注释门 + EditMode |
