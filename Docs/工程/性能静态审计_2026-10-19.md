## 4. 阴性结论（别按这些方向优化）

- **不是**每敌人重建 NavField：`NavFieldSet.Rebuild` 有 `field.Version == _version` 早退（`NavFieldSet.cs:96-103`），`RefreshNavFields` 在敌人循环之前一次追平。
- **不是** `Pool` 线性查找：`Foundation/Pool.cs` 用 `Stack<T>`，`Get`/`Release` O(1)。
- **不是** `WaveLogic` 批量刷怪：`SpawnDue` 一帧最多 1 只（`WaveLogic.cs:352-373`）。
- **不是** `SaveService` 每帧落盘：`Tick` 空实现，落盘只在事件里。
- **不是** `TimerWheel` 每帧遍历 512 槽：`Advance` 每帧最多推进 1 槽。
- **不是** 每帧全屏 Blit：`SaveCaptureFeature` 只在抓帧那一帧 Blit 一次，回读走 `AsyncGPUReadback`；`LowHealthScreenEffect` 无 Blit、满血自禁用。
- **不是** 每帧 `Physics2D` 非 NonAlloc：运行期只有 `ImpulseExecutor.OverlapCircleNonAlloc`（复用缓冲）；烘焙期 `OverlapBox` 用静态 `Hits[128]`。
- **不是** LINQ / 每帧 LINQ：全仓无 `using System.Linq`。
- 核心 Tick 快照（`InputSnapshot` / `WorldInfo` / `LogicContext` / `Damage` / `EffectContext` / `ThrowIntent` / `DropSpawnRequest` / `AudioRequest`）全是 `readonly struct`，按值/`in` 传递不产生 GC。

## 6. 后期关卡 60 怪掉帧：归因与处置（2026-10-19 晚，本轮）

> 起因：W7（50 普 + 10 精 = 60 只）"只跟随、不产生元素反应"也掉帧。
> 方法：静态读码 + **离线复现 `NavField.Build` 核心循环**做微基准与等价性验证；**仍未进 Play 跑 Profiler**（本机无 Unity CLI）。

### 6.1 量到的量级

L5 = 104×52 = **5,408 格**、**86,528 采样点/场**；两种体半径（0.3 / 0.5）= **2 张场**；玩家 8 单位/秒、战场格 1.0 ⇒ 最多 **8~11 次跨格/秒**；元素地貌作废另加 **≤5 次/秒**。
⇒ 重建由"跨格 + 地貌生灭"触发，**与怪物数量无关**；每次跨格会把 2 张场在同一条物理帧内各重算一遍。

离线基准（.NET，86k 采样点、6.4~7.7 万可达；**非 Unity 实测，只用来看比例**）：

| 版本 | BFS | 加权树 | 单场 |
| :-- | --: | --: | --: |
| 本轮前（二叉堆 + 每边 4 次整数除法查格） | 0.9 ms | **9.2~11.4 ms** | **11.5 ms** |
| 本轮后（地形快照 + 步价表，内层零除法） | 0.9 ms | 7.4 ms | 8.5 ms |
| 本轮后（同上 + 无元素格时整段跳过） | 0.9 ms | **0** | **1.3 ms** |

### 6.3 一处刻意的行为收窄（必须知道）

第 4 条让"**元素步价 < 1 但场上一个元素格都没有**"的情况走 BFS 父指针，而旧实现照样跑一遍加权树。
代价数组逐点相同（`cost` 不一致 0），但**父指针不同**（离线 40 个随机地形：17,321 个采样点，全部是等价最优路径）。
口径上这等价于把 `element_tile_cost = 1`：没有元素格可偏好时，偏好本就是 no-op。**要退回逐位一致，删掉 `!_preferredAny` 那个条件即可**（代价：这一场景回到 9.5 ms/场）。

### 6.4 复核顺序（进 Play 前必看）

1. EditMode `寻路Tests` 22 条全绿（尤其 `场只在目标格或阻挡变化时重建`、`元素格集合变化会作废流场且不会每帧重建`、`元素格每帧都变时流场重建被合并到每秒五次`）。
2. Profiler 新增 marker：`Nav.Build`（含 `.Terrain` / `.Bfs` / `.Tree`）、`Grid.Tick`、`Combat.FixedTick`（含 `Combat.Enemies`）、`Effects.Tick`。
3. `CombatRoot` 右键 ▸ `Dump perf counters`：`累计重建` 应随跨格增长、**不随帧数增长**。
4. 判据：无元素铺场时 `Nav.Build.Tree` **完全不出现**；铺场后单次 `Nav.Build` 仍是阶跃尖峰而不是每帧常态。
