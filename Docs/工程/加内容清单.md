# 加内容清单

> 本文件登记"加新 X"时所有需要改动的位置。
> 用途：加内容时不漏、Code Review 时对照、Agent 执行时核对。
> 改动基线以代码为准；本文与代码冲突时以代码为准并回头改本文。

---

## 共同约定（每节都适用）

- **导表入口**：Unity 菜单 `Luban ▸ 表格数据导入`。改任何 `ConfigWorkspace/Data/*.xlsx` 之前先读 `ConfigWorkspace/AGENTS.md`。
- **生成物禁区**：`Assets/Scripts/Generated/**`、`Assets/StreamingAssets/Luban/**` 禁手改，下次导表会被镜像覆盖。
- **枚举家**：`dso.BallType` / `dso.TileStateType` / `dso.SeedType` 都定义在 `ConfigWorkspace/Data/__enums__.xlsx`，加成员＝在这张表里加行，然后导表才有 C# 枚举成员（手写不出来）。
- **枚举列的填法现状（三套并存）**：①**中文别名**（`element_rule` / `element_duo_reaction` 的枚举列与 `tile_state.id` 自己那一列都挂了数据验证下拉框，列表是 16 项全量）—— `tile_state.id`（`B:B`）、`element_rule` 的 `source_tile` / `ball_type`（`纯水,纯土`）/ `result_tile`（`C:C` / `D:D` / `E:E`）、`element_duo_reaction` 的 `elem_a` / `elem_b` / `result_tile`（下拉框只在 `C:C` / `E:E`）；②**数字** —— `seed.spawn_tile`（`16` / `18` / `17` / `19`）；③**英文项名** —— `projectile.id`（`Water` / `Earth`）/ `seed.id`（`Fire` / `Elec` / `Ice` / `Plant`）/ `wave.grant_seed`。统一到别名是待办。
- **改 `__enums__.xlsx` 的两个实测坑**（不要用 openpyxl 重建工作表；`full_name` 只在块首行有值）：详见 `Docs/配表/技术文档_配表管线.md` 第 3.1 节。
- **`DropType` 不是表枚举**：它是 `Assets/Scripts/Data/Config/DropType.cs` 里的本地 C# 枚举，不进 `__enums__.xlsx`。

## 使用说明

- **加内容时**：对照本文件逐项打勾，避免漏改
- **Code Review 时**：改动涉及本文件某一节，对照检查
- **Agent 执行时**：Agent 可读本文件辅助定位，但**不修改本文件**（由人手维护）
- **本文件维护**：新增"加新 X"类别时补一节；某个改动位置消失时删对应行

## 与 `AGENTS.md` 的关系

`AGENTS.md` 讲"**不要做什么**"（铁律 / 边界）；本文件讲"**加内容要做什么**"（改动清单）。两者互补。
