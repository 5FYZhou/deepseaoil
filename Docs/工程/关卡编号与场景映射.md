# 关卡编号与场景映射

> **契约**：场景名 `Level_N` ⇔ `level_wave.id = N`。`Level_0` 是**教学关**，它也有配表行（`wave_ids` 指向 `wave` 表里 `name = L0` 的那一波）。
> 本文件是这份映射的唯一说明；改编号时先读这里，再动 `LevelReader` / `CombatRoot` / `StoryFlow`。

## 1. 对照表

| 场景 | id | 配表来源 | 波次 | 剧情段落 | `_nextLevelId` |
| :-- | :-: | :-- | :-- | :-- | :-: |
| `Assets/Scenes/Levels/Level_0.unity` | 0 | `level_wave#0` 教学关（→ `wave#21`「L0」） | 21 | 1001 / 1002 / 1003 | 1 |
| `Level_1.unity` | 1 | `level_wave#1` 沉沙水渠 | 1;2 | 2001 | 2 |
| `Level_2.unity` | 2 | `level_wave#2` 熔渣窑炉 | 3;4;5 | 3001，第 2 波→5002 | 3 |
| `Level_3.unity` | 3 | `level_wave#3` 逆生温室 | 6;7;8;9 | 4001，拾种→4002 | 4 |
| `Level_4.unity` | 4 | `level_wave#4` 极地电站 | 10;11;12;13 | 5001，第 2 波→5002 | 5 |
| `Level_5.unity` | 5 | `level_wave#5` 永夜核心 | 14..20 | 6001，**第 3 波→6002（日出）/ 第 5 波→6003（残阳）**，胜利→7001 | 0（末关） |

> 5.2 起 L5 是 **7 波次**战役，昼夜阶梯为 W1–W2 夜 → W3 昼 → W4 昼 → W5 暮 → W6–W7 夜
> （判据在 `CombatRoot.ApplyWaveTimeOfDay` 的 `case 3/5/6`；中途读档由 `SyncTimeOfDay` 直接落位）。

- 新游戏入口 `SceneName.Game = "Level_0"`，所以「开始游戏」先进教学关。
- 场景名从**文件名**来：`LevelReader.Awake` 按 `Level_` 前缀 + `int.TryParse` 解析，解析不出直接抛异常。
- 场景号 ≠ `Sorting`/`Order` 之类的东西，只是**表的主键**。

## 2. 这张表存在的原因（2026-10-19 的错位）

v5.1 把表砍到 5 关之后，场景还是 `Level_1`(教学) … `Level_6`（第五关）。结果是：

| 现象 | 根因 |
| :-- | :-- |
| 每个关卡读的是**下一关**的波次 | 场景 `Level_2` 解析出 id=2，而策划案第一关的配置在 id=1 |
| `Level_6` 一进就 `ConfigLoadException` | id=6 在表里不存在 |
| 夜晚/黄昏早来一关 | `CombatRoot.ApplyWaveTimeOfDay` 是**按设计编号**写的（`==2` 黄昏、`==4` 入夜），被场景名拖偏一格 |
| 结局提前一关触发 | `StoryFlow.OnLevelStateChanged` 的 `!= 5` 同上 |

改名（`Level_1→Level_0`，其余整体 −1）把这三处一次性掰正，**没有改那三处的判断值** —— 它们的 `2`/`4`/`5` 本来就是设计编号。

## 3. 代码里的判定点（改编号必须同步的清单）

| 位置 | 判据 | 语义 |
| :-- | :-- | :-- |
| `Data/Settings/SceneNameMap.cs` | `SceneName.Game` / `GetLevel(id)` | 场景名拼装；`Game` 指向教学关 |
| `Presentation/Level/LevelReader.cs` | 场景名 → id | 允许 0；`_nextLevelId` 由场景 Inspector 给 |
| `Presentation/Root/CombatRoot.cs` | `enableLevel && ConfigModule.HasLevel(id)` | 表里没有这一行就不建 `LevelLogic`/`CombatDirector`（并报一条 `[Level] … 按无波次运行`） |
| 同上 | `levelId == 0 \|\| levelId == 5` | 教学关与末关都把胜利事件延迟到剧情播完 |
| 同上 | 发 `RequestAutoSave` 前挡掉 `CurrentLevelId <= 0` | 教学关不自动存档（`SaveService` 也不收） |
| `Logic/Level/LevelLogic.cs` | 只有 `currentLevelId < 0` 才抛 | id=0（教学关）是合法关卡 |
| 同上 | `UsesScriptedStory` `0..5` | 教学关也要挂 `StoryFlow` |
| 同上 | `CurrentLevelId != 0` 时放 `BgmMain` | 教学关不放主 BGM |
| 同上 | `ApplyWaveTimeOfDay` `2`/`4` | 第二关第 2 波转黄昏、第四关第 2 波入夜 |
| `Presentation/Story/StoryFlow.cs` | `IntroParagraphOf` / `IntroStageOf`：段 = `(id+1)*1000+1`，只认 `0..5` | 每关的开场段；`BeginLevelIntro` 与重开续播点共用这一份映射 |
| 同上 | `BeginRestartIntro`：教学关 `== 0` 从 1003 第 2 句起，其余从 x001 首条弹窗行起 | 重开跳过开场；教学关补 1003 是为了释放 deferred victory |
| 同上 | `!= 3`（4002）、`== 4` 第 2 波（5002）、`== 5` 第 **3** 波（6002）/ 第 **5** 波（6003）、`!= 5`（7001） | 各关的插段与结局；L5 的两段钉在**昼夜大节点**上（日出 / 残阳），不是"第几波" |
| `Presentation/UI/Panel/SaveSlot.cs` | `== 0` → "教学关"，否则 `第 {id} 关` | 存档槽文案 |
| `Data/Save/GameSaveDTO.cs` | `CurrentSchemaVersion` | 编号变更即提版本，旧档整批失效 |

## 4. 教学关（id = 0）的特例

1. `LevelReader` **允许 0**，`LevelLogic` 只拒绝负数：教学关是**正常关卡**，有 `LevelLogic` + `CombatDirector`。
2. 开战不靠 `CombatRoot.Assemble`：教学关是剧情关（`UsesScriptedStory(0)` 为真）⇒ 装配时**不** `Start()`，
   而是等 `StoryFlow` 在 **1002 播完**时调 `CombatRoot.BeginLevel()`。紧接着 1003 把游戏推进
   `GameState.CG`（`PauseService` 把 `Time.timeScale` 置 0），所以备战倒计时与刷怪**不会在对话里偷跑**。
   **重开是唯一例外**：`restartAtLevelStart` 让装配期直接 `Start()`，剧情只补 1003 第 2 句起。
3. 教学关的 `LevelLogic` 用 `deferVictoryEndEvent = true`（与末关同一档）：1003 播完时 `StoryFlow` 调
   `ReleaseDeferredLevelEnd()` **预授权**，之后打完 `wave#16` 那 2 只才真正发 `LevelEnded(0, 1)`，
   `UIMgr` 见 `nextId > 0` 直接切 `Level_1`（**不走结算面板**）。
4. **表缺 `level_wave#0` 行时降级**：`CombatRoot` 报
   `[Level] level_wave 表里没有关卡 id=0 的行：本关按无波次运行`，不建 `LevelLogic`；
   `StoryFlow` 退回 `LoadNextLevelAfterTutorial()` 直接切 `_nextLevelId`。
   **别把 `LoadNextLevelAfterTutorial` 删了** —— 它就是这条降级路径。
5. 教学关**不存档**：自动存档在 `CombatRoot` 发 `RequestAutoSave` 前就被 `CurrentLevelId <= 0` 挡掉，
   手动存档被 `SaveService` 拒（"当前关卡编号无效"）。所以教学关退出即从头再来，这是刻意的。
6. 教学关**不放主 BGM**（`CurrentLevelId != 0` 才 `EnqueueBgm(BgmMain)`）；想放就把这个判据改成按关表配。

## 5. 存档

`CurrentSchemaVersion = 3`。旧档（2）读档报"格式版本 2 不受支持"。
要兼容旧档得写 `old id + 1` 的迁移器，且旧档还可能停在已不存在的 `Level_6`——不值得，清档即可。

> 5.2 把两个插段标志改名为 `levelFiveSunriseDialogueQueued` / `levelFiveDuskDialogueQueued`
> （原 `…WaveTwo…` / `…WaveThree…`）。**没有提 schema 版本**：这两个标志只在"进入某波备战"那一刻判一次，
> 旧档读进来是 false 也不会重播已过的波次，无副作用。

## 6. 已知残留

`slot_dialogue` 的**段落号**没有跟着重排：`1001~1003` = 教学关、`N001` = 第 N-1 关。
所以代码里会出现 `case 1: return FlowStage.LevelOneDialogue`（配 2001）这种"关卡 1 配 2001"的写法。
这是**数据键**，不是关卡号；要收口得改人工维护的 xlsx 并重新导表（见 `Docs/待办.md`）。

## 7. 自检

```powershell
# 场景名与 Build Settings 应恰好是 Begin + Level_0..5
Select-String -Path ProjectSettings\EditorBuildSettings.asset -Pattern "path:"
# 每个场景的 _nextLevelId 应为 1/2/3/4/5/0
Get-ChildItem Assets\Scenes\Levels\Level_*.unity | ForEach-Object {
  "$($_.Name)  " + (Select-String -LiteralPath $_.FullName -Pattern '_nextLevelId:').Line.Trim()
}
pwsh Tools/compile-gate.ps1
```

> `[KillAll] 关卡 N：按 K 秒杀全场敌人。`
