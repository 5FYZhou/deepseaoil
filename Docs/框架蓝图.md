# 框架蓝图

宏观：**分层、每帧时序、跨层契约、程序集、已知缺陷**。回答"能不能这么做"。
落到某一层的设计看 [`分层设计/`](分层设计/)；某个文件夹装什么看 [`目录说明.md`](目录说明.md)。

## 1. 三条铁律

1. **跨层只走 `EventBus<T>`**（只服务 Logic ↔ Presentation 的意图/事实通知）。
   两条例外：**组合根/驱动点允许直连**（`GameRoot` → 逻辑层、`PlayerController` → `PlayerLogic`）；
   **表现层可以实现逻辑层定义的端口再注入**（`MovementMotor : IMovementMotor`、`GameTime : IGameTime`）。
2. **每帧只有三个驱动入口**：`GameRoot.Update()` 驱动 `List<IService>`（渲染帧，组合根）、
   `PlayerController.FixedUpdate()` 驱动 `PlayerLogic`（物理帧，组合根）、
   `InputProvider.Update()` 采样输入（第三处，被输入后端强制——`WasPressedThisFrame()` 只在动态更新有效）。
   `MonoMgr` 的三个转发是基础设施、不算入口；**不在非驱动点自写 `Update()` / `FixedUpdate()`**。
3. **生成物专用位置有三处，禁止放手写文件**：
   `Assets/Scripts/Generated/Config/`、`Assets/StreamingAssets/Luban/`、`Assets/Scripts/Generated/Input/InputSys.cs`。

## 2. 依赖方向

```text
Data（只读、进程级常驻、不走 EventBus）        Logic（纯 C#）                    Presentation
ConfigModule    ──数值/查询──┬─────────────►  ActorLogic / PlayerLogic          GameRoot       组合根
PlayerConfig SO ──角色参数───┤                MoveGroup + 7 个状态              PlayerController 组合根
AssetModule     ──资源句柄───┴─────────────►  Pause / Scene / Save Service      UIMgr / InputProvider
                                                ▲                                  │
                          表现层实现端口再注入 ──┘                                  │
                          EventBus<T>（T : struct，唯一跨层通道）◄──意图───────────┤
                          └──事实──► 订阅方（Service / PlayerController / Debug） │
❌ 禁止：非组合根的表现层直接调逻辑层（唯一越界反例）
```

| 方向 | 允许 | 说明 |
| :-- | :-- | :-- |
| Data ← Logic / Data ← Presentation | ✅ | 直连读数值（含只读 SO）与资源句柄，不需要绕 EventBus |
| Presentation → Logic | ⚠️ **仅组合根/驱动点** | 其它一律走 EventBus。`GameRoot` 驱动 `IService`、`PlayerController` 驱动 `PlayerLogic` 属此列 |
| Presentation ─实现─> Logic 的接口 | ✅ | 依赖反转：`MovementMotor : IMovementMotor`、`GameTime : IGameTime`，实例由组合根注入 |
| Logic → Presentation | ❌ | 唯一例外：通过 EventBus |
| Data → 任何层 | ❌ | Data 层零业务依赖 |

- 箭头是**依赖方向，不是调用方向**；数据（数值与资源）不走 EventBus——它是**直连查询**，不是通知。
- 数据层全部只读：SO、Luban Tables、资源缓存都只被读。表现层与逻辑层之间只有**两条组合根直连边**与一条端口反转边。

| EventBus 能做 | 不能做 |
| :-- | :-- |
| 承载 Logic ↔ Presentation 的意图（`RequestXxx`）与事实（`XxxChanged`）；单向广播、订阅方零依赖 | 不传对象本体（`struct` 装不下 `UnityEngine.Object`）；不承担命令-响应语义（那是**直连查询**的领域） |
| 编译期查类型、无装箱、发布订阅方不共享堆引用；订阅/退订幂等；发布用快照遍历 | 不服务 Data 层；发布**每次分配一个快照数组**（`new Action<T>[count]`）——热路径上要留意 |

## 3. 单例

两条基类都在 `Assets/Scripts/Foundation/`，**Data 层两条都不用**：

| 基类 | 形态 | 用于 | 已知坑 |
| :-- | :-- | :-- | :-- |
| `Singleton<T> : MonoBehaviour` | 找不到就 `new GameObject` + `AddComponent`，并 `DontDestroyOnLoad` | `MonoMgr` | 反射式创建会顺带触发 `Awake`，顺序依赖要多想一步 |
| `BaseManager<T>` | 纯 C# 单例，反射取**非公开**无参构造 | `UIMgr` | 子类若只有公开构造函数，`info == null` → 只记 Error，`Instance` **永久为 null**（D20） |

`PauseService` / `SceneService` / `SaveService` **不是单例**：由 `GameRoot.Start()` `new` 出来放进 `List<IService>`。

## 4. 每帧时序

```text
Update 通道（渲染帧）GameRoot.Update() 顺序表
  ① Services.Tick(unscaledDt)   Pause / Scene / Save           Time.unscaledDeltaTime
  ② AssetModule.Tick(dt)        异步队列 / 冷却期 / LRU 淘汰     Time.deltaTime（冷却期读 realtimeSinceStartup）
InputProvider.Update()          采样 InputSys，|= 累积按下沿     帧（WasPressedThisFrame）
  渲染帧与物理帧无先后关系：一个渲染帧可能对应 0 或 2 个物理帧（默认 Fixed Timestep 0.02s = 50Hz）

FixedUpdate 通道（物理帧）PlayerController.FixedUpdate()
  ① InputProvider.ConsumeSnapshot()          取快照并清按下沿
  ② InputBuffer.Push(in snap, Time.fixedTime) 记按下时间 + 算松键沿
  ③ new WorldInfo(...) → new LogicContext(...)
  ④ PlayerLogic.FixedTick(ctx)
  ⑤ MoveGroup.Tick(ctx)                      仲裁 → ChangeState → State.Tick
  ⑥ 帧末一次提交 Motor.Move(frameStart + delta + accel*dt)     Time.fixedTime / fixedDeltaTime
窗口：InputBuffer 容量 = max(jumpBufferTime, dashBufferTime) × (1/fixedDeltaTime) = 0.12s × 50 = 6 帧
```

- 两条通道**互不嵌套**。暂停时 `Time.timeScale = 0`，`FixedUpdate` 不再触发，所以暂停期间不会有 `Push`。
- **物理帧的唯一硬序是 `InputBuffer.Push` 必须先于 `PlayerLogic.FixedTick`**——由调用顺序保证，**类型系统不保证**。
- step ② 由 `GameRoot` 驱动而**不是**由 `Services` 驱动：保持 Data 层独立；这条例外记在契约表，**不作为通用模式推广**。
- **两套 Tick 抽象并存，且都不是分发机制**：`IService.Tick(float unscaledDeltaTime)` 真被 `GameRoot` 遍历调用；
  `ITickable.Tick(LogicContext)` / `IFixedTickable.FixedTick(LogicContext)` 带**默认接口实现**（空 body），
  `ITickable` **零实现、零调用**，`IFixedTickable` 只被 `ActorLogic` 与 `PlayerController` 列在基接口里，**从不经接口分发**。

## 5. 程序集与平台

### 5.1 程序集（事实）

| 程序集 | 内容 | 关键点 |
| :-- | :-- | :-- |
| `Assembly-CSharp` | `Scripts/` 下全部（含生成物） | 自动引用 `Luban.Runtime` |
| `Assembly-CSharp-Editor` | `Assets/Tests/Runtime/Editor/` | 自动引用 `Assembly-CSharp` ＋ NUnit |
| `Luban.Runtime.asmdef` | `Assets/Luban.Runtime/` | 无引用；**`allowUnsafeCode: true`**（`ByteBuf` 需要） |
| `DeepseaOil.EditorTools[.Tests].asmdef` | `Assets/Editor/`、`Assets/Tests/Tools/` | Tests 只按名字引 EditorTools；`autoReferenced: false`；`UNITY_INCLUDE_TESTS` |

**决定：Jam 期不给生成物划 asmdef。** 收益（热更隔离、编译增量）Jam 用不上；代价是多一层引用配置，且输出目录与 asmdef 必须成对维护。

🔴 **不要装 Luban 的 UPM 包**：本地拷贝与 UPM 包的 asmdef 都叫 `Luban.Runtime`，撞名会让**整个工程所有程序集都编译不出来**。

### 5.2 平台假设

| 平台 | 状态 | 说明 |
| :-- | :-- | :-- |
| Windows / macOS / Linux | ✅ 支持 | `ConfigModule.Init` 在 `Awake` 同步读 `StreamingAssets` |
| Android / WebGL | ❌ 不支持 | `StreamingAssets` 在包内，`File.ReadAllText` 读不到，必须改 `UnityWebRequest`（异步）——会让 `Init` 变异步，**牵动整条启动链** |

## 6. 启动装配序（两阶段）

```text
GameRoot.Awake       ← 阶段 1：Data 层。Unity 只保证「所有 Awake 先于任何 Start」
  ConfigModule.IsReady? 否则 InitFromStreamingAssets()   同步全量加载；失败抛 ConfigLoadException
  AssetModule.IsInitialized? 否则 Init()                 建缓存表 / 调度器 / 引用计数 / 生命周期
  ⚠️ 顺序不可反：AssetModule 的 Key 来自 Config

GameRoot.Start       ← 阶段 2：表现层与逻辑层
  UIMgr.Instance.ShowPanel<BeginPanel>()   构造 UICamera / Canvas / EventSystem（DontDestroyOnLoad）
  new GameTime() → new PauseService(gameTime) / SceneService(gameTime, pauseService) / SaveService()
  → 各自 Init() → services.Add 三次          顺序 = [Pause, Scene, Save] = 每帧 Tick 顺序（都不是单例）
```

- **Data 层装配放 `Awake` 不放 `Start`**：`Start` 的顺序在多个 MonoBehaviour 之间不确定，放 `Start` 会与别的脚本的 `Start`（例如 `ConfigLoader`）抢顺序。
- **阶段 2 内部：初始化序 = 每帧序**；**跨阶段不要求同序**——`AssetModule` 在阶段 1 装配，却在每帧最后 Tick。
- **`IsReady` 守卫防 `Init` 二次调用**：`ConfigModule.Init` 重复调用会抛（无重置入口，O10）；`GameRoot` 是场景对象、Data 层是进程级常驻，"重开本关"会二次进入场景。
- **`IsInitialized` 守卫防同一帧出现第二个 `GameRoot`**：`AssetModule` 在 `OnDestroy` 里被 `Dispose` 过，再 `Init` 合法。
  `OnDestroy` 里靠 `_dataLayerOwner` 判断归属，否则叠加场景里第二个 `GameRoot` 被销毁时会清掉第一个还在用的缓存。

## 7. 判层依据

**判定层的依据是命名空间，不是目录。** 目录现在按同一套分层组织（见 [`目录说明.md`](目录说明.md)）。

| 命名空间 | 目录 | 层 |
| :-- | :-- | :-- |
| `DeepseaOil.Data` | `Scripts/Data/` | **Data**（`ConfigModule`、`AssetModule`、`DataMetrics`、`TablesMeta`、`PlayerConfig`） |
| `DeepseaOil.Logic[.{Movement,Movement.States,Player,Input,Service}]` | `Scripts/Logic/` | Logic（`ActorLogic`、`WorldInfo`、`LogicContext`、`ITickable`、`IMovementMotor`、7 个状态、`PlayerLogic`、`MoveGroup`、`InputBuffer`、`StateMachine<T>`、三个 Service） |
| `DeepseaOil.Logic.Events` | `Scripts/Logic/Event/` | **通道**（不是层）：`EventBus<T>`、`RequestPause`、`GamePaused`… |
| `DeepseaOil.Presentation[.UI]` | `Scripts/Presentation/` | Presentation（`GameRoot`、`PlayerController`、`MovementMotor`、`InputProvider`、`GameTime`、`UIMgr`、`BasePanel`、`MonoMgr`） |
| `DeepseaOil.Foundation` | `Scripts/Foundation/` | ⚠️ **不是层**：与游戏无关的地基（`Singleton<T>`、`BaseManager<T>`、`Pool<T>`） |
| `cfg` / `cfg.demo` / `DeepseaOil.Generated` | `Scripts/Generated/` | ⚠️ **不是层**：机器生成（Luban 生成物、`InputSys`） |
| `DeepseaOil.EditorTools[.Tests]` / `DeepseaOil.Tests` | `Editor/`、`Tests/` | ⚠️ 独立程序集：导表工具与测试 |

## 8. 重要契约

| 主题 | 契约 |
| :-- | :-- |
| 输入后端 | 新输入系统（`com.unity.inputsystem` 1.14.2，`activeInputHandler: 1`）；动作表是 `InputSys.inputactions`；**不要用 `UnityEngine.Input`**——工程设置已禁用它，调用会抛 |
| 输入 | `InputProvider` 是唯一**采样**点；`InputBuffer` 是唯一**按键沿存储**点；同一物理帧内 `Push` 必须先于 `PlayerLogic.FixedTick` |
| 每帧 | 驱动入口共**三处**；`ITickable` 零实现零调用，`IFixedTickable` 从不经接口分发 |
| 通信 | Logic ↔ Presentation 只走 `EventBus<T>`；意图祈使式、事实过去式；组合根/驱动点与端口实现两处例外 |
| Data 层 | 被所有层直连；只读；查询式；进程级常驻；不走 EventBus；ConfigModule 同步、全量常驻、无释放、启动时装配、**重复 `Init` 抛异常**；与 AssetModule 零依赖，通过字符串 Key 衔接，调用方是衔接点 |
| AssetModule | 异步 `LoadAsync<T>` ＋ 同步 `Load<T>`；引用计数；冷却期缓存 60s；并发 4；LRU 淘汰上限 100 条；每帧 Tick；`Tick` 是 `GameRoot.Update` 顺序表第 ② 步、Data 层唯一被允许的主动行为 |
| 资源 Key | 表里存「相对 `Assets/` 带扩展名」；`Resources.LoadAsync` 用「相对 `Assets/Resources/` 不带扩展名」；转换点只有 `AssetRegistry.ResolvePath`；⚠️ 表值还**必须落在 `Assets/Resources/` 下**才可加载（D4） |
| AsyncHandle | 必须是 `class`；`Complete` 只在主线程调用；不传 `RunContinuationsAsynchronously`（续体在 `AssetModule.Tick` 里**内联**执行）；二次完成不抛异常 |
| 配置源 | 两条并存，各自服务不同的东西：数值走 Luban/xlsx（经 `ConfigModule`）；角色参数走 SO（`PlayerConfig`，**不经 `ConfigModule`**） |
| 物理字段 / 状态 | 每刚体每项唯一写者：角色由代码从 SO 写，非角色归 Inspector；`ChangeState` **立即** `Exit → Enter`、同帧生效，"该不该切"由 `MoveGroup` 两段仲裁，未注册标签返回 false |
| 切场景 | 复位四项：`Time.timeScale` / `PauseService` / `EventBus.ClearAll` / `AssetModule.OnSceneSwitch`，全部在 `LoadScene` 之前。⚠️ `SceneService.Load` 目前无调用点（D9） |
| 程序集 | Jam 期不给生成物划 asmdef；`Assets/Scripts/**` 全部落 `Assembly-CSharp`（事实见 §5.1） |
| 测试程序集 | asmdef **无法**引用 `Assembly-CSharp`；要测 `Assets/Scripts/` 必须放 `Assets/Tests/Runtime/Editor/`（无 asmdef，靠 `Editor` 目录名落 `Assembly-CSharp-Editor`） |
| 平台 | Jam 期只支持桌面端（见 §5.2） |
| 观测 / 面板顺序 | 观测走拉模型 `DataMetrics.GetSnapshot()`，不推送事件；面板顺序由 `ui/Canvas.prefab` 四个子节点（`Bottom`/`Middle`/`Top`/`System`）的兄弟顺序决定，**没有** `sortingOrder`，`ShowPanel` 默认 `Middle`。⚠️ 同层内的顺序无处表达（D28） |
