# 表现层

**定位**：把逻辑层的结论呈现出去，把环境事实喂进逻辑层。跨层通信只走 `EventBus<T>`（意图祈使式、事实过去式）；
只允许两类直连——**组合根/驱动点**（`GameRoot`、`PlayerController`）与**表现层实现逻辑层端口**
（`GameTime : IGameTime`、`MovementMotor : IMovementMotor`）（`Docs/框架蓝图.md`、`:892-893`）。
无 `Presentation.asmdef`，全部落 `Assembly-CSharp`（`Docs/框架蓝图.md`）。

## 2. 每帧三个驱动入口

| # | 入口 | 驱动什么 | 帧 | 出处 |
| :-- | :-- | :-- | :-- | :-- |
| ① | `GameRoot.Update()` | `List<IService>` 逐项 `Tick(Time.unscaledDeltaTime)`，再 `AssetModule.Tick(Time.deltaTime)`（顺序表两步） | 渲染帧 | `Assets/Scripts/Presentation/Root/GameRoot.cs:65-84` |
| ② | `PlayerController.FixedUpdate()` | `ConsumeSnapshot()` → `InputBuffer.Push` → `new WorldInfo` → `Logic.FixedTick(new LogicContext(...))` | 物理帧（默认 50Hz） | `Assets/Scripts/Presentation/Root/PlayerController.cs:79-96` |

- **③ 是被输入后端强制的例外**：`WasPressedThisFrame()` 只在动态更新里有效，而按下沿必须由物理帧侧的
  `ConsumeSnapshot()` 消费（`Assets/Scripts/Presentation/Input/InputProvider.cs:55-56`、`:63-77`；`Docs/框架蓝图.md`）。
- 渲染帧与物理帧**互不嵌套**，之间没有先后关系：一个渲染帧可能对应 0 或 2 个物理帧（`Docs/框架蓝图.md`、`:264-265`）。

## 3. 组合根

### 3.1 GameRoot —— 场景对象

| 时机 | 行为 | 出处 |
| :-- | :-- | :-- |
| `Awake`（阶段 1） | `if (!ConfigModule.IsReady) ConfigModule.InitFromStreamingAssets();` 然后 `if (!AssetModule.IsInitialized) { AssetModule.Init(); _dataLayerOwner = this; }` | `Assets/Scripts/Presentation/Root/GameRoot.cs:34-44` |
| `Start`（阶段 2） | `UIMgr.Instance.ShowPanel<BeginPanel>()` → `new GameTime()` → `new PauseService/SceneService/SaveService` → 各自 `Init()` → `services.Add` 三次 | `Assets/Scripts/Presentation/Root/GameRoot.cs:46-63` |
| `Update` | §2 的 ① | `Assets/Scripts/Presentation/Root/GameRoot.cs:65-84` |
| `OnDestroy` | `if (_dataLayerOwner != this) return;` → `AssetModule.Dispose()` → `_dataLayerOwner = null` | `Assets/Scripts/Presentation/Root/GameRoot.cs:91-98` |

- **阶段 1 放 `Awake` 不放 `Start`**：Unity 只保证「所有 `Awake` 先于任何 `Start`」；`Start` 在多个 MonoBehaviour 之间
  顺序不确定，放 `Start` 会与别的脚本（例如 `ConfigLoader.Start`）抢顺序（`Assets/Scripts/Presentation/Root/GameRoot.cs:23-24`；`Docs/框架蓝图.md`、`:299-300`）。
- **`ConfigModule` 必须先于 `AssetModule`**：`AssetModule` 的 Key 来自 Config；加载失败即抛，带病数据不进运行时
  （`Docs/框架蓝图.md`、`:298`）。
- **幂等守卫**：`GameRoot` 无 `DontDestroyOnLoad`（本文件唯一出现处是注释 `Assets/Scripts/Presentation/Root/GameRoot.cs:28`），
  而 `ConfigModule` 进程级常驻且重复 `Init` 抛异常（`Docs/框架蓝图.md`），故必须先问 `IsReady` 再 `Init`
  （`Assets/Scripts/Data/Config/ConfigModule.cs:21`）。`AssetModule` 侧相反：它在 `OnDestroy` 里被 `Dispose` 过、`_initialized`
  已复位，再 `Init` 合法，守卫只为防同一帧里出现第二个 `GameRoot`（`Assets/Scripts/Presentation/Root/GameRoot.cs:31-32`；`Assets/Scripts/Data/Asset/AssetModule.cs:48,108`）。
- **`_dataLayerOwner` 是归属判定**：只有真正装配了 Data 层的实例负责拆，否则叠加场景里第二个 `GameRoot` 被销毁时会把第一个还在用的缓存一起清掉（`Assets/Scripts/Presentation/Root/GameRoot.cs:17-18`、`:88-89`）。
- **阶段 2 内部：初始化序 = 每帧序**。`services` 顺序 `[Pause, Scene, Save]` 既是 `Init` 序也是 `Tick` 序，不允许两套顺序；三个 Service 都不是单例（`Assets/Scripts/Presentation/Root/GameRoot.cs:55-61,69-72`；`Docs/框架蓝图.md`）。
  跨阶段**不**要求同序：`AssetModule` 在阶段 1 装配却在每帧最后 `Tick`——它是依赖，不是 tickable（`Docs/框架蓝图.md`）。

`GameRoot` 挂在 `SampleScene`（`Assets/Scenes/SampleScene.unity:948`）。

### 3.2 PlayerController —— 物理帧组合根

| 时机 | 行为 | 出处 |
| :-- | :-- | :-- |
| `Awake` | `config`/`motor`/`inputProvider` 任一为空 → `LogError` ＋ `enabled = false`；否则 `new InputBuffer(max(jumpBufferTime, dashBufferTime), RoundToInt(1 / Time.fixedDeltaTime))`、`new PlayerLogic(motor, config, _buffer)` | `Assets/Scripts/Presentation/Root/PlayerController.cs:59-77` |
| `OnEnable`/`OnDisable` | 订阅/退订 `EventBus<GamePaused>`、`EventBus<GameResumed>` | `Assets/Scripts/Presentation/Root/PlayerController.cs:35-45` |
| `OnGamePaused` / `OnGameResumed` | `inputProvider.Clear()` → `SetInputEnabled(false)` → `_buffer.Clear()`；恢复时 `SetInputEnabled(true)` | `Assets/Scripts/Presentation/Root/PlayerController.cs:47-57` |
| `FixedUpdate` | §2 的 ② | `Assets/Scripts/Presentation/Root/PlayerController.cs:79-96` |
| 对外只读 | `Logic` / `World` / `EngineVelocity`（供调试面板读） | `Assets/Scripts/Presentation/Root/PlayerController.cs:27-33` |

- **同一物理帧内的唯一硬序是 `Push` 先于 `FixedTick`**，由调用顺序保证，**类型系统不保证**（`Docs/框架蓝图.md`）；
  顺序反了松键沿滞后一帧、可变跳高失效（`Assets/Scripts/Presentation/Root/PlayerController.cs:14-15`）。
- `FixedUpdate` 读的 `motor.WallSide` 是具体类型成员，**不在** `IMovementMotor` 上；组合根可以这么用，别处不行（`Docs/框架蓝图.md`）。
- `InputBuffer` 的时间窗在 `Awake` 按当时的 `Time.fixedDeltaTime` 折算成帧数，事后改工程 Fixed Timestep 会与实际窗口不一致（`Docs/框架蓝图.md`）。
- `PlayerController` 声明实现 `IFixedTickable`（`Assets/Scripts/Presentation/Root/PlayerController.cs:17`；接口在 `Assets/Scripts/Logic/Tickable.cs:7`），但全仓库无按接口调用点。

### 3.3 启动装配序（两个组合根）

```mermaid
sequenceDiagram
    participant U as Unity
    participant GR as GameRoot（场景对象）
    participant PC as PlayerController
    U->>GR: Awake　阶段 1 · Data 层
    Note over GR: if (!ConfigModule.IsReady) ConfigModule.InitFromStreamingAssets()<br/>if (!AssetModule.IsInitialized) { AssetModule.Init(); _dataLayerOwner = this; }<br/>顺序不可反：AssetModule 的 Key 来自 Config
    U->>PC: Awake
    Note over PC: new InputBuffer(max(jumpBufferTime, dashBufferTime), RoundToInt(1 / fixedDeltaTime))<br/>new PlayerLogic(motor, config, _buffer)
    U->>GR: Start　阶段 2 · 表现层与逻辑层
    Note over GR: UIMgr.Instance.ShowPanel 显示 BeginPanel（默认 Middle 层）<br/>new GameTime() → new PauseService / SceneService / SaveService<br/>→ Init() x3 → services.Add x3（顺序 = 每帧 Tick 顺序）
```

Unity 只保证「所有 `Awake` 先于任何 `Start`」（`Docs/框架蓝图.md`）；`Awake` 之间、`Start` 之间的相对顺序不保证
（`Docs/框架蓝图.md`）。`GameRoot.Awake` 与 `PlayerController.Awake` 之间无依赖：前者只碰 Data 层，后者只碰序列化引用与输入缓冲。

单例基类 `BaseManager<UIMgr>`，构造函数私有（`Assets/Scripts/Presentation/UI/UIMgr.cs:39,87`），靠反射取非公开无参构造（`Assets/Scripts/Foundation/BaseManager.cs:38-45`）。

  仅 `SetActive(false)` 的隐藏不释放（`Docs/框架蓝图.md`）。
- `AddCustomEventListener` 先复用控件上已有的 `EventTrigger`，保证只挂一个（`Assets/Scripts/Presentation/UI/UIMgr.cs:308-320`）。
