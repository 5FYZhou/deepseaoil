# 技术文档：配表管线

面向**程序**。策划操作见 [`策划手册_数据表填写.md`](策划手册_数据表填写.md)。

## 1. 准入

| 项 | 要求 |
| :-- | :-- |
| Unity | 2022.3.62f3c1（URP 14.0.12） |
| .NET 运行时 | `Microsoft.NETCore.App` ≥ 8.0.0（**不需要 SDK**）；实测 8.0.25。`ConfigWorkspace/Tools/Luban/Luban.runtimeconfig.json` 声明 `tfm = net8.0` / `framework = Microsoft.NETCore.App 8.0.0`，跑 `dotnet <dll>` 要的是运行时。注：`LubanImport.DescribeLaunchFailure` 的提示文案写的是「请安装 .NET SDK 8+ 后重启 Unity」，与"不需要 SDK"不一致（**待核对**） |
| Git LFS | 拉 `ConfigWorkspace/Tools/Luban/` 的 `*.dll`/`*.exe` 之前必须装 |
| Luban 工具 | 随仓库交付，132 文件约 5.33 MB，`net8.0`，入口 `ConfigWorkspace/Tools/Luban/Luban.dll`。导表进程的工作目录就是 `ConfigWorkspace`（`LubanProject` 的 `WorkingDirectory = Workspace`），所以命令行里一律写相对路径 `Tools/Luban/Luban.dll`——工程根下**没有** `Tools/` 目录 |
| Luban 构建指纹 | `Luban.Core.dll` 的 `ProductVersion = 1.0.0+df34215d2e22035073d1af83d44e3ac0744dc3b3`（二进制里读不到对外版本号，这是唯一强标识） |
| Unity 侧运行库 | `Assets/Luban.Runtime/`，7 个 `.cs`，**本地拷贝，不走 UPM** |

🔴 **不要装 Luban 的 UPM 包**：本地拷贝与 UPM 包的 asmdef 都叫 `Luban.Runtime`，撞名报 `Assembly with name 'Luban.Runtime' already exists`，**整个工程所有程序集都编译不出来**。

## 2. 链路

```text
ConfigWorkspace/Data/*.xlsx            源表；登记在 __tables__.xlsx
        ↓  dotnet Tools/Luban/Luban.dll --conf luban.conf -t client --strict
             -c cs-simple-json -d json
             -x outputCodeDir=output/code -x outputDataDir=output/data
             -x pathValidator.rootDir=<工程>/Assets
           （工作目录 = ConfigWorkspace；参数表见 LubanProject.BuildExportCommand）
ConfigWorkspace/output/{code,data}     暂存区（gitignore）
        ↓  退出码 == 0 才发布：镜像拷贝
Assets/Scripts/Generated/Config/  +  Assets/StreamingAssets/Luban/
        ↓  cfg.Tables 由 TablesHolder 构造
DeepseaOil.Data.ConfigModule           运行期唯一的**数值**入口
```

🔴 **发布闸门是退出码，不是 Luban 的行为**——Luban 校验失败也会写暂存区。

⚠️ 表里资源路径（如 `icon`）的校验盲区：`#path=unity` 只校验文件在 `Assets/` 下**存在**，不校验它在 `Assets/Resources/` 下，而运行期 `Resources.LoadAsync` 只能加载后者。当前值 `Resources\Icons\sardline.png`（`weapon.xlsx` 的 `icon` 列 / `fish.xlsx` 的 `icon` 列）合规，填错地方**导表通过、运行期才失败**。详见[数据层 §4](../框架设计/分层设计/数据层.md)。

> 现状补充：这两列**当前没有任何运行期消费者**——只有 `Assets/Scripts/Presentation/Debug/ConfigLoader.cs` 把它打印出来、以及 `Assets/Tests/Runtime/Editor/Data层Tests.cs` 断言它像个资源路径。所以"填错地方"眼下表现为"没人发现"，而不是"运行期黑屏"；一旦接 UI 取图，上一条盲区就立刻成立。

**枚举（`__enums__.xlsx`）**：`demo.Quality`（示范）、`demo.BallType`（`Water` 水 / `Earth` 土）、`demo.TileStateType`（`Normal` 常规 / `Mud` 泥浆）。枚举列的数据格填**别名**（中文），如 `水` / `泥浆`。

**加表后还要同步两处手写清单**：① `Assets/Scripts/Data/Config/TablesMeta.cs` 的 `Names` 数组（给 `DataMetrics.TableCount` 与 `StartupValidator` 用，生成物没有表数量属性；当前 9 条）；② `Assets/Tests/Tools/仓库一致性Tests.cs` 里 `生成物目录无手写文件` 的基线清单（加表/加枚举会新增生成物文件，漏改这条测试会红）。

### 3.1.1 🔴 实测坑：`##type` 里的 `!` 是"**不许是默认值**"，不是"必填"

`!` 在 Luban 里要求该列**不能等于类型的默认值**（数字是 `0`、字符串是空）。所以：

| 写法 | 填 `0` 会怎样 | 该写什么 |
| :-- | :-- | :-- |
| `float!#range=[0,10]` | **校验失败**：`记录 demo.TbXxx[id].field:0 (来自文件:Sheet1@…xlsx) 是一个默认值` | 可填 0 的列去掉 `!`：`float#range=[0,10]` |
| `float!#range=[0.05,5]` | 通过（0 不在范围里，填 0 会先被范围规则拦下） | 保持 |

**本次踩过一次**：`tile_state` 表的"常规"行 `duration` / `enter_damage` / `enter_knockback` 天然是 `0`，最初四列都写成 `float!#range=[…]`，导表直接红。修法是把可填 0 的列改成 `float#range=[…]`（范围校验保留）。**判据**：这一列的合法取值里包含 `0` 时不要加 `!`。

### 3.2 改输入输出路径

路径推算全部集中在 `Assets/Editor/LubanProject.cs`，无硬编码盘符。**必须成套改**，漏一处会出现"导成功了但工程没变"。

| 要改什么 | 改哪里 |
| :-- | :-- |
| 源表目录 | `luban.conf` 的 `dataDir`；新建表还要加到 `schemaFiles` |
| 生成代码/数据目录 | `BuildExportCommand` 里 `-x outputCodeDir=` / `-x outputDataDir=` —— 必须指向暂存区 |
| 发布目录 | `LubanProject.OutputCodeDir` / `OutputDataDir` —— 与上面两行配对 |
| 暂存区 | `LubanProject.StageCodeDir` / `StageDataDir` —— 改了它，两个 `-x` 要一起改 |
| 日志目录 | `LubanProject.LogsDir`（gitignore） |
| `#path=unity` 的基准 | `LubanProject.PathValidatorRoot`（现为 `Assets`） |

发布与暂存**成对**：`MirrorCopy(StageCodeDir, OutputCodeDir)` 与 `MirrorCopy(StageDataDir, OutputDataDir)`。
写绝对路径也能跑通，但会锁死本机布局，且路径不存在时报原生英文错 `Could not find a part of the path …`——一律用相对路径。

### 3.3 改代码（不用导表）

| 文件 | 影响 |
| :-- | :-- |
| `Assets/Scripts/Data/Config/` | 运行期怎么读 JSON、怎么暴露查询：`ConfigModule`（入口 ＋ 逃生舱 `Tables`）→ `SpecCatalog`（表行 → 纯结构体的**唯一折算点**）→ 各 `*Spec` / `BallDefinition`；`TablesMeta.Names` 是手写的表清单 |
| `Assets/Scripts/Data/Settings/` | SO 调参（`ThrowTuning` / `DropTuning` / `CharacterConfig` / `PlayerConfig` / `AudioConfig`）——**不经 ConfigModule**，改完不用导表 |
| `Assets/Resources/tuning/{ThrowTuning,DropTuning}.asset` | 上表两份观感资产，**必须随仓库发布**（见下） |
| `Assets/Scripts/Presentation/Debug/ConfigLoader.cs` | 链路自检示例（可选，删掉不影响导表） |
| `Assets/Luban.Runtime/` | 运行期反序列化实现 |
| `Assets/Editor/*.cs` | 导表工具本身：`LubanProject`（路径推算 ＋ 命令行）、`LubanImport`（暂存 ＋ 镜像拷贝 ＋ 日志）、`LubanMenu`（菜单入口），改完下次导表生效 |

**两份 SO 观感资产必须随仓库发布**：`Assets/Resources/tuning/ThrowTuning.asset`（键 `tuning/ThrowTuning`）与 `Assets/Resources/tuning/DropTuning.asset`（键 `tuning/DropTuning`），都走 `AssetModule` 的同步窄路（`AssetModule.Load<T>`）。
资产缺失时 `ThrowTuning.LoadOrDefault()` / `DropTuning.LoadOrDefault()` 会退化成「一份字段默认值的实例」，本局的投掷观感与冲量、掉落物抛物线手感随之失效。
这是**安全网，不是正常路径**：真丢了资产，`AssetModule` 会先记一条加载失败（并计入 `DataMetrics`），`LoadOrDefault` 再打一条 Warning 并给出默认值——两条记录同时出现就说明资产没进仓库。

## 4. 禁区与排障

| 注意 | 违反了会怎样 |
| :-- | :-- |
| **Luban 清空它的两个输出目录**：`-x` 指向的目录先整体清空再重写，不区分谁生成的 | 往 `ConfigWorkspace/output/` 放手写文件，下次导表直接消失 |
| **发布目录由镜像拷贝清理**：暂存区没有的文件会被删除（**`.meta` 例外保留**） | 往两个生成目录放手写文件必丢 |
| **不在生成类里写逻辑**：`Generated/Config/` 每次导入整体重写 | 手写的字段、方法、注释全丢。生成类都是 `partial`，要扩展就另建文件 |
| 调用参数必须带 `--strict` | 校验失败不改变退出码，闸门失效，坏数据被当成功发布 |
| 两个 `-x` 只能指向 `ConfigWorkspace/output/` | Luban 的写盘发生在校验之后；直接指向 `Assets/` 时一次失败导入当场毁掉整个生成目录 |
| 必须走「暂存区 → 退出码 0 → 镜像拷贝」 | 少了这层，校验失败的中间态直接进工程 |
| 仅校验模式要同时带 `-f` 与 `-x outputSaver=null` | 只带 `-f` 不保证零写入 |
| 工作目录必须是 `ConfigWorkspace` | conf 内的相对路径解析失败，报「表输入路径未找到」 |
| **删列 / 改字段名必须先通知程序**（加列、加表免通知） | 引用该字段的代码当场编译报错，策划无法自行修复 |
| `Assets/` 下所有文件与目录的 `.meta` 必须提交 | Unity 靠 GUID 维持引用，漏提交会让队友那边引用全断 |
| 新建表必须登记进 `__tables__.xlsx` | 表被静默忽略，导表不报错，白做 |
| 一格多值不支持：`list`/`array` 单元格不按分隔符拆，`map` 写法未通过验证 | 被当成一个元素，数据静默变形 |
| 怀疑路径推算错误 | 跑菜单 **Luban ▸ 路径自检（不导入）**：打印全部推算路径、两条未转义命令行、当前锁文件清单 |
