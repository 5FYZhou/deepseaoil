# 技术文档：配表管线

> 面向：**程序**。目录操作规范面向策划，另见 `策划手册_数据表填写.md`。

## 1、原理与依赖

**原理**：Excel 是唯一真相源。生成的 C# 与 JSON 全部由它派生，任何手改生成物的动作都会被下一次导入抹掉。

依赖：

| 项 | 要求 |
| --- | --- |
| Unity | 2022.3.62f3c1（URP 14.0.12） |
| .NET 运行时 | `Microsoft.NETCore.App` ≥ 8.0.0（**不需要 SDK**）。实测 8.0.25 |
| Git LFS | 拉 `ConfigWorkspace/Tools/Luban/` 的 `*.dll` / `*.exe` 之前必须装 |
| Luban 工具 | 随仓库交付，132 个文件约 5.33 MB，`net8.0` 框架依赖，入口 `dotnet Tools/Luban/Luban.dll` |
| Luban 构建指纹 | `Luban.Core.dll` 的 `ProductVersion = 1.0.0+df34215d2e22035073d1af83d44e3ac0744dc3b3` |
| Unity 侧运行库 | `Assets/Luban.Runtime/`，7 个 `.cs`，**本地拷贝，不走 UPM** |

对外版本号在二进制里读不到，可用的强标识就是上表构建指纹。

不装 UPM 的原因：UPM 包与本地拷贝的 asmdef 都叫 `Luban.Runtime`，同时存在会撞名，报 `Assembly with name 'Luban.Runtime' already exists`，整个工程所有程序集都编译不出来。

## 2、管线链路

```text
ConfigWorkspace/Data/*.xlsx            ← 源表；登记在 __tables__.xlsx
        │
        ▼
ConfigWorkspace/luban.conf             ← 分组 / schema 清单 / 数据目录 / target
        │  dotnet Tools/Luban/Luban.dll --conf luban.conf -t client --strict …
        ▼
ConfigWorkspace/output/{code,data}     ← 暂存区（gitignore）
        │  退出码 == 0 才发布
        ▼
Assets/Scripts/Generated/Config/  +  Assets/StreamingAssets/Luban/
        │  内容有变化时 AssetDatabase.Refresh()
        ▼
cfg.Tables                             ← 由 TablesHolder 构造（经 DeepseaOil.Data.ConfigModule）
        │
        ▼
DeepseaOil.Data.ConfigModule           ← 运行期唯一的**数值**入口
        │                                 Assets/Scripts/Data/Config/
        ▼                                 见 Docs/框架蓝图.md 与 Docs/分层设计/数据层.md
Assets/Scripts/Presentation/Debug/ConfigLoader.cs   ← 链路自检示例：经 ConfigModule 查询，
                                                      不再自己 new cfg.Tables
```

> ⚠️ 表里资源路径（如 `icon`）的校验盲区：`#path=unity` 只校验文件在 `Assets/` 下**存在**，
> 不校验它在 `Assets/Resources/` 下——而运行期 `Resources.LoadAsync` 只能加载后者。
> 当前表值合规（`Resources\Icons\sardline.png`），但盲区还在，下次填错仍会导表期通过、
> 运行时才失败。详见 [`分层设计/数据层.md` §5.3](../分层设计/数据层.md) 与 蓝图 D4。

Luban 校验失败也会写暂存区。**发布闸门是退出码，不是 Luban 的行为。**

## 3、配置文件的修改点位

### 改配置（改完要重新导表）

| 文件 | 影响 |
| --- | --- |
| `ConfigWorkspace/Data/*.xlsx` 数据格 | 生成的数据内容 |
| 同上的四个表头行 | 字段名（`snake_case` → C# `PascalCase`，JSON 仍是 `snake_case`）、类型与校验器、分组、注释 |
| `ConfigWorkspace/Data/__tables__.xlsx` | 哪些表被收集、表类名、输入文件名、主键字段、输出数据文件名（`output` 列，留空默认 `<模块>_<表名>`） |
| `ConfigWorkspace/Data/__enums__.xlsx` | 枚举全名、项名、项名别名、项名到数字的映射 |
| `ConfigWorkspace/Data/__beans__.xlsx` | 结构体（bean）定义。**当前为空，未使用** |
| `ConfigWorkspace/Defines/*.xml` | 内置类型（`builtin.xml` 提供 `vector2/3/4`） |
| `ConfigWorkspace/luban.conf` | 分组集合、schema 文件清单、数据目录、target 名与 `manager` / `topModule` |

**加表之后还要同步一处手写清单**：`Assets/Scripts/Data/Config/TablesMeta.cs` 的 `Names` 数组。
它给 `DataMetrics.TableCount` 与 `StartupValidator` 的关键表抽样用（生成物没有表数量属性）。

### 改输入输出路径

全部路径推算都集中在 `Assets/Editor/LubanProject.cs`，没有硬编码盘符。改路径必须成套改，漏一处会出现"导成功了但工程没变"。

| 要改什么 | 改哪里 | 备注 |
| --- | --- | --- |
| 源表目录 | `luban.conf` 的 `dataDir`；新建表还要加到 `schemaFiles` | 相对 `luban.conf` 所在目录解析（实测确认） |
| 生成代码目录 | `BuildExportCommand` 里 `-x outputCodeDir=` | 必须指向暂存区 |
| 生成数据目录 | `BuildExportCommand` 里 `-x outputDataDir=` | 必须指向暂存区 |
| 发布目录（代码） | `LubanProject.OutputCodeDir` | 与上一行配对 |
| 发布目录（数据） | `LubanProject.OutputDataDir` | 同上 |
| 暂存区 | `LubanProject.StageCodeDir` / `StageDataDir` | 改了它，`-x` 两个参数要一起改 |
| 日志目录 | `LubanProject.LogsDir` | gitignore |
| `#path=unity` 的基准 | `LubanProject.PathValidatorRoot` | 现为 `Assets`，表里路径即相对 Assets |

**发布目录与暂存区必须成对改**：`MirrorCopy(StageCodeDir, OutputCodeDir)` 与 `MirrorCopy(StageDataDir, OutputDataDir)` 是两两配对的参数。

`luban.conf` 里写绝对路径也能跑通（实测），但会锁死本机布局；路径不存在时报的是原生英文错 `Could not find a part of the path …`，排查成本高。工程内一律用相对路径。

### 改代码（不用导表）

| 文件 | 影响 |
| --- | --- |
| `Assets/Scripts/Data/Config/` | 运行期怎么读 JSON、怎么暴露查询（ConfigModule / TablesHolder / StartupValidator） |
| `Assets/Scripts/Presentation/Debug/ConfigLoader.cs` | 链路自检示例（可选，删掉不影响导表） |
| `Assets/Luban.Runtime/` | 运行期反序列化实现（SimpleJSON 等） |
| `Assets/Editor/*.cs` | 导表工具本身；改完下次导表生效 |

## 4、注意事项

| 注意 | 违反了会怎样 |
| --- | --- |
| **Luban 会清空它的两个输出目录**：`-x outputCodeDir` / `outputDataDir` 指向的目录先整体清空再重写，不区分哪些文件是它生成的 | 往 `ConfigWorkspace/output/` 里放手写文件，下次导表直接消失。该目录已 gitignore |
| **发布目录由镜像拷贝清理**：`Assets/Scripts/Generated/Config/` 与 `Assets/StreamingAssets/Luban/` 里，暂存区没有的文件会被删除，**`.meta` 例外保留** | 往这两个目录放手写文件必丢；删表后遗留的孤儿 JSON 会被自动清掉 |
| **不要在生成类里写额外逻辑**：`Assets/Scripts/Generated/Config/` 下所有文件每次导入整体重写 | 手写的字段、方法、注释全部丢失。生成类都是 `partial`，需要扩展就另建文件（`Tables` 在命名空间 `cfg`，记录类在 `cfg.demo`） |
| 调用参数必须带 `--strict` | 校验失败不改变退出码，闸门失效，坏数据被当作成功发布 |
| 两个 `-x` 输出目录只能指向 `ConfigWorkspace/output/` | Luban 的写盘发生在校验之后；直接指向 `Assets/` 时，一次失败的导入当场毁掉整个生成目录 |
| 必须走「暂存区 → 退出码 0 → 镜像拷贝」 | 少了这一层，校验失败的中间态直接进工程，Unity 立刻导入坏数据 |
| 仅校验模式要同时带 `-f` 与 `-x outputSaver=null` | 只带 `-f` 不保证零写入 |
| 工作目录必须是 `ConfigWorkspace`（`LubanProject.Workspace`） | conf 内的相对路径解析失败，报「表输入路径未找到」 |
| 加列、加表免通知；**删列 / 改字段名必须先通知程序** | 引用该字段的代码当场编译报错，策划无法自行修复 |
| `Assets/` 下所有文件与目录的 `.meta` 必须提交 | Unity 靠 `.meta` 的 GUID 维持引用，漏提交会让队友那边引用全断 |
| 不要装 Luban 的 UPM 包 | 见第 1 节的撞名后果 |
| 新建表必须登记进 `__tables__.xlsx`，否则不被收集 | 表被静默忽略，导表不报错，白做 |
| 一格多值不支持：`list` / `array` 的单元格值不按分隔符拆，`map` 的单元格写法未通过验证 | 会被当成一个元素，数据静默变形 |
| 怀疑路径推算错误时 | 跑菜单「Luban」→「路径自检（不导入）」，打印全部推算路径、两条未转义命令行、当前锁文件清单 |
