# 策划手册：数据表填写

## 1. 导一次表

| 步 | 动作 |
| :-- | :-- |
| 1 | `Git` 拉取最新改动 |
| 2 | 改 `ConfigWorkspace/Data/` 下的表格（表头 4 行见 §2） |
| 3 | **保存** |
| 4 | **关闭 Excel**（否则锁住文件，导表读不到） |
| 5 | 切回 Unity，按 <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>D</kbd>（菜单 `Luban ▸ 表格数据导入`；<kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>K</kbd> 是仅校验，只报错不写盘） |
| 6 | `Git` 提交：表格与 `Assets/Scripts/Generated/Config/`、`Assets/StreamingAssets/Luban/` 下的生成物一起提交 |

**导入失败不改动工程里任何文件，反复重试是安全的。** 报错照 §3 改。

## 2. 怎么调表

工作路径：

![p3](image\p3.png)

### 表头四行

| 行 | A1 列 | 非 A1 列填什么 | 例 |
| :-- | :-- | :-- | :-- |
| 1 | `##var` | 程序字段名，**只允许小写英文和下划线** | `atk_speed` |
| 2 | `##type` | 数据类型，见下表 | `float` |
| 3 | `##group` | 分组，目前一律填 `c`（client 客户端） | `c` |
| 4 | `##comment` | 中文注释，会写成程序里的注释 | `攻速` |
| 5 起 | 空 | **数据从这里开始，第 1 列不填** | `1.2` |

![p4](image\p4.png)

### 数据类型（第 2 行）

| 我要什么 | 写什么 | 留空会怎样 |
| :-- | :-- | :-- |
| 整数 / 小数 / 文字 / 是否 | `int` / `float` / `string` / `bool` | 0 / 0 / 空 / 否 |
| 必须填 | `int!` `float!`（加叹号） | 报错 |
| 限范围 | `int#range=[1,100]`；`[1,]` 表示 1 到无穷 | 报错 |
| 引用他表（外键） | `int#ref=demo.TbItem` | 报错 |
| 引用可空 | `int#ref=demo.TbItem?` | 不报 |
| 限定取值 | `int#set=5` / `int#(set=1,2,3)` | 报错 |
| 资源路径 | `string#path=unity`，填**相对 `Assets`** 的路径 | 不报 |

- 限制符写在**类型行**，不写数据格。
- 多值必须**括号 + 逗号**；用 `;` 直接报错。
- 🔴 程序**只能加载 `Assets/Resources/` 下**的资源。导表期只校验"文件在 `Assets/` 下存在"，不校验它在 `Resources/` 下——填了别处的路径**导表不报错，运行期黑屏**。资源一律放 `Assets/Resources/` 下再填。

### 加表

表格文件自己建，但**必须登记**：在 `ConfigWorkspace/Data/__tables__.xlsx` 加一行。

| 列 | 填什么 | 例 |
| :-- | :-- | :-- |
| `full_name` | 模块名 + `Tb` + 记录名 | `demo.TbFish` |
| `value_type` | 记录类名 | `Fish` |
| `input` | 表格文件名 | `fish.xlsx` |
| `index` | 主键字段 | `id` |
| `output` | 生成的数据文件名 | `demo_tbfish` |

![p5](image\p5.png)

### 加列

**可以插在任意位置**，包括两个已有字段之间。插入一列 → 填齐 4 行表头 → 逐行补数据格（留空可以，但**数字格留空会变成 `0`**）→ 保存 → 关 Excel → 导表。

![p6](image\p6.png)

### 登记枚举

在 `ConfigWorkspace/Data/__enums__.xlsx`：`full_name` 写完整枚举名（如 `demo.Quality`），**每个枚举项占一行**。

![p7](image\p7.png)

**枚举列的数据填"别名"（中文），不是英文项名**：

| 枚举 | 可选值（填这些） |
| :-- | :-- |
| `demo.Quality`（品质） | `普通` / `精良` / `史诗` |
| `demo.BallType`（球种） | `水` / `土` |
| `demo.TileStateType`（格子状态） | `常规` / `泥浆` |

### 战斗相关的六张表（白模迁移新增）

填写口径：**只改数据格，不要动这四行表头**（字段名/类型是程序的契约，改字段名会让代码编译不过）。

#### `projectile.xlsx` — 球种（2 行：水球 / 土球）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` | 球种 ID（枚举 `水` / `土`） | 枚举别名 | 水 / 土 |
| `name` | 显示名 | 文字 | 水球 / 土球 |
| `flight_duration` | 最远一投的飞行时长（秒） | 0.05 ~ 5 | 0.6 |
| `max_height` | 抛物线视觉最高点（世界单位） | 0 ~ 10 | 2 |
| `max_throw_distance` | 最远投掷距离（世界单位） | 0.5 ~ 50 | 5 |
| `min_throw_distance` | 最小投掷距离：鼠标压在脚下时兜底 | 0.01 ~ 5 | 0.4 |
| `tile_state` | **落地后把落点格改成什么状态**（`常规` = 不改） | 枚举别名 | 水=泥浆 / 土=常规 |

> 水球落地改格子（格子再对踩上去的敌人结算伤害与击退）；土球不改格子。
> 想给土球加效果时，先填这一列或找程序加列。

#### `enemy.xlsx` — 敌人（1 行：白模敌人）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` | 编号（主键） | 整数 | 1 |
| `name` | 显示名 | 文字 | 白模敌人 |
| `radius` | 视觉与碰撞半径（世界单位） | 0.05 ~ 5 | 0.45 |
| `max_speed` | 追击满速（单位/秒，玩家是 8） | 0 ~ 50 | 3.6 |
| `acceleration` | 加速度（单位/秒²）—— 决定"起步看得出来" | 0 ~ 300 | 14 |
| `knockback_decay` | 被击退后的滑行衰减率（1/秒），越大停得越快 | 0 ~ 100 | 10 |
| `stop_distance` | 贴到多近就停下（世界单位，**必须小于接触半径**） | 0 ~ 10 | 0.6 |
| `chase_range` | 超出多远就放弃追击 | 0 ~ 200 | 60 |
| `stun_seconds` | 被打中后的禁足时长（秒）—— **它同时是"被推多远"的旋钮** | 0 ~ 5 | 0.24 |
| `hp` | 耐久（几下打碎） | 1 ~ 999 | 3 |
| `flash_hz` | 受击闪烁频率（Hz，**不要超过 10**，60 帧下会变成闪频） | 0 ~ 10 | 4 |

#### `tile_state.xlsx` — 格子状态（2 行：常规 / 泥浆）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` | 状态 ID（枚举 `常规` / `泥浆`） | 枚举别名 | 常规 / 泥浆 |
| `name` | 显示名 | 文字 | 常规 / 泥浆 |
| `slow_factor` | 踩在上面的速度系数（1 = 不减速） | 0 ~ 1 | 常规 1 / 泥浆 0.45 |
| `duration` | 持续时长（秒，**0 = 永久**） | 0 ~ 600 | 常规 0 / 泥浆 8 |
| `enter_damage` | **进入该状态时**对该格敌人的伤害 | 0 ~ 999 | 常规 0 / 泥浆 1 |
| `enter_knockback` | 进入该状态时对该格敌人的击退冲量 | 0 ~ 50 | 常规 0 / 泥浆 1.83 |

> ⚠️ 这四列的"常规"行要填 `0`，所以**类型行里不能带 `!`**（`!` 表示"不许是默认值"，填 0 会被判失败）。见《技术文档_配表管线》§3.1.1。
> **伤害在"每一次球落地"时都会结算一次**（与该格是不是已经是泥浆无关），但泥浆的 8 秒计时**不会**被刷新。

#### `player.xlsx` — 玩家（1 行）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` / `name` | 编号 / 显示名 | 整数 / 文字 | 1 / 玩家 |
| `max_hp` | 血量上限 | 1 ~ 99999 | 100 |
| `contact_damage` | 敌人贴身一次造成的伤害 | 0 ~ 9999 | 10 |
| `invulnerable_duration` | 受击后的无敌时长（秒） | 0 ~ 10 | 0.8 |
| `retry_delay` | 打空后到重来之间的停顿（秒） | 0 ~ 60 | 1.2 |
| `attack_interval` | 两次攻击之间的最短间隔（秒） | 0.01 ~ 10 | 0.5 |
| `knockback_impulse` | 受击被推开的冲量 | 0 ~ 100 | 12 |
| `knockback_speed_limit` | 受击期间的速度上限（**与冲量填同一个数**，否则推不满） | 0 ~ 100 | 12 |
| `contact_radius` | 判定"敌人贴上了"的圆心距（世界单位） | 0.05 ~ 10 | 1 |

#### `wave.xlsx` — 波次（1 行）

| 列 | 含义 | 取值范围 | 现值 |
| :-- | :-- | :-- | :-- |
| `id` / `name` | 编号 / 显示名 | 整数 / 文字 | 1 / 默认波次 |
| `enemies_per_wave` | 每波敌人数 | 1 ~ 100 | 4 |
| `spawn_interval` | 同波内两只之间的间隔（秒） | 0.01 ~ 10 | 0.25 |
| `initial_delay` | 开局到第一波的等待（秒） | 0 ~ 60 | 1.5 |
| `respawn_delay` | 清完一波到下一波的等待（秒） | 0 ~ 60 | 2.5 |
| `spawn_radius` | 出生环半径（世界单位，以玩家为圆心） | 0.5 ~ 50 | 5 |

#### `tile_initial.xlsx` — 关卡初始格子状态（**当前 0 行**）

| 列 | 含义 | 取值范围 |
| :-- | :-- | :-- |
| `id` | 编号（主键，随便给不重复的整数） | 整数 |
| `cell_x` / `cell_y` | 格子坐标（**必填**） | 整数 |
| `state_id` | 初始状态（枚举 `常规` / `泥浆`） | 枚举别名 |

> 一行 = "开局时把某一格设成某状态"。开局就站在泥浆上的敌人**不会**掉血（伤害的语义是"发生了转换"）。
> 当前没有"关卡"维度：所有行都作用于当前场景；关卡系统立项后再加 `level` 列。

## 3. 报错对照

| 报错片段 | 我该改哪一格 |
| :-- | :-- |
| `位置:[D5] abc` / `abc 不是 int 类型值` | `weapon.xlsx` D5。这列只能放数字 |
| `'普通剑' 不是 enum:'demo.Quality' 的有效枚举值` | 品质列。改成 `普通`/`精良`/`史诗`（或对应枚举的别名） |
| `durability:999 … 不在范围:[1,100] 内` | 编号 1 那行的耐久度 |
| `[常规(0)].duration:0 … 是一个默认值` | 这一列的类型行带了 `!`，而 `!` 的含义是"**不许是默认值**"（数字的默认值是 0）。**明确填 0 也会报**。要么填非 0，要么让程序把这一列的 `!` 去掉（本次 `tile_state` 就是后者）。见《技术文档_配表管线》§3.1.1 |
| `best_weapon = 9 … 在引用表…中不存在` | 编号 1001 那行的推荐武器。改成武器表有的编号 |
| `icon:… 找不到对应文件` | 编号 3 那行的图标格。改成存在的路径 |
| `有表格正被 Excel 占用` | 不用改格子。保存并**关闭**名单里的表 |

改完重新导表。Console 里 `[Luban] 完整日志：` 指向的文件有全部输出。
