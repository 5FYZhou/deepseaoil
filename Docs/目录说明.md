# 目录说明

本文件回答一个问题：**每个文件夹装什么**。目录树由 `仓库一致性Tests.目录说明与磁盘同源` 守着 —— 树里写的每个路径都会在 Test Runner 里被断言真实存在于磁盘上，脱钩即红。

---

## 根目录文件

| 文件 | 作用 |
| :-- | :-- |
| `README.md` | 落地页，指向 `Docs/目录说明.md` |
| `.gitignore` / `.gitattributes` | 忽略规则（`Library/`、`Temp/`、`Logs/`、`ConfigWorkspace/output|logs/`）；LFS 与换行符规则 |
| `deepseaoil.sln` / `*.csproj` | Unity 自动生成，已在 `.gitignore` 里（列于此处仅为说明来源） |
| `.vsconfig` | Visual Studio 组件清单，与配表无关 |

## 三处生成物禁区

放在这些位置的手写文件会被**静默删除** —— 不报错，只是下次生成后不见了。

| 目录 | 谁生成 | 何时覆盖 |
| :-- | :-- | :-- |
| `Assets/Scripts/Generated/Config/` | Luban 导表（`-c cs-simple-json`） | 每次导表整目录镜像覆盖，暂存区没有的文件被删除（`.meta` 例外保留） |
| `Assets/StreamingAssets/Luban/` | Luban 导表（`-d json`） | 同上 |
| `Assets/Scripts/Generated/Input/InputSys.cs` | Input System 从 `Presentation/Input/InputSys.inputactions` 生成 | `.inputactions` 被重新导入/修改时整体重写（文件头明确写着 manual edits will be discarded） |

需要扩展生成类时另建文件：生成类都是 `partial`。

## `Assets/Resources/` 的字符串 Key

这些 Key **由路径派生**，所以 `Assets/Resources/` 下任何移动都会当场断链（不报编译错，只在运行期加载失败）。

| Key | 解析到 | 出现位置 |
| :-- | :-- | :-- |
| `ui/UICamera` | `Assets/Resources/ui/UICamera.prefab` | `Presentation/UI/UIMgr.cs` |
| `ui/Canvas` | `Assets/Resources/ui/Canvas.prefab` | 同上 |
| `ui/EventSystem` | `Assets/Resources/ui/EventSystem.prefab` | 同上 |
| `ui/Panel/<面板类名>` | `Assets/Resources/ui/Panel/<面板类名>.prefab` | 同上（所以**预制体名必须等于面板类名**） |
| 表里 `icon` 字段的值 | 形如 `Resources\Icons\xxx.png` | Excel → `StreamingAssets/Luban/*.json` |

转换点是唯一一处：`Data/Asset/AssetRegistry.cs`。表里存「相对 `Assets/` 带扩展名」，`Resources.LoadAsync` 要「相对 `Assets/Resources/` 不带扩展名」。

## 三层 ↔ 目录 ↔ 命名空间

判定层的依据是**命名空间**，不是目录。目录按同一套分层组织，所以两者现在是一致的。

| 目录 | 命名空间 | 层 |
| :-- | :-- | :-- |
| `Scripts/Data/` | `DeepseaOil.Data` | 数据层 |
| `Scripts/Logic/` | `DeepseaOil.Logic`、`DeepseaOil.Logic.{Movement,Movement.States,Player,Input,Events,Service}` | 逻辑层 |
| `Scripts/Presentation/` | `DeepseaOil.Presentation`、`DeepseaOil.Presentation.UI` | 表现层 |
| `Scripts/Foundation/` | `DeepseaOil.Foundation` | 不属三层：与游戏无关的地基 |
| `Scripts/Generated/` | `cfg`、`cfg.demo`、`DeepseaOil.Generated` | 不属三层：机器生成 |
| `Editor/` | `DeepseaOil.EditorTools` | 不属三层：编辑器工具（独立程序集） |
| `Tests/Tools/` | `DeepseaOil.EditorTools.Tests` | 测试 |
| `Tests/Runtime/Editor/` | `DeepseaOil.Tests` | 测试 |

## `Assets/Tests/` 为什么有两个目录

它们的分界**不是** EditMode / PlayMode（两边都在 EditMode 里跑），而是**有 asmdef vs 无 asmdef**：

- asmdef 程序集**无法**引用预定义程序集 `Assembly-CSharp`，而 `Scripts/` 下的全部运行时代码都在其中。所以 `Tests/Tools/`（被 asmdef 覆盖）够不到它们，只能测 `Assets/Editor/`。
- `Tests/Runtime/Editor/` **故意不建 asmdef**，靠「路径里有一个名为 `Editor` 的目录」落 `Assembly-CSharp-Editor` —— 它既能引用 `Assembly-CSharp`，又被 Test Framework 自动引用 NUnit。
- 🔴 因此 `Tests/Runtime/Editor/` 的**末级目录名 `Editor` 不可改**，也不能给它加 asmdef。
