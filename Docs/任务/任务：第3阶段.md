# 任务一：`VisualPalette` 数组化

## 1.1 目标

把 `BallColor(BallType)` 与 `DropColor(DropType)` 两个 `switch` 方法改为**数组驱动**。加新球种 / 掉落物时，Inspector 加一行即可，不再改代码。

**同时**：
- **数据迁移**：旧的 `waterBall` / `earthBall` 字段值要自动迁到新数组
- **自检**：数组里的条目做校验（重复、未覆盖），异常报错

## 1.2 数据结构

新增两个 `[Serializable]` struct：

```csharp
[Serializable]
public struct BallColorEntry
{
    public cfg.dso.BallType Type;
    public Color Color;
}

[Serializable]
public struct DropColorEntry
{
    public DropType Type;
    public Color Color;
}
```

**注意**：`BallType` 在 `cfg.dso` 命名空间（生成物），`DropType` 在 `DeepseaOil.Data` 命名空间（本地枚举）。

## 1.3 字段改造

**新增**：

**处理旧字段 `waterBall` / `earthBall`**：

- 加注释说明："数据迁移字段：首次打开本资产时自动迁往 ballColors 数组，迁移完成后可由用户手删"

## 1.4 数据迁移逻辑

**在 `OnValidate` 里自动迁移**（编辑器内首次打开资产即触发）：

```csharp
#if UNITY_EDITOR
private void OnValidate()
{
    MigrateLegacyColors();
    ValidateEntries();
}

/// <summary>旧字段 → 新数组：仅在数组为空且旧字段非默认时触发，幂等</summary>
private void MigrateLegacyColors()
{
    if (ballColors == null || ballColors.Length == 0)
    {
        var migrated = new System.Collections.Generic.List<BallColorEntry>(2);

        if (waterBall != default(Color))
            migrated.Add(new BallColorEntry { Type = cfg.dso.BallType.Water, Color = waterBall });

        if (earthBall != default(Color))
            migrated.Add(new BallColorEntry { Type = cfg.dso.BallType.Earth, Color = earthBall });

        if (migrated.Count > 0)
        {
            ballColors = migrated.ToArray();

            // 迁移后清空旧字段，防止重复迁移
            waterBall = default;
            earthBall = default;

            UnityEditor.EditorUtility.SetDirty(this);

            Debug.Log($"[VisualPalette] 已迁移 waterBall / earthBall 到 ballColors 数组（{migrated.Count} 条）。");
        }
    }
}
#endif
```

**注意**：
- `default(Color)` 是 `(0,0,0,0)`，与 Unity 里"未填"的显示一致
- 迁移后**清空旧字段**（置 default），避免下次 `OnValidate` 重复迁移
- `SetDirty` 标记资产被改，Unity 会提示保存

**关于 `dropColors`**：现在没有对应的旧字段（`DropColor` 方法是 switch 硬编码），所以**不做迁移**——用户手工填。但为了一致性，`OnValidate` 里可以给一条提示（若 `dropColors` 为空，且用户点过某 flag）：

**简化处理**：不做 `dropColors` 的迁移，用户手工填（提示词的用户手工清单里说明）。

## 1.5 自检逻辑

```csharp
/// <summary>数组条目校验：重复项报错，未覆盖项警告一次</summary>
private void ValidateEntries()
{
    ValidateBallColors();
    ValidateDropColors();
}

private void ValidateBallColors()
{
    if (ballColors == null || ballColors.Length == 0) return;

    for (int i = 0; i < ballColors.Length; i++)
    {
        for (int j = i + 1; j < ballColors.Length; j++)
        {
            if (ballColors[i].Type == ballColors[j].Type)
            {
                Debug.LogError(
                    $"[VisualPalette] ballColors 里 {ballColors[i].Type} 出现了两次（第 {i} 行与第 {j} 行）：只会取第一条。",
                    this);
            }
        }
    }

    // 覆盖率警告：未覆盖的枚举值会在运行时回落到 unknownBall
    foreach (cfg.dso.BallType type in System.Enum.GetValues(typeof(cfg.dso.BallType)))
    {
        bool found = false;

        for (int i = 0; i < ballColors.Length; i++)
        {
            if (ballColors[i].Type == type) { found = true; break; }
        }

        if (!found)
        {
            Debug.LogWarning(
                $"[VisualPalette] ballColors 未覆盖 {type}：运行时回落到 unknownBall。",
                this);
        }
    }
}
```

`ValidateDropColors` 同构。

**注意**：`OnValidate` 会被频繁调用（Inspector 每次改动都会），**不要在里面打太多日志**。覆盖率警告会刷屏。缓解：

- 覆盖率警告用 `Debug.LogWarning` 但只在"资产被改动时"打一次（用一个 static flag 记录已警告的枚举值）
- 或干脆用 `LogWarningFormat` 汇总成一条

**推荐**：汇总成一条警告：

```csharp
// 收集缺失的枚举值，最后一条警告
var missing = new System.Collections.Generic.List<string>();

foreach (cfg.dso.BallType type in System.Enum.GetValues(typeof(cfg.dso.BallType)))
{
    bool found = false;
    for (int i = 0; i < ballColors.Length; i++)
    {
        if (ballColors[i].Type == type) { found = true; break; }
    }
    if (!found) missing.Add(type.ToString());
}

if (missing.Count > 0)
{
    Debug.LogWarning($"[VisualPalette] ballColors 未覆盖：{string.Join(", ", missing)}，运行时回落 unknownBall。", this);
}
```

## 1.6 `BallColor` / `DropColor` 方法改造

```csharp
/// <summary>球种 → 颜色；未列出的回落到 unknownBall</summary>
public Color BallColor(cfg.dso.BallType type)
{
    if (ballColors != null)
    {
        for (int i = 0; i < ballColors.Length; i++)
        {
            if (ballColors[i].Type == type) return ballColors[i].Color;
        }
    }

    return unknownBall;
}

/// <summary>掉落物 → 颜色；未列出的回落到 unknownBall</summary>
public Color DropColor(DropType type)
{
    if (dropColors != null)
    {
        for (int i = 0; i < dropColors.Length; i++)
        {
            if (dropColors[i].Type == type) return dropColors[i].Color;
        }
    }

    return unknownBall;
}
```

**性能**：数组线性查找。当前 2 条，O(1)。未来 10 条也 O(1) 量级。**不预建 Dictionary**（Play 时热路径是投掷 / 掉落，不在每帧调）。

## 1.7 `LoadOrDefault` 保持

`VisualPalette.LoadOrDefault` 现有实现不改（缺资产走 `CreateInstance`）。但**注意**：

- `CreateInstance<VisualPalette>()` 时，`ballColors` / `dropColors` 是空数组
- 走 `BallColor(Water)` 会回落到 `unknownBall`（白）
- **降级行为可接受**（比之前 switch 版"未知也回落到 unknownBall"一致）

**可选增强**（不做）：在 `LoadOrDefault` 里若走降级路径，给 `ballColors` / `dropColors` 填默认两条。**不做**——降级就是降级，不给"看似有值"的假象。

## 1.8 消费点核对

- `ProjectileSpec.BallColor` → `ConfigModule.Visuals.BallColor(Type)`（**方法签名未变，消费点不改**）
- `DropSpec.Color` → `ConfigModule.Visuals.DropColor(_type)`（**同上**）
- `ProjectileSpec.ShadowColor` → `ConfigModule.Visuals.shadow`（**不变**）
- 其他字段（`enemyBodyNormal` / `enemyBodySlowed` / `highlightAvailable` / `highlightBlocked` / `shadow`）**全部保留**

**结论**：消费点**零改动**。方法签名保持向后兼容。

## 1.9 验收

- `VisualPalette.asset` 打开后，Inspector 显示 `ballColors` / `dropColors` 两个数组（`waterBall` / `earthBall` 已隐藏）
- 首次打开时 Console 有 `已迁移 waterBall / earthBall 到 ballColors 数组（2 条）`
- 保存资产后，`ballColors` 数组里 Water / Earth 两条颜色与迁移前一致
- 进 Play，投水球 / 土球颜色不变
- 掉落物（水/土/种子）颜色不变
