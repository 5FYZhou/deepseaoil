> # 角色
>
> 你是本仓库的**文档对齐执行者**。任务分两阶段：
>
> - **阶段一（本任务书全部）**：扫代码 diff → 出"改动总账"与"文档波及面清单" → **停下等用户批准**
> - **阶段二（用户批准后另行下发）**：按批准的清单逐条改文档
>
> 本任务书**只做阶段一**。阶段二不在本任务书范围，不许提前动 `Docs/`。
>
> ---
>
> # 一、铁律（不要动这些）
>
> 1. **本任务书阶段一：一个文件都不改**。纯扫描 + 报告。
> 2. **严禁**：`.cs` / `.asmdef` / `.asset` / `.prefab` / `.unity` / `.mat` / `ConfigWorkspace/**` / `Tools/**`。**包括 `Docs/**`**。
> 3. **不改 `Tools/comment-budget.json`**。
> 4. **不跑** `-Mode seal` / `-Mode verify` / `luban-mirror.ps1`。
> 5. **不发明**：diff 里没有的改动不进总账；总账里的改动不推导出"文档该改成什么"（那是阶段二的事）。
> 6. **不评价**代码改动本身（好坏、风格、是否合理）。你只做"记录"。
> 7. **遇到不确定立即停**。
>
> ---
>
> # 二、第一步核对输入（缺一停）
>
> 用户会提供**两个 commit**：
>
> | 名           | 含义                      |
> | ------------ | ------------------------- |
> | `STAGE_BASE` | 阶段起点（T 批之前）      |
> | `HEAD`       | 阶段末（批 4 / 6 已提交） |
>
> 核对：
>
> 1. `git log --oneline <STAGE_BASE>..HEAD` 打印提交列表，确认非空
> 2. `git status` 必须干净（阶段一不动文件，但基线要干净）
> 3. `git diff --stat <STAGE_BASE>..HEAD` 看规模
>
> **若 `STAGE_BASE` 与 `HEAD` 相同**（无提交）→ 停下汇报。
>
> **若工作区不干净** → 停下汇报（可能是用户还有未提交改动；需澄清后重来）。
>
> ---
>
> # 三、改动总账（Agent 扫描产出）
>
> ## 3.1 扫描命令
>
> ```
> git diff <STAGE_BASE>..HEAD -- '*.cs' '*.asmdef'
> git diff --stat <STAGE_BASE>..HEAD -- '*.cs' '*.asmdef'
> ```
>
> **只扫 `.cs` 与 `.asmdef`**。`.asset` / `.prefab` / `.unity` / `.mat` 不进总账主体（属"Unity 侧变更"，另列 §3.3）。
>
> ## 3.2 分类维度
>
> 对每份改动文件，按下列维度**逐条**记录：
>
> | 维度                  | 记录什么                                                     |
> | --------------------- | ------------------------------------------------------------ |
> | **A · 类型签名**      | class / struct / enum / interface 的新增 / 删除 / 重命名     |
> | **B · 成员签名**      | field / property / method / event 的新增 / 删除 / 重命名 / 签名变更 |
> | **C · 命名空间**      | 迁移 / 新增 / 删除                                           |
> | **D · 枚举成员**      | 增删                                                         |
> | **E · 文件**          | 新增 / 删除 / 移动（重命名）                                 |
> | **F · 常量 / 字面量** | 硬编码 → SO / 表 的搬迁；字符串 Key 变更                     |
> | **G · 契约注释**      | `/// <summary>` / `/// <remarks>` 里明示"契约"的行变化       |
>
> **判据**：只记录**改动事实**，不做"文档该不该改"的推断。
>
> ## 3.3 Unity 侧变更（另列，不细扫）
>
> ```
> git diff --stat <STAGE_BASE>..HEAD -- '*.asset' '*.prefab' '*.unity' '*.mat' '*.controller'
> ```
>
> 只出"改动的文件清单 + 规模"，不出逐行分析。**用于用户手工核对**。
>

>

>
> | 文档 | 本阶段是否可能波及 | 依据（哪一条总账条目触发怀疑） |
