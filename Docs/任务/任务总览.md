### 一、美术需求意图解构与工程矛盾消除 (First-Principles Analysis)

将《美术视觉规范》与《执行宪章》结合现网源码对比分析，美术的核心诉求可提炼为**“低饱和复古赛博、手绘色块感、重色调轻明暗”**。要将这些感性与规范要求落入代码库，必须在架构层面消解以下 5 处关键工程矛盾：

```text
       ┌───────────────────────────────┐        ┌───────────────────────────────┐
       │   美术原始诉求 / 概念设计     │        │     工程实操陷阱与硬约束      │
       ├───────────────────────────────┤        ├───────────────────────────────┤
       │ 1. 2D俯视受光与立体感        │  VS    │ 默认Lit导致像素发脏、全屏死黑 │
       │ 2. 金属强反光 / 玻璃高光      │  VS    │ 缺乏法线贴图，严禁PBR材质     │
       │ 3. 泥浆陷入感 / 地貌高低差    │  VS    │ 纯平面Tilemap，无高度图与深度 │
       │ 4. 蒸汽/导电/火池等元素发光   │  VS    │ 大量静态光源引发DrawCall爆炸  │
       │ 5. 濒死全屏裂纹与暗角反馈     │  VS    │ 复杂后处理Blit严重拖累低端机  │
       └───────────────────────────────┘        └───────────────────────────────┘
```

#### 1. 矛盾消解与判定标准

1. **光照模型：赛璐珞色阶（Cel-Lit） vs 传统漫反射（Lambert/Blinn-Phong）**
   - **痛点**：URP 2D 默认 Lit Shader 会根据光源距离做连续反比例衰减。美术素材本身是手绘低饱和色块，一旦被线性衰减压暗，暗部会产生大量灰脏污色（发泥）。
   - **消解**：放弃平滑连续衰减。全局光照仅作为**色调乘数（Tint Multiplier）**，且必须锁死**环境光下限（Ambient Floor $\ge 0.35$）**；地貌与物体受光采用“阶梯截断（Step-Banding）”，保持色块清晰利落。
2. **高光与立体感：手绘伪高光 vs 法线贴图（Normal Map）**
   - **痛点**：美术需要金属反光和冰面高光，但明确“禁止物理真实感、禁止法线贴图”。
   - **消解**：在 Shader 片元层以原始贴图亮度（Luminance）或顶端 UV 梯度进行阈值截断（如 $UV.y > 0.92$ 或 $Luminance > 0.85$），直接叠加 `#F9CE5A`（明黄）或白色硬高光线。
3. **陷入感与伪高度：纯物理位移 vs 视差/高度图**
   - **痛点**：泥浆和稀泥地貌需要“踩进去的陷入感”，但 Tilemap 没有 3D 深度。
   - **消解**：严禁在 Shader 中写视差偏移。由逻辑层/表现层控制器联动，当角色/怪物的中心格属于 `Mud` 或 `MudSkid` 时，真身渲染器（`View.localPosition.y`）直接向下偏移 **0.08 世界单位**（8 像素），产生机械沉降，零 Shader 开销。
4. **发光与特效通道：Unlit 绝对隔离 vs 受光**
   - **痛点**：若全场景统一受光，受击纯白剪影（`SpriteFlash`）、伤害跳字（`DamagePopup`）、电弧粒子在夜间会被压暗成灰色。
   - **消解**：**材质与通道物理分流**。地表/角色走 Cel-Lit（受光），粒子/弹幕/飘字/UI 走 100% Unlit。光源的 Target Sorting Layers 严禁勾选特效与 UI 层。

### 二、工程现状差距分析 (As-Is vs To-Be Gap Analysis)

对照主场景 `Range.unity` 及当前 Presentation 层代码，存在以下断层需要系统化补全：

| 维度              | 工程现状 (As-Is)                                            | 目标规范 (To-Be)                                     | 差距与阻断点                                                 |
| :---------------- | :---------------------------------------------------------- | :--------------------------------------------------- | :----------------------------------------------------------- |
| **Light2D 组件**  | 全仓 **0 盏** Light2D，三个沙盒仅有空 GameObject            | 1 盏全局光照（Global Light） + 32 盏池化动态点光源   | 缺少全局光照时段控制器；缺少地块点光源对象池与驱动           |

| **材质矩阵**      | 六层 Tilemap 共用默认 Sprite-Unlit 材质                     | 地貌/角色用 Cel-Lit；特效/飘字保持 Unlit             | 现状下即使场景放入 Light2D，Tilemap 也完全不产生任何光照反应 |

### 三、关键技术选型与 Trade-off 决策表

在开启第一步具体代码落地前，以下 **3 个核心技术分叉点**需要确立标准：

#### 决策点 1：地表与实体的受光着色器（Cel-Lit Shader）实现路径

| 评估维度          | 推荐方案：轻量定制 Cel-Lit Shader (`DeepseaOil/2D/CelLit`)   | 备选方案 A：直接使用 URP 官方 `Sprite-Lit.shader` | 备选方案 B：保持纯 Unlit，全局用材质 Tint 变量与后处理模拟 |
| :---------------- | :----------------------------------------------------------- | :------------------------------------------------ | :--------------------------------------------------------- |
| **选型理由**      | 精确锁死 Ambient Floor $\ge 0.35$ 底线；内置手绘高光线，无 PBR 杂质 | 引擎自带，零开发成本                              | 性能极高，DrawCall 零增加                                  |
| **致命缺陷/代价** | 需手写 1 个轻量 URP 2D HLSL Pass                             | 官方光照为连续衰减，暗部发脏，无法实现手绘硬高光  | 无法实现局部火池/电网的点光源投射与呼吸感                  |
| **DrawCall 影响** | 受光统一合批，增加极小                                       | 易受官方复杂宏干扰合批                            | 零额外 DrawCall                                            |
| **适用规模**      | 商业量产，保证艺术风格绝对可控                               | 极速白模验证阶段                                  | 极简像素/低配平台                                          |
| **结论建议**      | **推荐定制**：编写单 Pass、支持 2D Light、带硬阶梯保护的 Cel-Lit Shader。 |                                                   |                                                            |

#### 决策点 2：Sorting Layer 物理分层与光照隔离拓扑

| 评估维度         | 推荐方案：5 层轻量物理隔离结构                               | 备选方案：维持 Default 单层，靠 Sorting Order 区分 |
| :--------------- | :----------------------------------------------------------- | :------------------------------------------------- |
| **方案结构**     | `Ground` (地表) $\rightarrow$ `Actor` (角色/立面) $\rightarrow$ `Aim` (瞄准) $\rightarrow$ `Effect` (粒子/弹幕) $\rightarrow$ `UI` | 全都在 `Default` 层，纯靠 Order（0~1200）区分      |
| **选型理由**     | Light2D 的 `Apply To Sorting Layers` 只能按 Layer 过滤，无法按 Order 过滤 | 不用动 `TagManager.asset`，改动最小                |
| **光照隔离能力** | **完全隔离**：Light2D 仅勾选 Ground 与 Actor，Effect/UI 绝对不受光 | **完全失效**：灯光会无差别照射 UI 和全屏特效       |
| **结论建议**     | **推荐 5 层隔离**：这是 2D 光照管线成立的物理前提，必须在 `TagManager` 登记分层。 |                                                    |

#### 决策点 3：全局光照时段（Time-of-Day）驱动与业务解耦

| 评估维度     | 推荐方案：数据驱动的 `EnvironmentDirector` (表现层组合根挂载) | 备选方案：耦合进 `WaveLogic` / 关卡状态机 |
| :----------- | :----------------------------------------------------------- | :---------------------------------------- |
| **架构归属** | `DeepseaOil.Presentation.Visual`，订阅波次/时间事件，纯表现控制 | `DeepseaOil.Logic.Wave` 直接控制灯光参数  |
| **选型理由** | 遵守架构铁律：Logic 层禁止引用 UnityEngine/Light2D，时间与色温属于视觉表现 | 编写简单，几行代码搞定                    |
| **扩展性**   | 既支持按关卡波次（Wave 1 白天, Wave 4 黄昏, Wave 6 夜晚），也支持沙盒直接调参 | 破坏单向依赖，编译门拓扑守卫必红          |
| **结论建议** | **推荐方案**：表现层编写环境控制器，接收逻辑事件并做平滑插值过渡。 |                                           |
