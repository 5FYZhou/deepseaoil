## 结论

抽搐不是"流场算错了路"，而是三件事叠出来的：**① 每个物理帧重新二选一的转向模式（直线 / 阶梯）没有滞回；② 反向时速度矢量当帧整块翻面（配置的加速度在这一刻完全不生效）；③ 玩家身体是物理障碍，但流场不认识它**——顶住 → 引擎把速度压到零 → 被判"卡死" → 换步侧移 → 再顶住，约 0.44 秒一轮。所以修的方向不是把流场算得更准，而是**给方向加闸门、给模式加滞回、把"被目标身体顶住"从卡死里摘出去**。

## 四个机制（按贡献排序）

**① 直线/阶梯每帧重判，无滞回** — [EnemyNavigator.cs:80](Assets/Scripts/Logic/Actor/EnemyNavigator.cs:80) 每帧问一次 [IsStraightDescend](Assets/Scripts/Logic/Actor/EnemyNavigator.cs:125)：它要求沿"到玩家**原始位置**"的直线，采样点场距**严格**递减。直线模式输出的方向恰好指向玩家（实测误差 0.0°），阶梯模式输出的是 [一步父采样点](Assets/Scripts/Logic/Actor/EnemyNavigator.cs:175)——只有 **0.25 格**远，所以是轴对齐的 4 邻步，最坏偏 45°+。两者的差就是这个抖动，而判据本身逐帧翻转、没有任何记忆。

**② 反向是当帧瞬变，配置的加速度在这一刻不存在** — [ActorLedger.cs:151](Assets/Scripts/Logic/Movement/ActorLedger.cs:151) 的反向分支：`decay` 那一支数学上**永远取不到**——`|desired − current| > |current| > λ|current|`（λ = 1−e^(−30×0.02) = 0.45）恒成立，所以实际执行的是**未限幅的 `desired − current`**。实测峰值 **220 u/s² = 配置 5 的 44 倍**，一帧内把速度矢量整个翻过去。机制①的小抖动就是被这一级放大成"抽搐"的。

**③ 玩家是物理障碍，流场不认识它** — [CombatRoot.cs:491](Assets/Scripts/Presentation/Root/CombatRoot.cs:491) 已经为"怪↔怪顶住会让速度归零、整群卡成一团"关掉了怪↔怪碰撞，但**怪↔玩家碰撞是开的**（层矩阵全 1，双方都是非 Trigger 的动力学刚体）；而 `NavField` 的阻挡只读 [grid.IsObstacle（地块）](Assets/Scripts/Logic/Grid/NavField.cs:81)，于是流场持续命令敌人往玩家身体里走。顶住后引擎把速度压到零，而 [DetectStuck](Assets/Scripts/Logic/Actor/EnemyLogic.cs:86) 读的是**引擎真值** `Body.velocity` → 连满 10 帧 → `NotifyStuck` → 12 帧"换步"，可换步用的还是那张不认识身体的场 → **顶住/侧移以 22 帧 ≈ 0.44 秒（≈2.3 Hz）为周期交替**。这一环要 Unity 求解器才能复刻，但"速度归零→换步"和代码里已记录的怪↔怪症状是同一件事。顺带：接触伤害走的是 [纯距离判定](Assets/Scripts/Logic/Combat/ContactProbe.cs:83)（`contact_radius = 1`），**不依赖这层物理碰撞**。

**④ 停靠环无滞回 + 刹车滑行 1.2 格** — `StopDistance 0.6`，刹停率 = `moveAcceleration` 5，滑行距离 v²/2a = 1.22 格。静止玩家时角点刹车能把它按在 0.6 上（实测干净）；玩家一折返，敌人就滑行 1.2 格**从玩家身上穿过去**，正好把机制③触发起来。

## 方案

**L0 · 先定位（30 分钟，避免盲改）**：`Navigator.JamCount`、`NavFields.TotalRebuilds` 和 [NavFieldGizmos](Assets/Scripts/Presentation/Diagnostics/NavFieldGizmos.cs:105) 的"场重建 N 次"已经在手。在 `ResolveSteering` 里临时加三个只读计数（模式切换次数、单帧 |Δv|/dt、"上一帧是否 idle"）就能一次分诊：抽搐瞬间 `JamCount` 在涨 → 机制③；模式切换/有效加速度峰值在涨 → 机制①②。（顺带：`TotalRebuilds` 实测 7.9 次/秒 = 玩家跨格率，本身正常。）

**L1 · 只改调参，零编译零导表，SO 热改今天就能对比录像**
- `EnemyTuning.acceleration` 5→12（精英 8→16）：刹停距离 1.22 → 0.51 格，机制④的穿透基本消失。副作用是起步更急、观感更贴人，要你手感判定。
- `stuckFrames` 10→18、`jamFrames` 12→6：假卡死更难触发，真卡死的横向位移减半（压机制③的振幅）。
- `separationWeight` 0.5→0.25、`separationRadius` 0.6→0.45：方向抖动幅度减半。
- 预期：抽搐幅度明显下降但不会消失（①②不动就还在）。

**L2 · 小改代码（每项 3–15 行，都能落成 EditMode 判据）**
1. **方向闸门（收益最大，建议第一个做）**：`EnemyNavigator` 记住上一帧 `desired`，对新 `desired` 做角速率限制（如上限 540°/秒）+ 一阶低通（时间常数 40–60 ms）。它不改任何决策，只把"每帧翻面"变成"划弧"——**单这一项就能把 220 u/s² 的瞬变压回配置量级**，同时覆盖①②④③的所有放大器。
2. **模式滞回**：直线↔阶梯的判定要连续 3 帧同向才切换（现在单帧定夺）。3 行。
3. **固定前视距离的路标**：`waypoint` 从"一步父节点（0.25 格）"改成"沿父指针链累计前进 0.5–0.75 格的插值点"，阶梯模式的方向误差从 mean 6°/max 135° 收敛到近 0。~10 行。
4. **停靠环滞回**：进入 0.6、退出 0.9（在 `EnemyLogic` 里按上一帧意图放宽，`ChaseBrain` 保持无状态）。3 行。
5. **把"被玩家身体顶住"从卡死里摘出去**：`DetectStuck` 加一条"目标在 1 格内不计卡死"，或把判据从"速度≈0"换成"窗口内沿期望方向的净位移 < 0.1 格"。3–8 行，直接消掉机制③的换步抖动。
6. **让流场认识目标身体（根治③）**：给 `NavField.Build` 加一个动态阻挡格参数，把玩家当前格标成阻挡——`ResolveSeed` 的 `SeedRing = 2` 外搜本来就能处理"目标格自己被堵"，敌人会自然地绕到玩家身边而不是往身体里顶。注意只标玩家（不标其他怪，否则每只怪都要一张排除自己的场），且必须排除自己所在格。
7. （可选）分离的 0/1 门改成投影：探针站不住时不返回零向量，把 push 投影到可走半平面，消掉分离量的开关抖动。

**L3 · 结构性（可选，v2）**：把"直线 vs 阶梯"二选一换成连续加权的 context steering——流场只提供走廊吸引力，障碍/同伴/目标提供排斥，从根上不存在"模式"这个概念。

**验收判据（把"看视频"变成"测试会红"）**：现有 [寻路Tests.cs](Assets/Tests/Runtime/Editor/寻路Tests.cs) 的 `NewMaze` + fake physics 夹具正好能跑——脚本化玩家在敌人前方 8 u/s 折返 3 次，断言 ① 相邻帧 `desired` 夹角 > 60° 的次数 ≤ 2；② 单帧 |Δv| ≤ 5 × `moveAcceleration` × dt；③ `JamCount == 0`。改之前我这份复刻读数是 **14–15 次 / 220 u/s²**，正好当红绿分界。

**建议最小落点**：L1 全套（今天）+ L2.1 方向闸门 + L2.5 卡死豁免 + 上面这条验收测试，跑一周手感再决定 L2.2/2.3/2.6。要我把这份方案写进 [待办.md](Docs/待办.md) 或单独开一篇 `Docs/工程/敌人转向抖动.md`，说一声就行。
