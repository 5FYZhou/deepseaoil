# 项目文档精简 · 提示词

> 用法：把「提示词正文」整段发给一个 Agent（或人），它就会按这份规范重写 `Docs/`。
> 「我的验收」一节由发起方执行，**不要**发出去。

---

## 提示词正文（从这里开始复制）

### 角色

你是这个 Unity 项目文档的**删减编辑**。你不写新内容，只做一件事：
把现有 `Docs/` 压缩到"一个刚加入 Game Jam 的程序员，第一次打开仓库，十分钟内能扫完并开始改代码"。

### 读者画像（唯一判据）

- 读者是**临时加入 Jam 的程序员**：写代码，时间以小时计，目标是让游戏能跑、能加一个自己的系统。
- 读者的动作只有四种：**找文件、改数值、加一个状态/面板/事件、避开禁用区**。
- 读者**不会**做：架构评审、技术选型、重构规划、代码考古、性能调优。
- 读者的时间预算：**整份文档 10 分钟**。扫到一个标题下三段还没出现文件名或数值，就跳过了——等于没写。

### 三条不可违背的原则

1. **每条信息必须能落成一个动作**："我该改哪个文件、填什么值、不要碰哪里"。
   落不成的句子一律删掉——不管它多正确。
2. **同一事实只出现一次，出现在最强的地方**。其它文档只留一行链接。
3. **表格和代码块优先于散文**。一个单元格 = 一个命令 / 一个数值 / 一个 `文件:行号`，
   不是一段推导。句子超过 60 字就拆成表行或删掉。

### 必须留下（这类信息就是"逻辑"）

| 类别 | 具体 |
| :-- | :-- |
| 禁令 | 跨层只走 `EventBus<T>` ＋ 两条例外；每帧只有三个驱动入口；三处生成物禁地；`Assets/Resources/**`、`Assets/StreamingAssets/Luban/**`、`Assets/Editor/**`、`Tests/Runtime/Editor/` 末级 `Editor` 不可动；不要装 Luban UPM 包 |
| 依赖方向 | 谁能引用谁（一张表） |
| 帧序 | 四条 Tick 通道；物理帧 `InputBuffer.Push` 必须先于 `PlayerLogic.FixedTick`；渲染帧与物理帧无先后关系 |
| 装配序 | 启动阶段 1 / 2 的动作顺序，两次守卫各防什么 |
| 数值与常量 | 每个常量的名字与当前值；两套配置源（Luban 数值 / SO 角色参数）各自服务什么 |
| 契约 | 转换点唯一（`AssetRegistry.ResolvePath`）；资源 Key 的两种路径语义；`AsyncHandle` 为何必须是 class；状态切换是立即 `Exit → Enter` |
| 缺陷登记 | 全部条目保留。已修的折叠成一行打 ✅；未修的三列：**ID / 现象 / 影响范围**。删掉"修法建议""历史证据链"（行号留一条最短的） |
| 接口 | 对外方法的签名。**不贴实现体的代码副本** |
| 状态机 | 仲裁顺序、7 个状态各自的 `Enter`/`Tick`/`IsDone` |
| 工具准入 | 配表依赖（.NET 8 运行时、Git LFS）、发布闸门是退出码、改路径的表 |

### 一律删掉

| 类别 | 例 |
| :-- | :-- |
| 设计辩护 | "为什么保留 A 而不做 B""收益 / 代价""本可在 X 里加 Y""值得商榷" |
| 演进叙事 | "曾几乎每个文件都带未使用 using""已随重组清理""旧命名空间残留已清" |
| 重构账 | "文本副本已漂移 47 行""旧测试只断言存在""冗余字段""纯冗余分配" |
| 过程废话 | "本节只登记不修复""修与不修是独立决策""按编号单独开工""复验""下列清单" |
| 待验证项 | 整节删除。"待验证"= 没有结论 = 读者无法行动 |
| 元信息 | 写作动机、文档结构自述、置信度标注、适用范围与局限、ADR |
| 重复 | 目录说明里再讲一遍三处生成物；层文档里再列一遍蓝图的契约表 |
| 低价值细节 | 压缩率算法、字符分类、测试内部结构、上游未采纳方案 |

### 密度标尺（硬指标）

行数基准是 `f64bae9`（本提示词写成时的 HEAD），度量方式为 `[IO.File]::ReadAllText(p) -split "\`n"` 的元素数

### 硬约束（破坏一条就算失败）

1. **`Docs/目录说明.md` 的 `## 仓库目录` 一节是机器测过的**：Test Runner 里 `仓库一致性Tests.目录说明与磁盘同源` 会解析这段树、逐个断言真实存在于磁盘。规则：
   - 树放在 ```text 代码块里；**缩进单位恰好 4 字符**（`├── ` / `│   `）；
   - 目录名**结尾必须带 `/`**（不带就当成文件名，其下子项路径会算错）；
   - 名字与右侧注解之间**至少 2 个空格**；
   - 缩进**不得跳级**；解析出的路径数**必须 ≥ 40**；
   - 树里**不得出现磁盘上不存在的路径**（含文件）。
   - 不要删掉整棵树来省行数。
2. **不得改文件名、不得改目录结构**。
3. **不得动** `Docs/表格数据配置/策划指导手册_数据表填写_Docx.docx`、`Docs/表格数据配置/image/*`。
4. **不得改任何代码、测试、配置**。只写 `Docs/` 下的 `.md`。
5. **不得改 `file:line` 行号**：那是验证过的证据。要么原样保留，要么整条证据一起删。
6. 保留原有文档间的相对链接；重命名锚点后同步所有引用。全文搜一遍 `Docs/` 的残留引用。
7. 编码 **UTF-8 无 BOM**，换行 LF。
8. 事实不许走样：数值、常量名、方法签名、异常类型、路径大小写，改一个字都算错。
9. 不确定的**删掉**，不要猜。宁可少写。

### 自检清单（交回前逐条核对）

```powershell
cd <仓库根>
node Tools\verify-mermaid.mjs .   # 改到图时必须 0 FAIL
node Tools\check-tree.mjs .       # 改到目录树时必须 0 FAIL
node Tools\check-links.mjs .      # 必须 0 断链
```

- [ ] 每份文档都在行数上限内
- [ ] `## 仓库目录` 的树格式满足上面 6 条规则（`check-tree.mjs` 全绿）
- [ ] 全文搜 `](` 引用的每个相对路径都真实存在（`check-links.mjs` 全绿）
- [ ] 逐份对照原版：所有常量值、异常类型、方法签名、`file:line` 都没丢也没改
- [ ] 代码块与 ``` 围栏成对闭合
- [ ] 没有"为什么 / 收益 / 代价 / 历史 / 待验证"字样残留
- [ ] 每个表格单元格能回答"改哪个文件、填什么值"

### 交回格式

1. 表格：文件 → 原行数 → 新行数
2. 删除类别清单（按上面「一律删掉」的类别归类，每类举 1 个例子）
3. 你认为是"逻辑"但删掉后可能有人不满意的 3 处，说明理由
4. 你**没能**确认、因此整条删掉的事实

## 我的验收（不要发给 Agent）

子 Agent 交回后逐条复核，命令都能直接跑：

| # | 检查 | 手段 |
| :-- | :-- | :-- |
| 1 | 目录树仍与磁盘同源 | `node Tools\check-tree.mjs .` —— 复跑 `仓库一致性Tests.目录说明与磁盘同源` 的解析逻辑，退出码 0 才算过 |
| 2 | 没有烂链接 | `node Tools\check-links.mjs .` —— 扫全部 `](相对路径)` |
| 3 | 事实未被改坏 | 把 `git show HEAD:<path>` 的旧版与新版分别喂给事实提取器，对比**常量名 / 异常类型 / `file:line` 锚点**三个集合；锚点必须逐条相同 |
| 4 | 密度真的降了 | `git diff --stat`，逐文件核对行数 |
| 5 | 命令自检 | Unity 里跑 EditMode 测试，仍是 14 项 0 失败 |

事实提取器抓的集合（缺一个都算没验）：

- **常量名**：`[A-Z][A-Z0-9]*_[A-Z0-9_]+`，如 `COOLDOWN_SECONDS`、`MAX_CACHE_ENTRIES`
- **异常类型**：`*Exception`
- **`file:line` 锚点**：`*.cs:123` 与 `*.cs:123-145`
- **盘内路径**：`Assets/`、`ConfigWorkspace/`、`Docs/`、`ProjectSettings/` 开头的
- **mermaid 块**：文件:行号 + 图类型，确认没丢图

任何一条不过，**打回子 Agent 重做那一条**，不自己动手改。
