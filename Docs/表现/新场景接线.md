# 新场景接线

## 必备 / 禁止
- 场景需：`GameRoot`、`InputProvider`、`PlayerController`、`CombatRoot`、`TilemapAdapter`、有地板的 Tilemap、主相机。
- 关卡场景需在 `CombatRoot` 同一物体挂 `LevelReader`，并把它接到 `CombatRoot.levelReader`；Inspector 的波次模式（`LevelReader` 的 `_wavePlayMode`）默认 `Sequential`。**场景名必须叫 `Level_<非负整数>`**：`LevelReader.Awake` 解析不出就抛 `InvalidOperationException`（`[Level] 场景名 '…' 无法解析关卡 ID；关卡场景必须使用 'Level_非负整数' 命名（0 = 教学关）。`）；关卡读哪几波由 `level_wave` 表按这个 id 给出。**`Level_0` 是教学关**：它没有 `level_wave` 行，`CombatRoot` 会跳过整个 `LevelLogic`/`CombatDirector` 装配（不刷怪、不结算胜利），收尾由 `StoryFlow` 直接切 `_nextLevelId`。编号契约见 `Docs/工程/关卡编号与场景映射.md`。
- 禁止：`Canvas`、`EventSystem`、第二个 `AudioListener`。UI 由 `UIMgr` 自动创建。
- 敌人**两条路都行**：运行时按波次生成（默认），或直接在场景里摆 `Enemy_<id>` 预制体实例 —— `CombatRoot.AdoptSceneEnemy` 会自动收养，不必手工登记。
- 参考现状：主场景 `Assets/Scenes/Range.unity` = `GameRoot` ＋ `InputProvider` ＋ `BoundsArea` ＋ `SceneFlowConfig` ＋ 六层 Tilemap（`Grid` 下 `Ground` ＋ `InitialSetup` ＋ 四个效果层 `TileEffect_Static` / `TileEffect_Fire` / `TileEffect_Water` / `TileEffect_Steam`），`CombatRoot` 是**场景组件**（`scane_prebs/` 里没有它的预制体，也没有单独的 `Player` 场景物体：它是 `scane_prebs/Player.prefab` 的实例）。`TilemapAdapter` 走 `scane_prebs/TilemapAdapter.prefab` 实例，各层的引用是在场景里**覆盖**上去的。`Fountains` 下是 `WaterWell` / `EarthMound` / `LifeTotem` 三个泉眼预制体实例（`kind` 0/1/2），另有 `Player` / `Virtual Camera` 预制体实例、**十几只手摆的 `Enemy_1` / `Enemy_2`**，以及 `Tree` / `Fence_*` / `Signpost` 等装饰件。

## 1. 场景
- 从 `Assets/Settings/Scenes/URP2DSceneTemplate.unity` 另存。
- **光照不要手搭**：把 `Assets/Prefabs/Environment/[LevelEnvironment_Preset].prefab` 拖进场景，作为**第一个根物体**（内含 `[Environment] ▸ Global Light 2D ＋ Global Volume`，并挂 `EnvironmentDirector` / `TileGridLightmap`）。关卡场景另需 `Assets/Resources/scane_prebs/Weapon.prefab` 实例，放在**最后一个根**；相机勾上 `Post Processing`（部署器会代做）。完整契约见 `全局光照.md` —— 旧说法「全工程零 `Light2D` / 不加光源也能出图」已作废。

## 2. Tilemap
- 建 `Grid`，子物体：`Ground` ＋ 效果层 `TileEffect_Static` / `TileEffect_Fire` / `TileEffect_Water` / `TileEffect_Steam`（按状态分组，每层一张 Tilemap），`InitialSetup` 可选。
- `Ground` 刷 `Tile_Floor`，至少一格。
- `Sorting Order`：`Ground=0`，其余"越压上越大"。`Range.unity` = `InitialSetup 1` / `Static 2` / `Fire 3` / `Water 4` / `Steam 5`；三个 `Slice_*` 沙盒（`Slice_CombatSandbox` / `Slice_GridReaction` / `Slice_PlayerFeel`）都没有 `InitialSetup` 层，效果层 = `Static 1` / `Fire 2` / `Water 3` / `Steam 4`。（`Sandboxes/Level_1` / `Level_2` 是关卡场景，与 `Range` 同构：含 `InitialSetup`，Order 0~5。）
- `InitialSetup` 可选；不画也行。**不建这一层就把 `initialSetupTilemap` 留空**（三个 `Slice_*` 沙盒的 `initialSetupTilemap` 都是 `{fileID: 0}`，也都没有该层）；建了就必须接进去。

## 3. GridView
新建空物体（现网场景里叫 `TilemapAdapter`，也可以直接用 `scane_prebs/TilemapAdapter.prefab`），挂 `TilemapAdapter`：
- `groundTilemap` → Ground（必接）
- `effectLayers`：每行一个 `Tilemap` ＋ 该层负责的 `States`（同一状态只能登记在一层；一层都不接时状态只记逻辑、不显示）
- `fallbackEffectTilemap`：没在任何 `effectLayers` 行登记的状态落到这一层，留空 = 取 `effectLayers[0]`
- `initialSetupTilemap` → InitialSetup（可选）
- `stateTiles`：**保持空数组**（`Range` / `Slice_CombatSandbox` / `Slice_GridReaction` 三个接了 `TilemapAdapter` 的场景现在全是 `stateTiles: []`），状态贴图自动走约定路径 `Assets/Resources/tiles/Tile_<TileStateType 成员名>.asset`（**顶层，别建子目录**）
- `overlayDirector` / `obstacleDirector` 可以留空：`Attach` 会在本节点自愈 `GetComponent` → `AddComponent`
- `effectLayers` 的任一行都不能指向 `groundTilemap` / `initialSetupTilemap`，`fallbackEffectTilemap` 同理 —— 这几条在 `Awake` / `OnValidate` 打 LogError。

## 4. BoundsArea（可选）
- `BoxCollider2D`：`Is Trigger ✓`，`Size` = 可走区域（`Range.unity` 是 `60 × 30`）。

## 5. 玩家
层级：
```text
Player
├── View
└── ShadowView        ← 脚底影子，Sorting Order 310（RenderOrder.GroundShadow）
```

`Player` 根：
- `Rigidbody2D`：Gravity Scale 0；Freeze Rotation Z；Interpolate；Collision Detection = `Continuous`（`Player.prefab` 与 `Enemy_1.prefab` 现在都是 `Continuous`，见《美术装配指南》§5.1）
- `BoxCollider2D`：Size (0.7, 0.5)，非 Trigger
- `PlayerMotor`：`body` 留空（`Player.prefab` 上就是 `{fileID: 0}`，运行期自愈）
- `PlayerController`：`motor` = 自身 PlayerMotor；`inputProvider` = InputProvider；`aimCamera` 可空；`boundsArea` = BoundsArea；`animView` = View 上的 ActorAnimationView
- `YSortAgent`：`layers` 只放 View 的 `SpriteRenderer`（`Offset = 0`），`ShadowView` 不要放

`View`：
- `localPosition` / Rotation 归零
- `SpriteRenderer`：任意色块（基准件挂 `M_SpriteFlash`，见《美术装配指南》§5.1）
- `Animator`：可留空
- `ActorAnimationView`：`animator` / `spriteRenderer` 可留空；`useFlipX` 不勾
- `SpriteRenderer` 必须挂 `View`，不能挂 `Player` 根。

## 6. InputProvider 与 GameRoot
各建空物体，分别挂 `InputProvider`、`GameRoot`，无字段（两者都没有任何 `[SerializeField]`）。

## 7. CombatRoot 与 Fountain
`CombatRoot`：
- `player` = PlayerController（必接）
- `gridView` = TilemapAdapter（必接）
- `levelReader` = LevelReader（关卡场景必接，不接只报 `CombatRoot 未接入 LevelReader；关卡流程与波次刷怪不会装配。`）
- `ballRoot` / `actorRoot` / `fountains` / `spawnCamera` 可空
- `enableLevel ✓`（关掉可以只验投掷链路）、`enablePlayerRespawn`（默认关）

`Fountain`：
- `CircleCollider2D`：`Is Trigger ✓`，Radius 3
- `spawnInterval` 1
- `landingRadius` 3 / `minLandingDistance` 0.8 / `autoTriggerRadius` 1.5

## 8. Cinemachine（可选）
- 主相机加 `Cinemachine Brain`（`Range.unity` 的 `Main Camera` 上就有，`Update Method` = SmartUpdate）；建 `2D Camera`。
- vcam：`Follow` = Player 根；`Look At` 空；`Orthographic Size` 8；`Camera Distance` 10；`Damping` —— `Assets/Resources/scane_prebs/Virtual Camera.prefab` 的现状是 **`m_XDamping` 0.5 / `m_YDamping` 0.5 / `m_ZDamping` 1**（`Slice_PlayerFeel` 场景里那个实例被改成了 1 / 1，即几乎不阻尼）；`Aim` = Do nothing；Brain `Update Method` = SmartUpdate。
- 可选：`CinemachineConfiner` + `Confine Mode = Confine 2D` + `Confine Screen Edges ✓`（`Virtual Camera.prefab` 里没有挂 Confiner，由各场景覆盖）。
  - `Bounding Shape 2D` **必须**指向 `PolygonCollider2D` / `CompositeCollider2D`：指 `BoxCollider2D` 时 Cinemachine 只抛 `Must be a PolygonCollider2D or CompositeCollider2D.`、相机完全不限制，属静默失效。
  - 现成做法：关卡场景的 `BoundsArea` 直接用 `Assets/Resources/scane_prebs/BoundsArea.prefab` 的实例（内含 `BoxCollider2D` 60×30 与与之匹配的 `PolygonCollider2D`，两者都 `Is Trigger ✓`）——`CombatRoot.player.boundsArea` 指该实例的 `BoxCollider2D`，vcam 的 `Bounding Shape 2D` 指同一实例的 `PolygonCollider2D`。`Level_0..Level_5` / `Level_Template` / `Range` 现状如此。
  - 要非 60×30 的活动区，改实例的 `Transform.LocalScale`（两个碰撞体一起缩放、形状永远一致；`Level_2` 即 42.8×27.7 ⇒ scale 0.713333 / 0.923333）。**不要**只改其中一个碰撞体或手改 polygon 点，那正是形状失配的来源。

## 启动验收
Play 后 Console 应该**没有红色 `LogError`**（本工程没有"装配成功"日志）：
```text
（装配正常时 Console 干净；装配失败会打 `CombatRoot … 战斗内容已停用。` 之类的 LogError。）
```
- 菜单态点 `BeginPanel` 的 `BtnStart` 开始；玩法 HUD **不由按钮开** —— 新场景装配时 `CombatRoot.Assemble` 调 `UIMgr.EnterGameplayUi()`（`HudPanel` + `GamePlayPanel`，幂等），所以直接 Play 战斗场景也有 HUD。
- WASD 移动、Shift 冲刺、左键水球、右键土球、`E` 播种。
- 检查：Player 下只有 View 且 localPosition=(0,0,0)；Player 根无 SpriteRenderer / Animator；ActorAnimationView 在 View；`useFlipX` 未勾；相机 Follow 拖 Root；第一个根是 `[LevelEnvironment_Preset]`、最后一个根是 `Weapon`（§1）；`effectLayers` 各行不指向 `groundTilemap` / `initialSetupTilemap`。

## 关卡结算
- `LevelLogic` 进入胜利或失败终态后发布 `LevelStateChanged` 与 `LevelEnded { curId, nextId }`；前者只传递状态，后者只传递关卡 ID。`SettlePanel` 自己订阅这两个事件（不经过 `CombatRoot`），收到终结事件后更新结果、`ImgRoot` 淡入；淡入期间 `CanvasGroup.interactable / blocksRaycasts` 都是关的，所以按钮在淡入完成前不可交互。
- 按钮分工：`BtnNextLevel` 进入 `Level_<nextId>`（**只在胜利时有意义**，`_nextLevelId` 在胜利分支才被赋值）；`BtnRestart` **永远是重载当前场景**（`SceneManager.GetActiveScene().name`）；`BtnReturnMenu` 返回开始场景。失败终态不会自动复活并清空关卡状态。
- 三个按钮都会先过 `Application.CanStreamedLevelBeLoaded`：目标场景没进 Build Settings 就打 `[Level] 场景 '…' 不存在或未加入 Build Settings，无法切换场景。` —— 当前 Build Settings 里是 `Begin` 与 `Levels/Level_0..Level_5`。
- 因此当前场景、下一关场景和开始场景都必须启用在 Build Settings 中；下一关场景文件名必须符合 `Level_<ID>` 约定。
- CG 仍仅保留 `CGType` 接口（`Data/Config/CGType.cs`，成员 `None` / `Start`），不播放开场或结束过场；`LevelState` 只有 `NotStarted` / `Running` / `Victory` / `Defeat` 四个成员，没有 CG 态。
