# 粒子特效系统

一次 `EffectModule.Play(EffectId, EffectContext)` 播一次特效；资源在哪、池多大、何时回收、失败怎么办，调用方都不用管。代码在 `Assets/Scripts/Presentation/Effects/`（驱动在 `Drivers/`），测试在 `Assets/Tests/Runtime/Editor/粒子特效Tests.cs`。

## 1. 前置：谁把它装配起来

`EffectModule.Init` / `Preload` **只由 `GameRoot.Awake` 调**（不是自动的 MonoBehaviour），顺序 `AssetModule.Init` → `EffectModule.Init` → `Preload`；`Dispose` 必须早于 `AssetModule.Dispose`。**场景里没有 `GameRoot` 就没有特效**，`Play` 只会打一条 `[Effect] EffectModule.Play 在 Init 之前被调用。` 并返回 `None`。

| 场景 | `GameRoot` | 结论 |
| :-- | :-- | :-- |
| `Range.unity`（**主场景**） | 有 | 可进 Play 验碎片与瞄准高亮 |
| `Empty.unity`（空白件） | 无 | 直接 `Play` 只有一条 Error，没有特效 |

补装配：Hierarchy → Create Empty → 命名 `GameRoot` → Add Component → `Game Root`，**没有任何要拖的字段**。副作用是这个场景会一并初始化 Config / Asset / Pause / Save（幂等）。

`EffectDebugPanel` **已随死代码清理删除**（`Presentation/Diagnostics/` 里只有 `CombatDummyHarness` / `GridReactionHarness` / `HarnessGui` / `MovementDebugPanel`，没有这个件）。验播放走 §5 的战斗路径，或跑 `Assets/Tests/Runtime/Editor/粒子特效Tests.cs`（17 条）。

## 2. 建一个特效预制体

1. 放 `Assets/Resources/effects/`（**小写**，与 `EffectCatalog.KeyPrefix` 一致）。
2. 右键 **Effects → Particle System**，改名 **= 枚举名**（`Assets/Resources/effects/` 现有 7 份：`BurstSparks` / `ChainShock` / `DamagePopup` / `Dust` / `FlameEmbers` / `MudSplash` / `SteamBlast` —— 对应 `Specs` 里 6 行 `Particle` ＋ 1 行 `Popup`）。
3. 按下表设置（`Looping` / `Play On Awake` / `Stop Action` / URP 材质四项是硬要求，其余是观感）。
4. 从 Hierarchy 拖进 `Assets/Resources/effects/`，删掉场景里那个临时对象。

| 模块 | 项 | 值 | 为什么 |
| :-- | :-- | :-- | :-- |
| Main | Looping | **关** | 开着永不结束（`EstimateDuration` 直接返回 +∞），只能等 `+5s` 硬超时被强杀 ＋ 警告 |
| Main | Play On Awake | **关** | 池对象借出时会 `SetActive(true)`，开着会自己先播一次（双份粒子） |
| Main | Simulation Space | **World** | 对象是复用的，`Local` 会把上一轮粒子拖着走 |
| Main | **Stop Action** | **None** | 设成 `Disable` / `Destroy` 会让对象自己禁用或销毁 ⇒ **池拿到死对象，第二次播放起永久失效** |
| Emission | Rate over Time / Bursts | **0** / Time 0，Count 12~20 | 一次性爆发；数量太少会显得"几粒豆子" |
| **Renderer** | **Material → Shader** | **`Universal Render Pipeline/Particles/Unlit`** | ⚠️ 默认材质是 Built-in 的 `Particles/Standard Unlit`，URP 下渲染成**粉紫色** |
| Renderer | Sorting Layer / Order | 与目标同层、Order 调高 | Y 排序频带是 `RenderOrder.YSortBandStart=400` ~ `YSortBandEnd=1000`（`Presentation/Visual/RenderOrder.cs`） |

- **文件名逐字符等于枚举名**：Key 是 `effects/<枚举名>`。Windows 上大小写写错**可能侥幸加载成功**，打包到 Android / iOS 必失败。
- **程序生成的驱动不需要预制体**：`Shatter`（碎片用 `PrimitiveSprites.Circle` ＋ 确定性扇形，不读随机数）与 `Highlight`（整格方块 `PrimitiveSprites.Square`）。别去找 `effects/Shatter.prefab` —— 不存在，也不需要。
- **同一 `EffectId` 只尝试加载一次**：缺失会记进 `EffectModule._missing`，之后 `Play` 直接 `None`，两条 Error 各只出现一次。修好预制体要重进 Play。
- 复合预制体（父物体 ＋ 子粒子系统）支持；一个 `ParticleSystem` 都没有时打一次 Error 并把对象**还回池**。
- 判定路径对不对的快捷方式：改名预制体后进 Play，Console 会给出期望路径（`[Effect] 特效资源缺失：… → 期望 Assets/Resources/effects/….prefab。`）。

## 3. 尺寸与观感调参

"特效看起来很大 / 很小"要分清是哪个量在起作用——它们是三件独立的事：

| 量 | 管什么 | 注意 |
| :-- | :-- | :-- |
| `Start Size` | **每个粒子**多大 | 作者值就是基准，`At` 系列给 `Value = 1` 时与预制体逐位一致 |
| `Start Speed` × `Start Lifetime` | **这一团**铺多远 | 最常见的"为什么这么大"来源 |
| `Shape`（半径 / 角度） | 出生点散布范围 | Sphere 默认半径 **1**，等于"粒子从 1 单位外开始飞" |

**本项目的尺度参照**（战斗切片）：投掷落地冲量半径 `1.2`、球半径 `0.22`（`Resources/tuning/ThrowTuning.asset`）；敌方单位直径 ≈ `0.9`（判定半径 0.45，`Resources/tuning/EnemyTuning.asset`）；相机正交半高 `8`（`Range.unity` 的 `Main Camera`，`orthographic size: 8`）。

**量纲参照案例**："`Start Size` 设好了还是很大"这种观感，先查序列化数据确认 `Start Size` 是否真被覆盖 —— 真凶常是 `Start Speed 20 × Start Lifetime 0.2 = 4 世界单位`（相机半高 8 ⇒ 视野高 16，这一团铺掉 1/4 屏），再叠加 `Shape = Sphere` 的默认半径 1。修法在内容侧：`Start Speed` 降到 3~5、`Shape` 半径 0.05~0.2、Burst Count 提到 12~20，需要"飞出去但别飞远"时加 `Limit Velocity over Lifetime`（Drag 0.5~0.9）。

## 4. 在代码里播一次

```csharp
// 一次性：位置 ＋ 方向 ＋ 颜色（EnemyActor.Die 的真实写法；播哪个特效由预制体上的 deathEffect 给，代码不写死）
EffectContext ctx = EffectContext.At(Position, hitDirection);
ctx.Tint = ConfigModule.Visuals.enemyBodyNormal;
EffectModule.Play(deathEffect, in ctx);

// 持续型：一次 Play ＋ 每帧 Update，不瞄了 Stop（TileHighlightView 的真实写法）
if (_handle.IsValid && EffectModule.Update(_handle, in ctx)) return;   // 已在播 → 只更新
_handle = EffectModule.Play(EffectId.Highlight, in ctx);               // 句柄失效 → 重建
...
EffectModule.Stop(_handle);
```

| 项 | 契约 |
| :-- | :-- |
| 返回值 | `EffectHandle`；**失败一律 `EffectHandle.None`（全零），永不抛异常**，不关心可以忽略 |
| `EffectId.None` | 静默返回 `None`（不查表、不报错）：写它表示"这次不播"，与"未注册"不是一回事 |
| `EffectContext` | 纯数据 `struct`；`At` / `At(dir)` / `OnTarget` 三个工厂都给 `Value = 1` = 按预制体原样播 |
| 手写部分字段 | 安全：`Direction` 零向量 → `up`、`Tint` alpha 0 → 白。⚠️ **`Value` 与 `Modulation` 读时都不归一化**（原值直传，上下限由各驱动自持）；⚠️ **只有 `Duration` 不归一化**（`≤ 0` = 用驱动自己的默认时长）；⚠️ **`Value` 不显式赋值就是 0**（要满强度用 `At(...)` 或自己写 `Value = 1`） |
| `Value` | 主数值，`EffectModule` 只传递、语义由驱动解释：`ParticleDriver` 写的是 `粒子量与大小 = 作者值 × Lerp(0.4, 1, Clamp01(Value))`（**只做相对缩放，绝不覆盖作者值**）；各驱动自持上下限 —— `ScreenShake` 夹 `[0,1]`、`ScalePunch` 夹 `[0,1]`、`Shatter` / `Highlight` 取 `max(Value, 1e-3)`、`Hop` 拒收 `NaN` / 无穷 / `≤ 0`、`Popup` 取 `RoundToInt(Value)` |
| `Modulation` | `Vector2`，语义按驱动：`ScalePunchDriver` 读 `X` = 压扁比（夹 `[0.05,3]`）、`Y` = 回弹曲线指数（夹 `[0.25,8]`）；其余驱动不读 |
| `Tint` / `Value` / `Duration` | 只有把它们当参数的驱动才读：`Shatter` 读 `Tint`（身体色）与 `Duration`（默认 0.35 s、上限 5 s）、缩放读 `Value`；`Highlight` 读 `Tint` 与 `Value`（边长 = `Value × 2`）。`ParticleDriver` 只读 `Value`（颜色与时长都在预制体里） |
| 持续型 | `EffectModule.Update(handle, ctx)` 只更新位置 / 颜色 / 半径，返回值只代表"句柄有效"；**不要每帧 `Play`**（那等于每帧新建一个实例） |
| 跟随 | `Anchor` 非空时每帧挪到目标上；目标被销毁（Unity 假 null）即自动回收 |
| 调用频率 | 一次性特效每次落地 / 命中各一次即可；`SteamBlast`（`CombatRoot.OnGridBlastOccurred`，落地冲击 `impact_radius > 1` 且结果地块为 `Steam`）、`BurstSparks`（`EnemyActor.TakeDamage` 的受击火花）、`DamagePopup`（同处，伤害飘字）**有**自动调用点；`MudSplash` 目前**没有调用点**（`EffectCatalog.Specs` 登记了、`EffectModule.PreloadList` 含它、`prewarm: 4`，见 `Docs/待办.md`） |

## 6. 排错速查

| 症状 | 最可能原因 | 处置 |
| :-- | :-- | :-- |
| `EffectModule.Play 在 Init 之前被调用。` / 面板显示 `未 Init` | 场景里没有 `GameRoot` | §1 |
| `特效资源缺失：X → 期望 Assets/Resources/effects/X.prefab` | 目录不是 `effects`、文件名 ≠ 枚举名、不在 `Resources` 下 | 照期望路径逐字符核对 |
| 粒子是**粉紫色方块** | 材质用了 Built-in shader | Renderer → Material → Shader 改 `Universal Render Pipeline/Particles/Unlit` |
| 第一次正常、之后再也出不来 | 预制体 `Stop Action` = `Disable` / `Destroy` | 改 **None** |
| 每次播放**双份**粒子 | `Play On Awake` 开着 | 关掉 |
| 粒子跟着球或玩家跑 | `Simulation Space` = `Local` | 改 **World** |
| 粒子被地面挡住 / 盖住敌人 | Sorting Layer / Order | 提到前景层、调高 Order |
| "`Start Size` 设好了却还是很大" | 先分清是"每个点大"还是"这一团铺得远" | §3 |
| `池已满` 刷屏 | 同屏实例超过 `EffectCatalog` 的上限 | 调大 `maxSize`（警告已 1 秒节流，文案带累计丢弃次数） |
| 池内待用数远少于 12（开局） | 有预制体没加载成功 | 看 Console 的 `[Asset] load failed` 行 |
| `播放 Shatter` 只飞出 1~2 块碎片 | 上一批碎片没还回来（碎片池上限 = `maxSize × 3`） | 等 5 s 或调大 `maxSize`；Console 会写 `碎片池已满（上限 48），本次少飞 N 块` |
| 找 `ScreenShake` / `Flash` / `SlowTint` 的驱动 | 三者已实现（相机挂件 + 材质属性块 + 写渲染器色） | 见 `Drivers/CameraShaker.cs`、`Drivers/ScreenShakeDriver.cs`、`Drivers/ActorTintDriver.cs` |
| 调了 `ScreenShake` 的 `Value` 却没有任何震感 | `ScreenShakeDriver` 自己写的是 `Clamp01(ctx.Value)`，塞原始半径/伤害量会被拍成恒定满档（`EffectContext` 读时不再归一）；且相机不存在时驱动直接返回 `None` | 把物理量先线性映射到 0..1；确认场景里有 `MainCamera` 标签的相机 |
| 震屏把相机顶到奇怪的位置 / 越抖越远 | 相机偏移写在了 `Tick`（Update 通道）里，被相机系统在 `LateUpdate` 覆盖或与自身叠加 | 施加点必须在 `LateUpdate`，且每帧开头把上一帧偏移摘掉（照 `CameraShaker` 的写法） |
| 实体**通体染成某个颜色**（美术原画被套上一层滤镜） | 有第二个写者往同一个 `SpriteRenderer.color` 上刷**有色乘数**：该字段是**顶点色乘数**，写 `(1,1,1,1)` 才是 100% 美术原色 | 颜色只走 §8 的两条通道；中性件必须写 `Color.white`，有色件只在减速这类持续态里出现 |
| 受击闪白看不见 / 闪一下就掉 | ① 真身渲染器上没挂 `M_SpriteFlash`，退化成乘法闪白；② 底色方在同一帧或下一帧把颜色拍回去了 | ① 按 §8 挂材质；② 底色方不再写颜色；给对 `Anchor`（实体根即可，驱动会下探到真身渲染器） |
| 闪白了，但**黑发 / 暗色衣服还是不白** | 走的是 `color` 乘法回退（乘法法则下深色 × 纯白 = 深色） | 把 `Resources/materials/M_SpriteFlash.mat` 挂到真身 `SpriteRenderer` 的 `Materials[0]` |
| 闪白是**一整块纯白剪影**（眼睛、花纹一起白掉），且淡出后不回原画 | 材质通道没采到精灵贴图：`_MainTex` 空着，Shader 落到默认值 `"white"` | 贴图由 `ActorTintDriver.EnsureSpriteTexture` 钉进 `renderer.material`；别给 `_MainTex` 加回 `[PerRendererData]`，那等于把这份数据让回给渲染器、又被属性块顶掉 |
| **进战斗第一个挨打的角色就一直纯白** | 共享材质上的 `_FlashAmount` 残留了满值 | 驱动已在 `CleanAll` 把属性块压 0；若手改了驱动，务必保留这一步 |

## 7. 加一个新特效

**粒子型（三处，顺序固定）**

| # | 改哪 | 内容 |
| --: | :-- | :-- |
| ① | `Effects/EffectId.cs` | 加一枚枚举值（`None = 0` 不许动） |
| ② | `Effects/EffectCatalog.cs` 的 `Specs` | 加一行 `new EffectSpec(EffectId.X, maxSize: …, prewarm: …)`（`DriverKind` 默认 `Particle`；`maxSize ≤ 0` 按 1 处理，`prewarm` 截断到 `maxSize`） |
| ③ | 美术内容 | `Assets/Resources/effects/X.prefab`（文件名 = 枚举名） |

可选：加进 `EffectModule.PreloadList` → 开局零延迟（不加则首次 `Play` 走异步懒加载，**首次那一下拿不到**，资源到位后自动补播）。

**只有粒子型与 `Popup` 需要预制体**：`Flash` / `ScreenShake` / `Tint`（`SlowTint`）/ `ScalePunch`（`Squash`）/ `Shatter` / `Highlight` / `Hop`（Z-Hop 伪高度）这些程序型驱动**不读 `Assets/Resources/effects/`**，没有也不需要 `.prefab`；`DriverKind = Particle` 与 `DriverKind = Popup` 才要建文件 —— `Popup` 要的是根节点挂 `PopupView` 的世界空间弹窗。

**非粒子型（闪白 / 抖动 / 震屏 / 程序生成形状）——四步**：① 枚举加一项；② `EffectCatalog.cs` 的 `EffectDriverKind` 加一种；③ `Specs` 加一行写上新的 `DriverKind`；④ 在 `Drivers/` 写 `public sealed class X : IEffectDriver` 并在 `EffectDriverFactory.Create` 的分派里加一个 `case`。`EffectModule` 一行都不用改。现有两种写法可照抄：不碰资源的照 `Drivers/HopDriver.cs`（`Hop = 8`），要预制体的照 `Drivers/PopupDriver.cs`（`Popup = 7`，配 `Visual/PopupView.cs`）；`EffectDriverKind` 现为 `Particle = 0`（也是 `default` 落点）/ `Shatter` / `Highlight` / `Flash` / `ScreenShake` / `Tint` / `ScalePunch` / `Popup = 7` / `Hop = 8`。

只做枚举不加装配行的可见形态：`Play` 打一条 `[Effect] EffectId X 未注册：EffectCatalog 里没有这一行。` ＋ 返回 `None`。

**程序生成的驱动**：`AssetKey` 返回**空串** ＋ `IsAssetReady` 恒 `true` ⇒ 完全不碰 `AssetModule`（也不会因为"没有同名预制体"被判缺失、不进 `PreloadList`）。代价是 `EffectSpec.Key` 永远非空，所以这类驱动的构造函数必须**忽略 `spec.Key`**（照 `Drivers/HopDriver.cs` / `Drivers/ScalePunchDriver.cs`；要预制体的 `Drivers/PopupDriver.cs` 不属于这一类，它读的就是 `spec.Key`）。

**持续型多一处**：实现类覆写 `IEffectDriver.UpdateInstance`（默认实现是空的 → 不支持的驱动是 no-op，不报错），调用方一次 `Play` ＋ 每帧 `Update`。

**排序档位**：碎片用 `RenderOrder.ShatterPiece = 1200`（"这帧发生了什么"的最高优先级读数，必须盖住站在同一格上的人）；瞄准高亮用 `RenderOrder.Aim = 320`（贴地，压着格效果但被站在那一格上的人盖住）。

## 8. 实体颜色：单写者 + 双通道（`ActorTintDriver`）

实体身上有**两条互不干涉的颜色通道**，全部由 `Drivers/ActorTintDriver.cs`（`EffectDriverKind.Tint`）独占，谁都不许再直接写 `.color`：

| 通道 | 谁在用 | 载体 | 为什么 |
| :-- | :-- | :-- | :-- |
| **瞬态（闪白 / 闪红）** | `EffectId.Flash` | 挂了 `M_SpriteFlash` → `MaterialPropertyBlock` 的 `_FlashAmount`（0→1→0 线性淡出）；没挂 → `color` 写满白（乘满，整段瞬态不回渐变） | `SpriteRenderer.color` 是**顶点色乘数**：深色像素 × 纯白 = 深色，**乘法法则下永远闪不出纯白剪影**，只能靠片元向 `_FlashColor` 插值 |
| **持续态（减速垫色）** | `EffectId.SlowTint` | `SpriteRenderer.color = 持续态 × 基线` | 变暗变冷正是乘法的强项 |
| **贴图** | 只在挂了材质时 | `renderer.material._MainTex = renderer.sprite.texture` | 见下，材质那格**留空是刻意的** |

```text
  挂材质的角色：color = 持续态 × 基线（原画）      rgb = lerp( rgb, _FlashColor, _FlashAmount )
  没挂材质的：  color = 闪白期间恒为满白，到点还原持续态 × 基线    _FlashAmount 由 Tick 线性拉回 0
```

**乘法回退必须真的写 `color`，而且只能是"写满白 + 到点还原"**：`ApplyFlash` 在没有 `_FlashAmount` 时若直接 `return`，就再没有任何一行会把颜色推上去（`ApplyPersistentTint` 又因为 `FlashRemaining > 0` 而拒绝写白）——两边互相等待，闪白彻底消失。反过来，乘法**拉不出渐变**：`Color.white` 已是乘法的上限，照 `amount` 插值只会让 0.12 s 里颜色一路往下掉，看不出闪白。所以回退路上瞬态是一个**持续态**（`amount > 0` 恒写满白，到点才由 `ApplyPersistentTint` 还原），`N1` 用例守的就是这两条。

**要闪白，先挂材质**：Shader 是 `DeepseaOil/2D/SpriteFlash`（`Resources/materials/Shaders/SpriteFlash.shader`），材质是 **`Resources/materials/M_SpriteFlash.mat`** —— 把它挂到角色**真身** `SpriteRenderer` 的 `Materials[0]`（`Enemy_1.prefab` 的 `View`、`Player.prefab` 的玩家渲染器；脚底 `ShadowView` **不要**挂）。驱动在首次抓到渲染器时只读一次 `sharedMaterial.HasProperty("_FlashAmount")` 探测能力：

- **挂了** → 走材质插值，真·纯白剪影（黑发、暗色衣服也白）。
- **没挂** → 退化成 `color` 乘法闪白：整段瞬态写满白（深色区域不会变白），到点还原持续态 / 基线，**不报错、不静默消失**。

**贴图由驱动钉，不要自己往材质里填**：`.mat` 的 `_MainTex` 刻意留空 —— `SpriteRenderer` 交给渲染器的精灵贴图属于「逐渲染器属性」，我们的 `_FlashAmount` 属性块一写就把那一份顶掉，Shader 会落到 `Properties` 里的默认值 `"white"`，闪白就变成**一整块纯白剪影**（连眼睛、花纹一起白掉）且**淡出后也不恢复**（画出来的东西本来就与贴图无关）。`ActorTintDriver.EnsureSpriteTexture` 因此把 `renderer.sprite.texture` 显式写进 `renderer.material`（逐实例克隆，动的是自己那一份；逐帧只比较一次引用，动画换图集才换）。Shader 侧对应地按 URP 官方 sprite shader 写法：`TEXTURE2D/SAMPLER` 宏 ＋ `_MainTex_ST` ＋ `TRANSFORM_TEX`，且**不带** `[PerRendererData]`（带了等于把这条通道让给渲染器，见上）。

| 项 | 契约 |
| :-- | :-- |
| `EffectId.Flash` | 瞬态，最高优先级。`ctx.Tint` 给色（`Color.white` = 闪白，换成红色即闪红），`Duration ≤ 0` 时取默认 **0.12 s**；`Tint` 的 alpha 为 0 会被读成白色（所以底色的白用 `Color.white`，别用 `default(Color)`） |
| `EffectId.SlowTint` | 持续态，垫在瞬态下面。**实体自己持句柄**（`EffectHandle`）并在状态解除时 `EffectModule.Stop(handle)`；只在跨阶时发一次。**重复 `Play` 且 `Tint` 不变时复用同一个句柄**（发新句柄会让调用方手里那个永远 `Stop` 不掉）；换了颜色才发新句柄 |
| 基线 | 首次抓到渲染器时捕获**它当时的颜色**，故美术在预制体上给身体上的色不会被 `CleanAll` 洗掉；`Stop` 与 `CleanAll` 都还原到基线 |
| 目标解析 | `ctx.Anchor` 自己有 `SpriteRenderer` 就用它（指向渲染器节点最快），否则下探子树并**跳过名字含 `Shadow` 的节点**（脚底 `ShadowView` 不能跟着变白）；抓不到 → `None` 静默不播 |
| 打回基线 | 目标销毁假 null 由 `Tick` 摘账；`EffectModule.CleanAll`（切场景）把在场渲染器全部还原成基线，并把属性块的 `_FlashAmount` 压回 0 —— **共享材质上残留满值会让下一个用同材质的角色永久纯白** |
| 解除耦合 | 实体侧不再需要时间戳守卫：闪白走属性块、减速垫色走 color，两条路各自独立，`Stop` 也掐不掉正在跑的闪白 |
| 性能 | 闪白强度与颜色写的是**属性块**（不克隆材质）；只有**贴图**那一格写 `renderer.material`（逐渲染器克隆一份，缓存后仅在第 1 帧与换图集时触发）。代价：角色精灵与图块分属不同材质，会各走各的批次 |
