## 2. 范围

### 2.1 要做

**玩家移动**

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| M1 | 键盘输入 | 用新输入系统。`UnityEngine.Input` 是禁用的 |
| M2 | 刚体速度驱动 | 位移由物理刚体速度产生，不是直接改 `transform` |
| M3 | 脚底碰撞体 | 碰撞体位于角色脚下，与场景障碍物发生**物理阻挡** |
| M4 | 无惯性 | 松手当帧停；反向当帧即走。不要加速/滑行曲线 |
| M5 | 边界限制 | 玩家不能离开地图活动区域 |
| M6 | 八方向 | 上/下/左/右 + 四个斜向；斜向速度不得快于直向 |
| M7 | 无重力、无平台跳跃 | 俯视角不存在"落地"，跳跃键不在本次范围 |

**相机跟随**

| # | 要求 | 说明 |
| :-- | :-- | :-- |
| C1 | 正交视角 | 不用透视 |
| C2 | 平滑跟随 | 跟随玩家，不允许硬贴（相机不能是玩家的子物体） |
| C3 | **极小死区** | 玩家在画面中心附近的小范围内移动时相机不动，超出才开始跟 |
| C4 | 地图边界限制 | 相机视野不得越过地图边界 |
| C5 | 必须用 Cinemachine | 指定技术选型，不是可选项 |

### 2.2 明确不做

- **树叶半透明遮挡**（原话：暂不处理）
- 其它**任何**系统：敌人、AI、战斗、技能、buff、掉落、音效、存档、关卡、UI 流程
- 碰撞体之间除了"挡住"以外的任何交互

## 3. 硬约束：框架必须留着

原话：

> 假如策划要改需求，那么旧框架才有作用，注意现在只是草案！不是定稿

> 你把分层状态机删了，连给怪物上 buff 都做不到

拆分出来的含义：

| # | 约束 |
| :-- | :-- |
| F1 | 需求是**草案**。后续必然要加（敌人、AI、buff、状态、外力），代码不能按"一次性用完就扔"写 |
| F2 | 分层状态机**必须保留**。它是给未来的敌人 / buff / 状态扩展用的 |
| F3 | 只允许删除**设计上确实不再需要**的具体状态或代码，**不得**顺手拆掉框架骨架 |
| F4 | 框架的存在意义 = 需求变更时不用重写。这是验收标准之一，不是风格偏好 |

**KISS 的正确适用范围**（原话修正）：

> 保持 KISS 原则是实现的时候 KISS，不是让你把本就健壮可拓展的框架改成 KISS

即：**实现可以简单，框架不许被简化掉。**「简单」不能成为删架构的理由。

## 4. 外力接口（预留，当前不调用）

原话：

> 或者 ApplyGravity 改造成 ApplyExtraForce 接收外力作用，用于未来可能的拓展功能，现在可能不会被调用使用

| # | 要求 |
| :-- | :-- |
| E1 | 把原本的**重力**施加点，改造成**通用外力**施加点 |
| E2 | 它接收的是"一个力"，不绑定重力的语义——浮力、水流、吸附、击退滑行都应该是同一个入口的不同取值 |
| E3 | **本次可能不会被调用**，这是预期状态，不是未完成 |
| E4 | 敌人、buff、道具后续会用到它。因此"现在没人调所以删掉"是错的 |

## 8. 给复核 Agent 的清单

按需求逐条验，不要按现有实现的注释验：

| # | 复核点 | 判定依据 |
| :-- | :-- | :-- |
| R1 | 逻辑层是否真的没有引擎依赖 | 决策代码里不应出现 `MonoBehaviour`、`Update`/`FixedUpdate`、`UnityEngine.Time` |
| R2 | 速度是否只有一个写者 | 同时有两处写同一个刚体速度 = 缺陷（会互相覆盖） |
| R3 | 边界是否只有一个真值来源 | 玩家钳位与相机边界**必须**来自同一份地图数据，否则两者会不一致 |
| R4 | 无惯性是否当帧成立 | 松手那一帧速度必须归零，不能靠阻尼衰减 |
| R5 | 八方向斜向是否限速 | 斜向速度 = 直向速度（不是 ×1.414） |
| R6 | 输入采样点是否唯一 | 按键按下沿只能有一个存储点，宿主不许自存"上一帧输入" |
| R7 | 暂停时行为是否自洽 | 暂停后恢复，不应有暂停期间的按键"穿透"到恢复后 |
| R8 | 状态机是否仍是可扩展的骨架 | 加一个新状态是否只需要动"状态 + 标签 + 注册"三处 |
| R9 | §4 的外力入口是否语义干净 | 它不应该自带任何具体力的语义，也不该被自动调用 |
| R10 | §3 的框架是否被削 | 对照 F1–F4：有没有把"草案期不该删的东西"删了 |
| R11 | 相机是否真的跟随 | **本次唯一未解决的已知缺陷**：玩家移动而相机不动，原因未定位 |
| R12 | 交付纪律 | 对照 Q1–Q3：还有没有"本该自动查出来却留给人发现"的问题 |
