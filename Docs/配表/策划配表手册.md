# 《策划配表手册》

> **改表入口**：`ConfigWorkspace/Data/*.xlsx` ｜ **生效方式**：Unity 菜单 **Luban ▸ 表格数据导入**
>
> 逐列的**权威**是你打开的那张 `.xlsx` 本身；本文只是导航与坑位清单。表头四行的语义见
> [`策划手册_数据表填写.md`](策划手册_数据表填写.md)；工具链见 [`技术文档_配表管线.md`](技术文档_配表管线.md)。

## 一、配表铁律

1. **分工原则**：手感（移速、弹道抛物线、击退滑行、受击闪烁、敌人半径）去 Unity 调 SO 资产；
   **表里只填规则与结算数值**。表里删掉的边缘数值都在 SO 里，不能写回代码常量。
2. **符号禁区**：列表数组用半角分号 **`;`**（如 `level_wave.wave_ids` 的 `4;5`）；标签掩码用半角竖线 **`|`**。
   严禁中文标点与空格。
3. **不要手改表头四行**（`##var` / `##type` / `##group` / `##comment`）：字段名与类型是程序的契约，
   改名会让代码编译不过。列结构变动先与程序确认（**没有生成脚本可跑**，删列要在 Excel 里删干净、右侧不留孤立表头格）。
4. **枚举列选别名，别手打**：挂了单元格下拉框、且填**中文别名**的是
   `tile_state.id`（`B:B`）、`element_rule.source_tile` / `result_tile` / `ball_type`、
   `element_duo_reaction.elem_a` / `elem_b` / `result_tile`。
   仍是**英文项名或数字**的是 `seed.id`（`Fire` / `Elec` / `Ice` / `Plant`）、`seed.spawn_tile`（数字）、
   `projectile.id`（`Water` / `Earth`）、`wave.grant_seed`（`Fire` / `Elec` / `Ice`）。
   别名、英文项名、数字 Luban 都认，所以现在都导得过；**给其余表的枚举列补下拉框是待办收尾**（见 `Docs/待办.md`）。
5. **改完必须导表**：Excel 不是运行时数据源，跑一次 **Luban ▸ 表格数据导入** 才生效。

## 二、核心表格（共 13 张）

行数＝数据行（表头占 4 行）。枚举别名 ↔ 英文项名 ↔ 数值的对照见第三节。

### 1. `tile_state.xlsx`（地块状态属性 · 17 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 状态 ID，枚举 `TileStateType` 别名 | `空地` / `基础水` / `普通泥浆` / `导电区` … |
| `name` | 显示名（**只有诊断面板在读**，不在画面上显示） | 文字 |
| `duration` | 存活秒数，**`-1` = 永久**；到期回 `空地` | `-1` 或 `>0` |
| `slow_rate` | 踩在上面的移速倍率（**`1` = 不减速**，`<1` 减速，`>1` 加速） | `普通泥浆` 0.5、`稀泥` 1.2、`基础植物区` 0.7、`带电荆棘` 0.4 是**加速/减速**的现有用法 |
| `dot_damage` | 每秒持续伤害（`0` = 无） | 整数（列类型就是 `int`） |
| `touch_stun` | 踩上去的麻痹时长（秒，`0` = 不麻痹） | 目前只有 `带电荆棘` 填 `1.5` |
| `is_obstacle` | 物理阻挡墙体 | 数据上**只有 `陶砖` 为 `TRUE`** |
| `is_conductor` | **网格连锁导通体** | 为真的是 `基础水` / `基础土` / `普通泥浆` / `稀泥` / `导电区` |

> ⚠️ **`dot_damage` 是整数列**（类型行就是 `int`，没有取整环节）：别填 `0.5`，那会连导表都过不去。
> `Mathf.RoundToInt` 只作用在 `EnemyStats.ApplyDamage` 收到的伤害上，与这一列无关。
>
> **`is_obstacle` 已有物理体消费者**：`TileObstacleDirector` 订阅 `TileStateChanged`，
> 按 `IsObstacle = TRUE` 的地貌借还池对象并挂 `BoxCollider2D`。敌人的**绕障决策**读 `GridLogic.IsObstacle`。
>
> ⚠️ **`is_conductor` 是电泛洪的唯一判据，且泛洪的起点自己也必须是导通体**。
> `导电区` 之所以是 `TRUE`，正是因为水砸电源生成它之后，连锁要从**它自己**开始传下去。

### 2. `element_rule.xlsx`（一级反应：原格 + 球 ➔ 新地貌 · 16 行）

> **匹配规则**：按 **`(原格状态, 球种)` 双键**查表，**唯一命中**。不是"自上而下首条命中"。
> ⚠️ **同组合出现两行，导表不报错**（`__tables__.xlsx` 的 `index` 只有 `id`，导表只查主键）：
> 是运行期 `ReactionResolver` 建表时打 `LogError`，**先到的那行生效、后到的被忽略**。

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 编号（仅作标识） | 唯一整数 |
| `source_tile` | **被砸之前**那一格的 `TileStateType` | 枚举别名 |
| `ball_type` | 投入的球种（`纯水` / `纯土`） | `BallType` 别名 |
| `result_tile` | 轰完变成什么（`空地` = 不改地形） | 枚举别名 |
| `impact_damage` | 瞬时伤害（打给**站在该格上**的敌人） | 整数 |
| `impact_knockback` | 击退距离（格） | `0 ~ 50` |
| `impact_stun` | 麻痹时间（秒） | `0 ~ 10` |
| `impact_radius` | 落地冲击的**波及半径**（格） | `1` = 只打中那一格；`>1` 为范围波及 |
| `trigger_chain` | 是否触发网格连锁（见下方判据） | `TRUE` / `FALSE` |

> 🔴 **`trigger_chain` 的判据是"结果地貌有没有连锁的方向"**，而不是"这次反应够不够炫"，
> 且**填 `TRUE` 不会凭空产生连锁** —— 程序只看结果地貌本身：
> 结果是 **`燎原火海`** 或 **可燃面（`基础植物区` / `带电荆棘` / `基础花`）** 时会起延烧（可燃格会烧穿成火海）；
> 结果是 **`is_conductor = TRUE` 的状态（会导电泛洪）** 时连锁才有去处。反之，**蒸汽 / 结冰 / 陶砖这类
> 既不可燃也不导通的产物填 `TRUE` 是空转**。当前 16 行里只有 **id 6**（`基础电源 + 纯水 → 导电区`）是 `TRUE`，
> 它恰好正确：`导电区` 自己就是导通体。
>
> **兜底不走这张表**：表里没命中的组合同样有行为 —— 一律"地形不变、无伤害"。
> C# 那侧有一条"表缺行时的保险"（空地 + 水/土），但主路径是表里的 **id 13/14**（`空地 + 水 → 基础水`、
> `空地 + 土 → 基础土`）。
>
> **`impact_stun` 不要加 `!`**：16 行里 15 行天然是 0，带 `!`（不许是默认值）会直接导表失败。

### 3. `element_duo_reaction.xlsx`（二级反应：两个发生器相邻触发 · 6 行）

| 列名 | 含义 | 规范 |
| :-- | :-- | :-- |
| `id` | 编号 | 唯一整数 |
| `elem_a` / `elem_b` | 相邻的两个**发生器**地貌（顺序无关，程序两种顺序都认） | 枚举别名 |
| `result_tile` | 激发出的地貌（`空地` = 只清场不换地形） | 枚举别名 |
| `impact_damage` | 瞬发伤害 | 整数 |
| `impact_knockback` | 击退距离（格） | `0 ~ 50` |
| `result_duration` | 结果的存续秒数 | `>0` |
| `effect_radius` | 波及半径（格，**以格为单位**） | `0 ~ 5` |
| `pull_strength` | 向心吸力（单位/秒，`0` = 不吸） | 目前只有 id 3（`基础冰面 + 基础电源 → 结冰`）填 `5` |
| `break_aggro` | 是否清空范围内敌人的仇恨（**已退役**：仇恨系统已下线，填了也不会有任何效果，见 [`../工程/敌人仇恨系统_归档.md`](../工程/敌人仇恨系统_归档.md)） | 目前只有 id 5 填 `True` |
| `trigger_chain` | 是否继续连锁（判据同一级反应） | `TRUE` / `FALSE`。目前 id 1（→`燎原火海`）与 id 4（→`带电荆棘`）为 `TRUE` |

> **这条表不会"两人站一起就触发"**：必须是两种**发生器**地貌成了四邻，且球砸中其中之一。
> 所以想验证二级反应，得先有火池 / 电源 / 冰面 / 植物区这些地貌（用种子播，或在场景里刷）。

## 三、枚举对照（`__enums__.xlsx`，4 组）

| 枚举 | 项数 | 别名 ↔ 英文项名 | 备注 |
| :-- | --: | :-- | :-- |

## 四、改表 3 步防坑检查

1. **查符号**：没有用中文分号 `；`。列表列只有 `level_wave.wave_ids` 一处（用半角 `;`）；
   当前 13 张表**没有**标签掩码列，也没有 `#ref=` 外键列。
2. **查主键**：**主键一律是 `id`，导表只查它有没有重复**。
   `element_rule` 的 `(source_tile, ball_type)` 组合重复**导表不报错**，只在运行期报 `LogError`
   （见 §二.2）；`trigger_chain = TRUE` 的行，其结果地貌**必须可燃或是导通体**（见 §二.2 判据）。
3. **查导表**：Unity 中点击 **Luban ▸ 表格数据导入**，Console 无红字报错。
   导表用 `--strict`，**类型非法 / `#range` 越界 / 枚举值非法 / 主键重复 / 缺列都会当场报错**。
