# Skill · 交接包打包（Pack-to-Agent）

> **一句话**：把一个 Unity 工程里「另一个 AI 真需要读」的文档与代码筛出来，**平铺**成单一目录 ＋ 一份 `MANIFEST.txt`，
> 让对方不打开 Unity、看不到场景的前提下也能接手干活。
> **可执行真源**：[`Tools/pack-toagent.ps1`](../../Tools/pack-toagent.ps1)。本文解释**为什么这样列、怎么改、怎么验**；清单本身只在脚本里，别在两处各抄一份。

| 项 | 值 |
| :-- | :-- |
| 触发场景 | 换模型 / 换会话继续开发、给外部 AI 做方案评审、交接给新同事的"离线阅读包"、开源前脱敏整理 |
| 不适用 | 一次性问答（直接贴那几个文件更快）；需要对方**跑起来**才能判断的问题（该给可运行环境，不是文档包） |
| 产物 | `<目标目录>/` 平铺文件 ＋ `MANIFEST.txt`（UTF-8 BOM） |
| 判据 | 缺失 0 / 同名覆盖 0 / 改名件可还原 / 抽样哈希一致 / 无二进制混入 |

---

## 一、四个不变的设计决定

| 决定 | 理由 |
| :-- | :-- |
| **平铺，不建子目录** | 对方的上传/读取通道常常只能一次喂一批文件，或只认文件名；子目录会让"路径即上下文"这条信息在多数工具里丢失。 |
| **白名单外扩展名一律补 `.txt`**（`CelLit.shader` → `CelLit.shader.txt`） | 很多对话通道只收文本后缀。**补**而不是**换**：原扩展名留在文件名里，对方仍能判断"这是 shader、这是 asmdef"；内容一字节不改、不加头注释，去掉末尾 `.txt` 即还原。 |
| **`MANIFEST.txt` 逐条写「包内名 ← 仓库原路径」** | 平铺丢掉了目录，这一行是唯一能把文件映射回工程结构的线索；同时它承担"随包说明"和"阅读顺序"。 |
| **给清单，不给全量** | 本工程 `Assets/Scripts` 有 262 个 `.cs`（约 26k 行）。全塞过去对方读不完、也读不出重点；**筛选本身就是交接质量**。 |

---

## 二、素材筛选：三选一

一个文件想进包，至少要满足一条：

1. **定义纪律或边界**——`AGENTS.md`、架构约束、目录说明、注释规范、门禁脚本、四层 `asmdef`。
   对方最容易犯的错是"越层引用 / 在 Logic 里摸场景 / 热路径 LINQ"，这类文件是护栏。
2. **是某子系统的唯一入口或数据流主干**——`GameRoot`、`CombatRoot`、`TilemapAdapter`、`GridLogic`、`EventBus`、`ConfigModule`、`AssetModule`、`EffectModule`、`TileGridLightmap`…
   判据：删掉它，这条链就断了。
3. **承载"改错了不报错、只表现为观感/手感错"的契约**——`CelLit.shader` 的合成序、`RenderOrder`/`SortingLayerConsts`、调参 SO、可读的 EditMode 用例。
   判据：编译器拦不住、测试不一定红、但玩家能看出来。

**明确排除**（每条都踩过）：

| 排除项 | 原因 |
| :-- | :-- |
| 历史任务书、`Docs/暂存` 类草稿 | 含**已被推翻**的数值与做法（本工程实例：`_AmbientFloor ≥ 0.35`、点光池、`_OrganicJitter`）。给了它，对方会照着旧结论做。 |
| 生成物（`Generated/**`、`cfg.dso` 30 个表类） | 每次导表被镜像覆盖，手改必丢；结构由 `目录说明.md` 与 Spec 类代答。 |
| 二进制 / 超长机读件（场景 756 KB YAML、预制体、材质、贴图、字体） | 读不动也传不动；用"接线文档 + `TagManager.asset` + 关键脚本"替代。 |
| 实现细节（各 UI 面板、各特效驱动、诊断 Harness、编辑器工具） | 由文档的"怎么加一个 X"清单承担；进包只会稀释注意力。 |

## 三、产物规格

```text
T:\GAMES\toAgent\
  MANIFEST.txt
  AGENTS.md                        ← AGENTS.md
  README_Docs文档地图.md            ← Docs/README.md          (As 改名，避冲突)
  CelLit.shader.txt                ← Assets/…/CelLit.shader  (补 .txt)
  DeepseaOil.Logic.asmdef.txt      ← Assets/…/Logic.asmdef
  compile-gate.ps1.txt             ← Tools/compile-gate.ps1
  GameRoot.cs / GridLogic.cs / …
```

规则（与脚本一致，改脚本别改规则）：

1. **目标目录固定**，每次运行先清空再整包重建；清空前必须断言 `(Resolve-Path $dst).Path -eq $dst`，否则 `throw`。
2. **白名单**（原样保留）：`.txt .md .cs .json .xml .yml .yaml .csv`；其余一律 `原名 + .txt`。
3. **同名冲突**用脚本的 `@{ From = '…'; As = '…' }` 显式改名，**不允许靠顺序覆盖**。本工程固定两处：
   `Docs/README.md → README_Docs文档地图.md`、`ConfigWorkspace/AGENTS.md → AGENTS_配表工作区.md`。
4. **逐字节复制**（`Copy-Item`），不重写编码、不改行尾；脚本自身随仓库约定（`Tools/*.ps1` = CRLF 无 BOM）。
5. 允许目录项（整棵复制但**仍然平铺**）；本工程未用，因为二进制会让包变脏。

## 四、操作步骤

**Step 0 · 勘察现状（不要凭记忆写事实）**
读 `ProjectSettings/ProjectVersion.txt`、`Packages/manifest.json`、`ProjectSettings/TagManager.asset`、`ProjectSettings/EditorBuildSettings.asset`；
确认"哪些子系统还活着"（例：`TileLightDirector` 是否还有驱动者、哪些文档是历史档）。

**Step 1 · 列清单（10 组左右，每组 3~20 项）**
分组按"对方读的顺序"，不按仓库目录：

| 组 | 装什么 |
| :-- | :-- |
| 00-入口与纪律 | 宪章 / README / 架构 / 目录 / 注释 / 交接手册 / 噪声 / 加内容清单 |
| 01-设计与现状 | 策划案、待办、配表规范、美术装配、已下线系统归档、`TagManager` |
| 02-子系统文档 | 光照 / 特效 / 场景接线等"怎么跑起来"的文档 |
| 03-程序集与入口 | 四层 `asmdef` + `ISceneRoot` + `GameRoot`/`GameManager` |
| 04-组合根 | `CombatRoot`、`PlayerController`、包锁 `manifest.json` |
| 05..07-各层核心 | Logic 主干 / Data 与 SO / Presentation 适配与子系统 |
| 08-Shader | 受光与特效着色器（全部 `*.shader.txt`） |
| 09-门禁与工具 | `compile-gate.ps1`、`comment-lint.ps1`、`comment-budget.json` |
| 10-测试契约 | 3~5 个**读得懂**的用例，用来表达"什么算坏" |

**Step 2 · 存在性与冲突预演（只读，先跑再改脚本）**
```powershell
$list = @(
    'AGENTS.md'
    'Docs/表现/全局光照.md'
    # …把候选路径全部抄进来（相对仓库根）
)
$list | Where-Object { -not (Test-Path ($_ -replace '/','\')) }   # 必须为空：这是缺失清单
$names  = $list | ForEach-Object { $n = Split-Path $_ -Leaf; $e = [IO.Path]::GetExtension($n)
  if ($e -and (@('.txt','.md','.cs','.json','.xml','.yml','.yaml','.csv') -contains $e.ToLowerInvariant())) { $n } else { "$n.txt" } }
$names | Group-Object | Where-Object Count -gt 1                  # 有输出就补 As 改名
```

**Step 3 · 改脚本的两处**：`$groups`（清单）＋ `随包说明`（事实）。清单与说明必须同批改——只改清单会让说明继续骗人。

**Step 4 · 跑**：`pwsh Tools/pack-toagent.ps1` → 期望输出 `缺失: 0` / `同名覆盖: 0`。

**Step 5 · 校验**：见第六节，四条全绿才算完成。

**Step 6 · 回报**：文件数、体积/行数、改名件数、冲突改名、以及**已知偏差**（例："后处理判据与资产现值不一致，已记在待办"），别让对方以为包里全是事实。

## 五、`MANIFEST.txt` 必须写清的 8 条

对方打不开 Unity、看不到场景，这 8 条只能靠文字兜：

1. **版本与包锁**：Unity `2022.3.62f3c1` ＋ URP `14.0.12`（2D Renderer、Linear 色彩空间）＋ Cinemachine / InputSystem / TMP 版本；
   正交相机半高、格子世界尺寸；**哪个场景是唯一完整装配的场景**、哪些场景入 Build Settings。
2. **四层单向依赖** `Presentation → Logic → Data → Foundation`，以及 🔴 **asmdef 的 references 不传递**（跨层基类/接口必须显式写全）。
3. **驱动模型**：`GameRoot.Update`/`FixedUpdate` 是唯二入口、`ISceneRoot.Order` 拓扑、业务组件禁散乱 `Update`（有例外就点名）。
4. **性能铁律**：热路径 0 GC（禁 LINQ/闭包/`new List`/`GetComponent`）、物理 `NonAlloc`、排序走 `RenderOrder` 频带。
5. **子系统现状**：哪套在跑、哪套已停用。例：一盏 `Global Light 2D`（只照 `Ground+Actor`）＋ `TileGridLightmap` 网格光场；六层 Sorting Layer；`Effect/UI` 不受光；旧点光池无驱动者。
6. **禁区**：`Assets/Scripts/Generated/**`、`Assets/StreamingAssets/Luban/**`、`ConfigWorkspace/output/**` 每次导表被覆盖；配置真源是 Excel 人工维护。
7. **上传兼容**：`X.shader.txt` 这类"前面还有一层扩展名"的是改名件、去掉 `.txt` 即原格式、内容未加头注释。
8. **建议阅读顺序**：① 宪章/架构/目录 → ② 子系统文档 → ③ 设计意图与"表 vs SO"边界 → ④ 代码从组合根逆流而下 → ⑤ `待办.md` 收尾。

## 六、校验命令（复制即用）

```powershell
$dst = 'T:\GAMES\toAgent'
(Get-ChildItem $dst -File).Count                              # = 清单条目数 + 1（MANIFEST）
(Get-ChildItem $dst -Directory).Count                         # 必须 0
Get-Content (Join-Path $dst 'MANIFEST.txt') -Encoding UTF8 | Select-Object -Last 6   # 缺失 0 项。
Get-ChildItem $dst -File | Where-Object Length -gt 200KB      # 应为空（防误塞场景/预制体）
Get-ChildItem $dst -File | Where-Object { $_.Extension -in '.meta','.png','.unity','.prefab','.mat','.dll' }  # 应为空
(Get-FileHash 'Assets\Resources\materials\Shaders\CelLit.shader').Hash -eq (Get-FileHash "$dst\CelLit.shader.txt").Hash   # 抽 5~7 份
```

## 八、踩过的坑（每条都有判据）

| 坑 | 判据 / 做法 |
| :-- | :-- |
| **旧包的"随包说明"会过期** | 上一版脚本仍写着"零 Light2D / 只有 Default 一层 / 六层共用一个材质"，全错。每次打包**先读源码与工程设置**再写说明。 |
| **历史任务书混进包** | 它们含被推翻的数值，对方会照着做。排除，并在说明里点明"以包内为准"。 |
| **同名覆盖** | `AGENTS.md`×2、`README.md`×2 是最常见的。先跑第二节的冲突预演，再补 `As`。 |
| **清空前不验路径** | 脚本若被改坏变量会误删别处。必须 `Resolve-Path` 断言后 `Remove-Item`。 |
| **补 `.txt` 时改了内容** | 有人为了"加说明"在文件头补注释——那就不是原文件了。**只改名，不动字节**；说明写进 MANIFEST。 |
| **写完脚本没转行尾** | 编辑器/写文件工具默认 LF，本仓库 `.ps1`/`.cs`/`.md` 一律 CRLF 无 BOM；提交前用 `[IO.File]::WriteAllText` 归一。 |
| **清单太长当"全量备份"** | 超过 ~120 项、~1 MB 就该再筛：只留"删掉就断链"的和"错了不报错"的。 |

## 九、维护：哪些事实最容易过期，去哪核对

| 事实 | 核对源 | 过期症状 |
| :-- | :-- | :-- |
| Unity / 包版本 | `ProjectSettings/ProjectVersion.txt`、`Packages/manifest.json` | 对方按 API 写的代码编译不过 |
| Sorting Layer 与掩码 | `ProjectSettings/TagManager.asset`、`SortingLayerConsts.cs` | 说"只有 Default 一层"（旧包原话） |
| 场景装配现状 | `Docs/表现/新场景接线.md`、`Range.unity` 的 `[Environment]` | 以为主场景不在 Build Settings 就不能直接 Play |
| 子系统死活 | 全仓 grep 类名是否有驱动者（例 `Tick(` / `AddComponent<T>`） | 让旧点光池"复活" |
| 调参现值 vs 脚本默认 | 场景 YAML 与 SO 资产 | 把场景手调值当契约写进说明 |
| 判据与资产的偏差 | `Docs/待办.md`（"已确认的缺陷"节） | 包里宣称"全绿" |

## 十、移植到别的仓库

1. 拷走脚本，改 `$dst`；保留路径断言与"清空前确认"。
2. 改 `$groups`（按第二节的三选一筛），改 `随包说明`（第五节 8 条里，去掉不适用的、补上本仓库独有的坑）。
3. 白名单按目标通道能力调整：若只收 `.txt/.md`，把 `.cs` 也纳入"补 `.txt`"分支。
4. 语言/规模差异不影响方法：**筛什么、怎么命名、怎么写说明、怎么验**这四件事与仓库无关。

## 附：本次形成的工作约定

- 打包是**一次性、幂等**的操作：脚本每次都整包重建，不做增量（增量会让 MANIFEST 与磁盘不一致）。
- 包**不入 git**（`T:\GAMES\toAgent` 在仓库外）；仓库里只保留脚本与本文。
- 打包脚本与本文**都不入包**：对方要的是工程事实，不是打包工具与打包方法。
