# 白模接入（投掷切片 · 第一、二阶段 ＋ 反馈修订）

**临时文档。白模验收后随 `Assets/Scripts/Prototype/` 一起删除。**

- **第一阶段**：球能抛出并落地，落地给附近物理体一次冲量。
- **第二阶段**：敌人追击、土球击退、水球留泥浆减速、三下打碎、玩家血量与无敌帧。
- **反馈修订**：击退的位移（禁足）、命中闪烁、减速变深、耐久数字、血量读数挪到右上角、
  **落地闪圈改成两个**并让判定与圈精确对齐。

仍然没做：采集 / 合成 / 水储量 / 备战 15s / 战斗 45s 倒计时 / UI 进度条 / 波次提示 / 音效 / 粒子/拖尾。

## 一、怎么跑起来

1. 复制 `Assets/Scenes/TestPhysics.unity` 为 `Assets/Scenes/TestThrow.unity`（**不改 TestPhysics**：那是手测相机跟随的场景，被白模改了以后手测结论就不干净了）。
2. 在场景里建一个空物体，命名随意（建议 `★ ThrowSpawner`）。
3. 给它挂 `ThrowSpawner` 组件。
4. 把 `Player` 字段拖成场景里的 `Player` 物体。**留空也行** —— 组件会自己 `FindObjectOfType<PlayerController>()`。
5. Play。

**除第 4 步那一个引用外，零接线。** 指示器、球、阴影、落地瞬闪、**敌人、泥浆、玩家血量色块**
全部运行期 `new GameObject` + `AddComponent` 建出，白模不依赖任何 prefab，
也不往 `TagManager`/`Physics2DSettings` 里塞东西。

> `enemyRoot` 是第二阶段新加的可选字段（敌人/泥浆/血量的父物体），**留空即在场景根下建**。
> 它只是为了层级整洁，不影响行为。

### 三件容易搞错的事（都真错过一次）

**① 三个高度是三个不同的东西，不能混用。**

| 高度 | 谁用 | 含义 |
| :-- | :-- | :-- |
| `SampleGround(t)` | 阴影 | **贴地逻辑位置**，不含任何高度 |
| `THROW_ORIGIN_HEIGHT`（0.3，固定） | 球本体 | 出手抬高量，让它不从玩家身体里钻出来 |
| `MaxHeight × SampleHeight01(t)` | 球本体 | 抛物线弧高，两端为 0 |

球本体 = 逻辑位置 + 抬高量 + 弧高；阴影 = 逻辑位置（仅此）。**抬高量绝不能烘进
`BallData.Start` / `End`** —— 烘进去过一次，阴影也跟着离地、还随抛物线上下起伏。
`BallShadow.Apply` 因此必须写 `transform.position`（世界坐标），不能写 `localPosition`
（它的父物体"球根物体"本身是悬空的）。

**② 指示器/瞬闪/泥浆的形状是观感，与判定无关。**
`AIM_VERTICAL_SQUASH` / `AIM_PERSPECTIVE_TAPER` 只影响贴图形状。落点判定用的是
`ClampThrowPoint`，与它们无关。泥浆的**判定范围**虽然跟形状走（都是椭圆），
但它读的是同一个常量，不会与画出来的圈漂移。

**③ 球本体**不**压扁，这是刻意的。**
球是一颗**球**，正上方投影本来就是正圆；压扁它会让它看起来像躺在地上的药丸。
所以 `PrimitiveSprites.Circle` 保持正圆，只有**贴地件**（阴影、指示器、瞬闪、泥浆）走
`GroundDiscOrRing`。

### 伪高度是什么

球没有刚体、没有重力。世界坐标里它**始终在地面线 `SampleGround(t)` 上**（阴影走这条线），
抛物线只是多出来的那个 y 偏移。所以落地判定是一次纯数学的 `t ≥ 1`，
不需要碰撞检测、不需要射线、不需要 layer。

### 为什么每帧只有一个速度写者

这是白模里最重要的一条不变量，两条链路各自成立：

| 角色 | 唯一写者 | 受击怎么进去 |
| :-- | :-- | :-- |
| 玩家 | `PlayerLogic`（基类账本，帧末一次写出） | `PlayerController.OverrideLogicSpeedTargets` ＋ `PlayerLogic.AddImpulse` |
| 敌人 | `EnemyLogic`（同上） | `EnemyActor.TakeDamage` → `EnemyLogic.ApplyKnockback` → `AddImpulse` |

**`Rigidbody2D.AddForce` 只用在无生命刚体上**（`ThrowSpawner.PushBodies`）。
`ApplyKick` 先给角色结算伤害、再给物理体冲量，两条路查的是同一个半径但**不重叠**：
角色走账本，物理体走引擎。第一阶段那笔技术债（落地冲量直接写刚体速度）
就是在这里还掉的。

### 冲量为什么在 `FixedUpdate` 里做

`Update` 只把「落点 + 球种 + 球编号」压进队列，`FixedUpdate` 才出队施加。三条理由：

1. `Rigidbody2D.velocity` 与 `AddForce(Impulse)` 只在 `FixedUpdate` 与下一个 `Physics2D.Simulate` 之间生效。
   在 `Update` 里写速度会在多个渲染帧后的大固定步里被一次性消费，表现是"推得莫名其妙地远"。
2. `PlayerController.FixedUpdate` 每帧帧首重新读引擎速度当基准，所以冲量只是"下一帧的起步速度里已经有它"。
3. 冲量是**一次**施加，不是持续力。

### 为什么"同一颗球只算一次"用球编号而不是"本帧"

落地结算按半径查碰撞体，同一个敌人可能被查到多次（多碰撞体、多父级）。
最省事的写法是每帧复位一个 `HitThisFrame` 标记 —— **但那是错的**：
它要求"每帧有人来复位"，于是正确性被绑死在**脚本执行顺序**上，
而 `ThrowSpawner.FixedUpdate` 与 `EnemyDirector.FixedUpdate` 谁先跑 Unity 并不保证。
先跑的那一帧里标记还没复位，伤害会被**静默丢掉**，现象是"有时三下碎、有时四下还不碎"。

球编号（`Damage.BallId`）只增不减，所以"这颗球打过了吗"是一个**无状态比较**：
不需要复位、不关心谁先跑。`EnemyActor` 只记 `_lastBallId`。

### 击退为什么必须用 `SteerTowards` 而不是现有的 `ApproachX`

`ActorLogic.ApproachX` 只看 `Velocity.x` —— **竖直分量永远不衰减**。
拿它做 2D 击退，朝正上方被推飞的敌人会以恒定速度一路飘到地图外，
而且不报错，现象只有"敌人不见了"。

所以新增了二维版 `ActorLogic.SteerTowards`：控制律与 `ApproachX` 相同（加速度限幅 ＋ 反向走衰减率），
但走二维，并且多加了一步**指数衰减** —— 于是击退是"滑出去再停"，而不是"匀减速走到底"那个折点。
`ApproachX` 原样保留，玩家的移动状态仍走 `MoveDirection`（零惯性）。

### 击退的位移由"禁足时长"决定，不是由衰减率决定

这是踩过的一个坑，写在这里是因为它**看起来完全合理**：

被砸中时账本里被塞进一个比满速还大的速度（`5.5 > 3.6`）。旧写法是"禁足期间传零方向给
`SteerTowards`"，于是它走**指数衰减**那一支：`e^(-10×0.02) = 0.819`，每帧砍掉 18%。
0.08 秒之后速度只剩 `5.5 × 0.819⁴ ≈ 2.47`，总位移约 **0.5 米** ——
现象就是"球砸中了，但敌人几乎没动"，而**冲量本身一点问题都没有**。

而把衰减率改成 0 **还不够** —— 第二次踩的是同一个坑的另一半：

> **"某帧没有提交"必须靠"真的不调用任何提交入口"做到，不能靠"传一组看起来中性的参数"。**

`SteerTowards(零方向, 0, 0, 0)` 在零方向分支里算的是 `_delta = -当前速度`
（衰减率传 0 时正好是全额），于是 `HasSubmission` 为真、帧末**把速度写成 0** ——
刚加进去的冲量当场被抹掉，实测就是"禁足第 0 帧速度变成 0"。

正确的写法只有一句 `if (IsStunned) return;`：什么都不提交，引擎速度原样保留。

| 阶段 | 速度 | 位移 |
| :-- | :-- | :-- |
| 禁足 0.25 s（零提交，引擎按原速推进） | 恒为 5.5 | ≈ **1.32 米** |
| 结束后（追击恢复，但惯性还在） | 5.5 → 0 反向 | 再 ≈ 0.7 米 |
| **合计（离目标最远）** | | **≈ 2.0 米** |

所以调"打多远"要改 `ENEMY_STUN_DURATION`（或冲量），改 `ENEMY_KNOCKBACK_DECAY` 只影响
"禁足结束后还滑多久"。**W19/W20 钉住这两件事。**

### 落地闪圈为什么是两个

一粒水球同时造成两件范围不同的事：击退（`IMPULSE_RADIUS` = 1.2）与泥浆
（`MUD_RADIUS_METERS` = 1.8）。只画一个圈的时候，**"圈是 1.2 但泥铺到 1.8"看起来就是指示与实际对不上**。

所以现在画两个同心环，每个半径精确等于一件事的生效半径：

| 环 | 半径 | 颜色 |
| :-- | :-- | :-- |
| 内圈（击退） | `IMPULSE_RADIUS` = 1.2 | 球种色 |
| 外圈（效果） | 土球 1.2 / 水球 1.8 | 灰白 |

外圈晚 0.05 s 出现 —— 同时出现会糊成一个粗环，反而读不出是两层。

**同时判定也改精确了。** 之前用 `Physics2D.OverlapCircleAll` 的"碰撞体与圈相交"语义，
它比画出来的圈**大**一个敌人半径（0.45）—— 圈外半米也会被打到。
现在两条路都按**精确点距**判（敌人按圆心、物理体按 `Collider2D.ClosestPoint`），
查询半径放大成 `IMPULSE_RADIUS + PUSH_QUERY_MARGIN` 只作"别漏候选"用。

**代价（有意接受）**：擦边命中变严格了 —— 圆心在圈外就真的打不到。

### 敌人有四个颜色状态，不是两个

`EnemyVisual.BodyColor(slow, flashOn)` 是一张 **2×2 查表**：正常红 / 泥浆深红 / 闪烁亮色 / 泥浆+闪烁。

写成 `if (flash) 亮 else if (slow) 深` 的话，站在泥里被打中的敌人看起来"跟没中泥一样" ——
而那正是玩家会去判断"这泥到底有没有用"的时刻。

耐久则**直接写数字**（`TextMesh` + 引擎内置字体，不导入美术）：
两个状态用颜色、一个数字用文字，比"颜色深浅表示剩余耐久"好读得多。
`TextMesh` 走 MeshRenderer，**没有 `sortingOrder`**，靠深度排序 —— 白模是正交俯视，接受。
字体取不到时**报 Error 并且不建数字**，不静默画成豆腐块。

> **它不加进度条、不加倒计时** —— 需求书里的备战/战斗计时还没到做的时候，
> 提前加会让这份临时界面变成"框架"。
> 窄窗口（宽 < 约 848 px）下它会和 debugPanel 重叠，这是**已知且接受**的：
> 一行临时读数不值得为它写一套自动避让。

### 要调的时候改哪

| 症状 | 改哪 |
| :-- | :-- |
| 抛物线的最高点看不见 | `CameraRig` 的 ortho size，或调小 `MAX_HEIGHT` |
| 落地点与鼠标光标有系统性偏移 | `CAMERA_PLANE_DEPTH`（默认 100） |
| 影子飘在球下面、跟着球上下 | **这是曾经的缺陷**，`BallShadow.Apply` 必须写世界坐标。如果又出现，先看这里 |
| 球看着半埋在玩家身体里 | `THROW_ORIGIN_HEIGHT`（默认 0.3） |
| 指示器太扁 / 太圆 | `AIM_VERTICAL_SQUASH`（改成 1 就是正圆） |
| 指示器"上小下大"太夸张 | `AIM_PERSPECTIVE_TAPER`（改成 0 就是上下等宽椭圆） |
| 贴地环的线太粗 / 太细 | `GROUND_RING_THICKNESS_METERS`（**世界单位**，指示器与瞬闪共用，所以两者线宽一致） |
| 推力太猛 / 太弱 | `IMPULSE_STRENGTH`（单位是速度，不是加速度） |
| 生效范围看不清 | `IMPULSE_RADIUS`，瞬闪圈会跟着变 |
| 敌人追得太紧 / 太松 | `ENEMY_SPEED`（玩家是 8）；`ENEMY_CHASE_RANGE` 调小到 15 就能试出"能脱离" |
| 敌人贴在玩家身上抖 | `ENEMY_STOP_DISTANCE`（必须小于 `ENEMY_CONTACT_RADIUS`，否则接触伤害只会发生一次） |
| 敌人起步/停步太生硬 | `ENEMY_ACCELERATION`（调小 = 更飘） |
| **打一下推得不够远 / 太远** | **`ENEMY_STUN_DURATION`**（默认 0.25，位移 ≈ 冲量 × 它）；或 `ENEMY_KNOCKBACK_IMPULSE`。**改 `ENEMY_KNOCKBACK_DECAY` 只影响禁足结束后的余滑** |
| 命中看不出打中了 | `ENEMY_FLASH_HZ`（默认 4；**别超过 10**，60 fps 下会变成闪频） |
| 减速看不出生效了 | `ENEMY_SLOW_BODY_COLOR`（默认是身体色的约 0.4 倍亮度） |
| 耐久数字看不见 / 太大 | `ENEMY_HP_TEXT_CHARACTER_SIZE`（默认 0.06）；位置是 `ENEMY_HP_TEXT_OFFSET_Y`。Console 里会有 `取不到内置字体` 的 Error 就说明字体没拿到 |
| 水球打上去像没打中 | `WATER_KNOCKBACK_SCALE`（默认 1/3，改 1 就是与土球同额） |
| 泥浆太黏 / 没用 | `MUD_SLOW_FACTOR`（默认 0.45）；`MUD_RADIUS_METERS`、`MUD_DURATION`（= 8 s） |
| 闪圈外圈和内圈一样大 | `MUD_RADIUS_METERS` 必须大于 `IMPULSE_RADIUS`（W17 会拦） |
| 闪圈出现的时机 | `LANDING_FLASH_DURATION`（默认 0.15）、`LANDING_FLASH_SECONDARY_DELAY`（默认 0.05） |
| 总感觉"圈住的没生效" | **圈是准的**：判定已改成精确点距。如果还有偏差，看 `PUSH_QUERY_MARGIN` —— 但**调大它不会扩大作用范围**（判定不看它） |
| 玩家被撞开太远 / 太近 | `PLAYER_KNOCKBACK_SPEED_LIMIT` —— **同时把 `PLAYER_KNOCKBACK_IMPULSE` 改成同一个数**（冲量小于上限就推不满） |
| 敌人太多 / 太少 | `ENEMY_COUNT_PER_WAVE`（= 4）；`CHASE_RESPAWN_DELAY` 控制清完到下一波 |
| 挨打太频繁 / 太少 | `PLAYER_INVULNERABLE_DURATION`（默认 0.8 s） |
| 玩家死太快 / 太慢 | `PLAYER_MAX_HP` 或 `PLAYER_CONTACT_DAMAGE`（默认 100 / 10，正好十下） |

> **TestThrow 的相机是纯俯视正交**（`orthographic: 1`，`CameraRig` 旋转全零、z=-10），
> 严格说这种相机下地面上的正圆投影出来**还是正圆**。所以指示器/泥浆的"上小下大"是**风格选择**，
> 不是透视计算。想要真透视得改成有俯角 ＋ 透视投影的相机，那是另一个层面的决定。

两个文件，都是 `[Category("WhiteBox")]`，**整文件是临时资产**，白模验收后随白模一起删。
Test Runner ▸ EditMode ▸ 右侧可以按 `WhiteBox` 分类只跑这些。

| 文件 | 覆盖 |
| :-- | :-- |
| `白模抛球Tests.cs` | W1–W11：`BallData` 与 `ThrowSpawner.ClampThrowPoint` 两条静态纯函数通路 |
| `白模敌人Tests.cs` | W12–W20：`Steering` / `EnemyConfig` / `EnemyVisual` / `PlayerHealth.CanTakeDamage` 四条纯函数通路 ＋ 一段**手写探针**驱动的逻辑账本（含"击退 → 追回 → 再次接触"整个循环与击退位移的数值契约） |

**不覆盖** MonoBehaviour 生命周期、鼠标设备、渲染、`Physics2D` 接触检测、`OnGUI`、碎片外观 ——
那些只能人工手测（即上面的清单）。不写假测试是有意的：
`移动Tests.cs` 头部记录过"自动接线检查报了 31 项全部误报、假红训练人忽略它"这个教训。

**七条是真实缺陷回归测试，别删**：

| 用例 | 钉住的缺陷 |
| :-- | :-- |
| `W7_非法上限必须被换成默认值` | `NaN` 上限比任何数都"不可比"，会绕过 clamp 把 NaN 传染给落点，球带着 NaN 坐标凭空消失 |
| `W10_阴影走直线且球不沉地` | 出手抬高量被烘进 `BallData.Start/End` ＋ 阴影用 `localPosition` ⇒ 阴影跟着抛物线起伏 |
| `W11_贴地形状不得有断点或空洞` | 旧画法不是椭圆 ⇒ 环左右断成两截；实心盘靠"厚度取 1 再夹"⇒ 中心留洞变甜甜圈 |
| `W13_击退滑行会衰减且不反向` | `ApproachX` 只看 x 分量 ⇒ 竖直击退永不衰减，敌人以恒定速度飘出地图 |
| `W18_被击退之后必须还能重新贴上来` | "停止距离"是纯几何判据 ⇒ 击退把敌人推出一点点后它再也不回来，整局只掉一次血 |
| `W19_禁足期间不得衰减冲量` | **两个真实缺陷**：① 禁足走了衰减那一支 ⇒ 0.08 s 吃掉 82% 的冲量；② 用 `SteerTowards(零方向, 0, 0, 0)` 想"零提交"，实际算出 `_delta = -当前速度` ⇒ **把速度写成 0**，冲量当场被抹掉。正确写法是 `if (IsStunned) return;` |
| `W20_击退总位移必须看得出来` | 位移的**数值契约**：1.2~2.6 米。改任何参数都行，只要这件事还成立 |

手工验收清单里那些"看形状/看手感"的条目是**没有自动化**的：形状对不对只能眼睛看。
