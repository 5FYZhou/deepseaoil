# 用图替代文字 · 提示词

> 用法：把下面「提示词正文」整段发给一个 Agent，并把要处理的文档清单一起给出。
> 「我的验收」一节由发起方执行，**不要**发出去。

---

## 提示词正文（从这里开始复制）

### 任务

把 `Docs/` 里**能用箭头或时序表达**的关系换成 Mermaid 图，删掉被图取代的文字。
对象是已精简过的文档，字数已经贴着上限——所以每加一张图，必须删掉它替代的段落，**不许净增长**。

### 只画这五类

| 类型 | 什么时候画 | 画什么 |
| :-- | :-- | :-- |
| `flowchart` | 有分支、循环、多步流水线 | 帧时序（谁先谁后）、仲裁/判定顺序、启动装配序、管线链路、依赖方向 |
| `stateDiagram-v2` | 有状态与转移条件 | 移动状态机的 7 个状态与转移 |
| `sequenceDiagram` | 有多个参与者的往返调用 | 启动时 Unity ↔ GameRoot ↔ PlayerController 的调用次序 |
| `erDiagram` | 有实体与字段 | 生成的数据表结构与外键（仅在需要时） |
| `classDiagram` | 有继承/实现层次 | 端口与实现者的对应（仅在需要时） |

### 不画

- 纯并列清单（配置项、常量、开放项）—— 表格更好扫。
- 单条直线流程（A → B → C）—— 一行字就够，画图反而绕。
- 已经用表说清的东西 —— **不许图和表讲同一件事**。
- 任何"设计理念""架构愿景"图。
- 装饰性图标、主题皮肤、`style` / `classDef` 花活。

### 硬约束

| # | 约束 |
| :-- | :-- |
| 1 | 节点数：`flowchart` ≤ 15，`sequenceDiagram` 消息 ≤ 10 条，状态图 ≤ 10 个状态。超了先拆图或先删细节 |
| 2 | 一张图只讲一件事。高层概览图**不许**塞实现细节 |
| 3 | 图前一句话说明这张图讲什么；**图下不写解释**——图讲不清就重画 |
| 4 | 节点标签 ≤ 24 字符。放不下就下沉到图旁的表格，不要靠 `<br/>` 硬塞 |
| 5 | 每张图 ≤ 2 层嵌套（`subgraph` 不许套 `subgraph` 再套） |
| 6 | 图中出现的类名、方法名、文件名、常量值，**必须与代码一致**。图里写错比不写更糟 |
| 7 | 全部中文说明放标签文字里，不要用 `%%` 注释承载信息（`%%` 只用于给人看的下标备注） |

### 语法禁区（这几条会直接画出报错框）

1. **标签一律加双引号**：节点写 `A["GameRoot.Update()"]`，不写 `A[GameRoot.Update()]`；
   `subgraph` 写 `subgraph L1["① Data 数据层"]`，不写 `subgraph ① Data 数据层`。
   `[]` 与 `()` 是语法字符，裸写会断。
2. **`Note` 文字加引号**：`Note over GR: "装配 Data 层"`。
3. **`;` 与 `{}` 不要出现在任何未加引号的时序/注释文字里**，尤其别学 C# 写 `{ AssetModule.Init(); }`。
   已实测：`Note over GR: if (...) Init();<br/>…` 会让 mermaid 报
   `Parse error ... Expecting '()', 'SOLID_OPEN_ARROW'`。
4. `<br/>` 只在引号内用，且一格里最多一次。
5. 标签里需要竖线时写 `\|`，不要裸写 `|`。

### 不许动

- **不改任何代码、测试、配置**：只写 `Docs/` 下的 `.md`。
- **不改文件名**
- **不动章节号**：`Assets/` 下有 6 处代码注释按 `§` 引用具体小节（逻辑层 §3/§4/§5、数据层 §1/§2.4/§5、蓝图 §5.2）。
  这些编号重排后必须仍指向同一件事；保不住就在交回里单独列出，**不要默默改**。
- **不删**：事实与数值、常量值与名字、异常类型、方法签名、`文件:行号`、禁令类条目（哪里不能碰、哪里会被覆盖）、表格、代码块。
- **只删散文**：被图替代的推导过程、重复叙述、"为什么这么设计"。
- 图不能新增事实。不确定的关系就不要画那条边。

### 自检

写完后跑（`<harness>` 是任意装了 `mermaid` 与 `jsdom` 的目录，脚本见「我的验收」）：

```powershell
node <harness>\verify.mjs <仓库根>
```

必须 **全部 OK、无 FAIL**。有 FAIL 就按报错改图，直到清零。
另外逐条自查：每张图 ≤ 15 节点 / ≤ 2 层嵌套 / 标签都加了引号 / 图与表没有讲同一件事 / 总字数没有涨。

### 交回格式

1. 表格：文档 → 原行数 → 新行数 → 新增几张图
2. 每张图一行：`文件:行号 · 图类型 · 它替代了哪一段文字`
3. `verify.mjs` 的输出原文
4. 你想画但**放弃**的关系，说明放弃原因

## 我的验收（不要发给 Agent）

### 校验器

`Tools/verify-mermaid.mjs` 扫全仓库 `.md` 里全部 mermaid 围栏块，用 mermaid 真实解析 + 渲染管线逐个验证：

```powershell
# 一次性准备：依赖装在任意目录（别在仓库根跑 npm install，会往仓库里丢 node_modules）
npm install --prefix $env:TEMP\mermaid-deps mermaid jsdom
# 每次验收
$env:NODE_PATH = "$env:TEMP\mermaid-deps\node_modules"
node Tools\verify-mermaid.mjs .
```

输出形如 `OK Docs/框架蓝图.md:26 [flowchart LR] svg 12345B | viewBox 0 0 800 400 | node 12 | edge 14`，
末尾汇总 `块数= / 通过= / 失败=`，有 FAIL 时进程退出码为 1。

> 已知噪声：`WARN ... CSSStyleSheet is not defined` 是 jsdom 缺 SVG 样式表 API 导致的**渲染**告警，
> 解析已通过，不影响真机渲染。

### 复核清单

| # | 检查 | 手段 |
| :-- | :-- | :-- |
| 1 | 图全部可解析 | `verify.mjs` 退出码 0 |
| 2 | 图里没写错名字 | 抽图中出现的类名/方法名/常量，逐个 grep 源码 |
| 3 | 净增长为零 | `git diff --stat`，逐文件看新增行 ≥ 删除行就该打回 |
| 4 | 事实没被图挤掉 | 对比精简版的常量表与 `文件:行号` 清单 |
| 5 | 图与表不重复 | 人眼看一遍每张图下方是否还有讲同一件事的表 |

任何一条不过，**打回子 Agent 重做那一条**，不自己动手改。
